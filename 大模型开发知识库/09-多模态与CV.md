# 09 多模态与 CV：图像、视频、OCR、VLM 与生成式视觉

> 适用岗位：多模态 Agent、视觉语言模型应用、视频监控 AI、文档智能、文生图/图像编辑。  
> 优先级：图像处理基础、视觉任务、VLM 输入链路与评测为 **P0**；OCR、视频、生成式视觉和 Agent 集成为 **P1**；专用模型训练与大规模视频系统为 **P1/P2**。  
> 学习目标：能把“图片/视频交给大模型”拆解为可解释、可编码、可评测的处理链路，并知道哪些任务应该用专用 CV 模型、哪些适合 VLM、哪些需要二者组合。

## 0. 零基础导读：用户上传一张监控截图后，系统真正处理的是什么

假设用户上传一张仓库入口截图并问：

```text
图片里有几个人？有没有人没有佩戴安全帽？
```

从用户角度只是“图片+问题”，但计算机内部至少要经历：文件校验、图像解码、像素预处理、视觉模型、结构化结果和语言解释。

### 第1步：文件并不等于已经得到图像矩阵

上传内容先是一串JPEG/PNG压缩字节。服务需要检查：

- 文件真实类型是否与扩展名一致；
- 文件大小和像素数是否超过限制；
- 是否含异常EXIF方向；
- 解码器能否安全读取；
- 当前用户是否有权访问该资产。

解码后，1920×1080的RGB图像可以表示为三维数组：

```text
height × width × channels = 1080 × 1920 × 3
```

每个像素有红、绿、蓝三个数。例如：

```text
[255, 0, 0]     接近纯红
[0, 0, 0]       黑色
[255, 255, 255] 白色
```

模型接收的是这些数字经过处理后的张量，不是人类概念中的“照片”。

### 第2步：为什么RGB和BGR会造成问题

PIL通常按RGB读取，OpenCV经典接口常按BGR读取。同一像素：

```text
RGB [255, 0, 0] 表示红色
BGR [255, 0, 0] 表示蓝色
```

如果跨库时忘记转换，图片仍能显示，shape也正确，但颜色分布和训练时不同，模型结果可能下降。这类问题不会总是抛异常，所以要保存预处理后的样例做可视化检查。

### 第3步：为什么要Resize和Normalize

视觉模型通常按特定输入尺寸和数值分布训练。例如模型可能期望`[3,224,224]`、0～1浮点数并按指定均值标准差归一化。

原图1920×1080直接拉伸到224×224会改变宽高比，人和安全帽可能变形；使用letterbox可以保持比例但增加padding。哪种方法正确取决于模型训练方式。

小目标尤其敏感。原图中的安全帽可能只有30×20像素，整图缩小后只剩几个像素，即使大模型再强也无法恢复已经丢掉的信息。可以先检测人物区域，再裁剪高分辨率头部区域复核。

### 第4步：分类、检测和分割分别回答什么问题

**分类**回答整张图是什么：

```text
输入：整张图
输出："仓库场景"，置信度0.94
```

它不能告诉我们每个人在哪里。

**目标检测**输出每个目标的类别和边界框：

```json
[
  {"class":"person","score":0.97,"box":[120,80,420,960]},
  {"class":"person","score":0.91,"box":[760,110,1010,940]},
  {"class":"helmet","score":0.88,"box":[180,85,250,150]}
]
```

系统可以根据人框和安全帽框的空间关系判断哪个人可能没戴帽子。

**分割**为像素分配类别，能得到更精细轮廓。适合面积、边界或复杂形状任务，但标注和计算通常更重。

### 第5步：为什么不能让VLM包办所有事情

VLM适合回答开放问题、解释场景和组合多种视觉线索。但如果业务要求：

- 每秒处理25帧监控；
- 精确统计人数；
- 返回每个人的坐标；
- 告警结果可回溯；
- 控制单位视频成本；

通常应由专用检测/跟踪模型处理高频感知，再让VLM复核候选片段和生成解释。

```text
检测器：第2个人未匹配到安全帽，置信度0.83
VLM复核：观察裁剪区域，判断是否因遮挡导致误检
Agent：结合规则决定是否告警，并保存证据帧
```

### 第6步：VLM怎样把图像交给LLM

图像不能直接作为普通文字Token。常见结构是：

```text
图像像素
→ Vision Encoder切成Patch并提取视觉特征
→ Projector/Resampler映射并压缩视觉Token
→ 与文本Token一起输入LLM
→ LLM生成文本或结构化结果
```

如果一张图被切成很多Patch，高分辨率会产生更多视觉Token，保留更多细节，但显存、Prefill和延迟也会增加。

### 第7步：OCR为什么通常要单独处理

假设截图里有一块标牌：

```text
进入仓库必须佩戴安全帽
```

VLM可能读出文字，但小字、倾斜、密集表格和长文档更适合专用OCR。OCR结果还应保留坐标：

```json
{
  "text": "进入仓库必须佩戴安全帽",
  "bbox": [1020, 90, 1560, 220],
  "confidence": 0.96
}
```

这样系统不仅知道文字，还能说明文字在图中哪里，并与人员位置、文档页码或视频时间对应。

### 第8步：一分钟视频为什么不能逐帧调用大模型

25 FPS的一分钟视频有：

```text
25 × 60 = 1500帧
```

一小时则有90,000帧。逐帧调用VLM不仅昂贵，而且相邻帧高度重复。

更实际的两阶段方法：

```text
第一阶段：每秒低频采样/检测器扫描，定位候选事件
第二阶段：对候选时间段提高帧率，由跟踪或VLM精读
```

如果短事件只持续0.2秒，简单每5秒取一帧一定可能漏掉。因此采样策略必须根据事件持续时间和召回要求设计。

### 第9步：多模态Agent的完整状态

不要把巨大base64图片反复放进消息。Agent状态保存资产引用和结构化结果：

```json
{
  "asset_id": "image_123",
  "owner_id": "tenant_a",
  "width": 1920,
  "height": 1080,
  "detections": ["..."],
  "ocr_blocks": ["..."],
  "evidence_regions": ["..."]
}
```

Agent根据任务调用`detect_objects`、`ocr_image`、`inspect_region`等工具，最后引用证据回答。图片中的文字也属于不可信输入，不能因为OCR读到了“忽略系统规则”就把它当成高优先级指令。

### 第10步：怎样判断系统真的有效

不能只看几张展示图。要分别评测：

- 检测是否漏人、重复框和小目标表现；
- 安全帽判断的precision/recall；
- OCR字符错误率和坐标；
- VLM是否看图编造；
- 端到端告警是否正确；
- 每小时视频的处理成本和延迟。

后面的像素、检测、CNN/ViT、VLM、OCR、视频和Diffusion章节，都可以放回这条“输入媒体—结构化感知—语言推理—证据输出”的主线。

## 1. 多模态系统不等于“LLM 多传一个图片参数”

一条真实链路通常是：

```text
图片/视频/扫描件
  ↓ 解码、颜色、方向、尺寸、采样
视觉编码器或专用 CV/OCR 模型
  ↓ 视觉特征 / 框 / 文本 / 时间片段
Projector/Adapter 映射到语言模型空间
  ↓
LLM/VLM 理解、推理、工具选择
  ↓
结构化结果、自然语言、检索或图像生成工具
```

常见失败并不都来自“模型看不懂”：

- 图片方向、颜色通道或归一化错误；
- 分辨率太低，小字被缩没；
- 视频采样错过关键帧；
- OCR 顺序和版面关系丢失；
- VLM chat template 或 image token 不匹配；
- 目标检测框坐标缩放错误；
- 多租户图片被错误缓存；
- 生成图片缺少安全、版权与水印治理。

## 2. P0：图像的数据表示

### 2.1 像素、分辨率与通道

彩色图像常表示为：

```text
H × W × C  或  C × H × W
```

- `H/W`：高和宽；
- `C=3`：通常 RGB 或 BGR；
- PIL 常用 RGB；OpenCV 经典接口读图常为 BGR；
- PyTorch 常用 `[C,H,W]`，batch 后为 `[B,C,H,W]`。

颜色通道错位会让模型输入分布异常。跨库处理时显式转换，不要靠肉眼猜。

### 2.2 数据类型和值域

常见形式：

- `uint8`：0～255；
- `float32`：0～1；
- 进一步按训练时均值/标准差 Normalize。

如果把 0～255 的 float 直接送入期望 0～1 的模型，结果可能严重偏移。使用目标模型自带 image processor 通常更安全。

### 2.3 Resize、Crop、Padding

假设原图是 `1920×1080`，模型要求 `640×640`，至少有三种处理方式：

1. **直接 Resize**：把宽和高都强制变成 640。人物会被横向或纵向拉伸，圆形也可能变成椭圆；
2. **Crop**：先按比例缩放，再裁出 640×640。画面形状自然，但边缘的人可能被裁掉；
3. **Letterbox/Padding**：按比例把 `1920×1080` 缩成 `640×360`，再在上下各补 140 像素空白。完整内容保留，但模型输入中新增了 padding 区域。

检测任务还必须同步换算坐标。若原图中的框是 `[960, 540, 1440, 900]`，直接缩放到 640×640 时，x 缩放比例是 `640/1920=1/3`，y 比例是 `640/1080≈0.593`。新框四个坐标要分别按对应比例变化。Letterbox 还要再加上 padding 偏移：

```text
新x = 原x × scale + pad_left
新y = 原y × scale + pad_top
```

mask、关键点和多边形也要做同样几何变换。只改图片不改标注，会让模型被迫学习“框总是偏离目标”的错误数据。

高分辨率 VLM 常用 thumbnail、切片或多尺度：先给一张低分辨率全局图，再给若干高分辨率局部区域，以同时保留场景和小字，但视觉 token 数和 Prefill 成本会增加。

### 2.4 插值

缩放后新像素通常落不到原图整数坐标上，插值决定怎样估计它的颜色。

- **nearest**：直接取最近原像素，速度快、边缘呈锯齿。它适合类别 mask，因为原来只有类别 0 和 2，缩放后仍然只会得到 0 或 2；
- **bilinear**：根据周围 4 个像素加权，结果平滑，是自然图像常见选择；
- **bicubic**：参考更大邻域，通常更平滑但计算更多，也可能产生轻微过冲；
- **antialias**：在大幅下采样前过滤高频细节，减少细条纹变成假图案的混叠。

为什么分割 mask 不能随便用 bilinear？假设相邻类别 id 是 0 和 2，线性插值可能生成 1，而类别 1 在原区域根本不存在。这会污染标签。自然 RGB 图像可以产生中间颜色，离散类别标签则应保持整数语义。

### 2.5 数据增强

常见：随机裁剪、翻转、颜色抖动、模糊、噪声、MixUp/CutMix。增强必须符合业务：文字 OCR 随机水平翻转会产生不可读文本；交通方向类任务也可能改变标签语义。

当前 TorchVision 推荐的 `transforms.v2` 可同时处理图像、视频、边界框、mask 与 keypoints，更适合检测/分割的一致变换。

## 3. 最小图像预处理代码

```python
from PIL import Image
import torch
from torchvision.transforms import v2

transform = v2.Compose([
    v2.Resize((224, 224), antialias=True),
    v2.ToImage(),
    v2.ToDtype(torch.float32, scale=True),
    v2.Normalize(
        mean=[0.485, 0.456, 0.406],
        std=[0.229, 0.224, 0.225],
    ),
])

image = Image.open("example.jpg").convert("RGB")
pixel_values = transform(image).unsqueeze(0)
print(pixel_values.shape, pixel_values.dtype)
```

均值、标准差和输入尺寸必须匹配具体 checkpoint。对于 Hugging Face 视觉模型，优先用 `AutoImageProcessor`/`AutoProcessor`，不要未经核对照搬 ImageNet 参数。

## 4. P0：经典 CV 任务

### 4.1 图像分类

输入整张图，输出一个或多个类别：

```text
image → backbone → pooled feature → classifier
```

- 单标签：Softmax + cross entropy；
- 多标签：每个类别独立 sigmoid + binary cross entropy；
- 指标：accuracy、precision、recall、F1、AUROC；类别不均衡时避免只看 accuracy。

### 4.2 目标检测

输出多个目标的：`class + confidence + bounding box`。常见框格式：

- `xyxy = [x_min,y_min,x_max,y_max]`；
- `xywh = [x,y,width,height]`；
- 绝对像素或 0～1 归一化坐标。

交换格式时必须知道 `x,y` 是左上角还是中心点。

### 4.3 IoU 与 NMS

IoU：

\[
IoU=\frac{|A\cap B|}{|A\cup B|}
\]

假设预测框 A 面积为 100，真实框 B 面积为 80，二者重叠面积为 60，则并集不是 `100+80`，因为重叠被算了两次：

```text
并集 = 100 + 80 - 60 = 120
IoU  = 60 / 120 = 0.5
```

IoU 越接近 1，位置越一致；接近 0 则几乎不重叠。检测评测会用 IoU 阈值判断一个预测框是否成功匹配真实目标。

一个人周围常会产生多个高度重叠候选框。NMS 的典型过程是：

```text
候选A：score 0.95
候选B：score 0.90，与A的IoU 0.82
候选C：score 0.87，与A的IoU 0.10
```

先保留最高分 A；若 NMS 阈值为 0.5，则 B 因与 A 高度重叠而被抑制，C 保留。然后继续对剩余框重复。阈值过低时，并排站着的两个人也可能互相误删；阈值过高则一个人留下多个重复框。NMS 是预测后处理，不能修复模型根本没检测到目标的问题。

### 4.4 检测指标 mAP

检测器输出的 score 阈值会造成 Precision 与 Recall 的取舍。阈值降低会保留更多框，可能找回漏检，也会增加误报；从高到低扫描阈值可得到 Precision-Recall 曲线，曲线下的综合面积形成某一类别、某一 IoU 条件下的 AP。

例如 `AP50` 使用 IoU≥0.5 判断匹配，位置要求相对宽松；`AP75` 更严格。COCO 风格的 `AP@[.50:.95]` 会从 0.50 到 0.95 多个阈值平均，因此通常明显低于 AP50。mAP 再对多个类别的 AP 做平均。

一个模型 AP50 很高但小目标 AP 很低，可能在普通图片上表现不错，却不适合远距离安全帽监控。因此报告时写清：

- `AP50` 还是 `AP@[.50:.95]`；
- macro 还是按类别；
- 小/中/大目标；
- 置信阈值与测试集版本。

### 4.5 语义/实例/全景分割

- 语义分割：每个像素一个类别，不区分同类实例；
- 实例分割：区分每个目标实例；
- 全景分割：统一 stuff（天空、道路）与 thing（人、车）。

常用指标：pixel accuracy、IoU/mIoU、Dice。

假设画面中有两个人和一条道路：语义分割只会把两个人的像素都标为 `person`，无法区分谁是谁；实例分割会输出 `person_1` 与 `person_2` 两张 mask；全景分割还会把没有明确实例边界的道路、天空等 stuff 类一起覆盖，使整张图每个像素都有统一解释。

Pixel accuracy 在背景占比很大时可能虚高：即使模型完全漏掉很小的行人，只要背景都判对，总体像素准确率仍然高。mIoU 会分别计算每个类别预测区域与真实区域的交并比再平均；Dice 更关注两个区域的重叠，医学小目标中常见。报告必须说明是否忽略背景类以及类别平均方式。

### 4.6 目标跟踪

检测回答“这一帧有什么”，跟踪回答“跨帧是否为同一个对象”。典型流程：

```text
每帧检测 → 运动预测 → 外观/位置匹配 → 分配 track id
```

遮挡、交叉、镜头切换会造成 ID switch。单张图片没有真实的持续 track id；当前跟踪文档也强调 track id 依赖连续帧状态。

## 5. P0/P1：CNN 与 Vision Transformer

### 5.1 CNN 的直觉

卷积核是一小块可学习参数，例如 `3×3`。它在整张图上滑动，每到一个位置就把局部 3×3 像素与核相乘求和，生成一个特征值。同一套核在所有位置复用，因此无论边缘出现在左上还是右下，都能被相似方式识别，这叫权重共享。

早期层常响应边缘、颜色变化和简单纹理；更深层把这些局部特征组合成轮廓、部件和对象语义。池化或带步幅卷积会降低空间分辨率，使后续神经元看到更大的原图区域，即扩大感受野。

CNN 自带“附近像素关系更重要”的局部先验，在数据较少或边缘设备上常很实用。局限是相距很远的两个区域要经过多层才能交换信息，全局关系不像 Self-Attention 那样直接。

### 5.2 ViT

Vision Transformer 将图像切成 patch：

```text
image → patches → linear embedding + position → Transformer
```

假设输入为 `224×224`，patch 大小为 `16×16`，横纵各得到 14 个 patch，总数为：

```text
(224 / 16) × (224 / 16) = 14 × 14 = 196 个视觉 token
```

每个 patch 展平后通过线性层变成 embedding，再加入位置编码，让模型知道 patch 原本位于哪里。之后 Transformer Attention 可以让左上角 patch 直接与右下角 patch 建立联系。

若分辨率翻倍为 `448×448`，patch 数变成 `28×28=784`，是原来的 4 倍；标准 Attention 的两两关系规模又近似随 token 数平方增长。因此提高分辨率能保留小字细节，却会显著增加显存和计算。部分 VLM 会通过更大 patch、视觉 token 压缩、局部窗口或动态切片控制成本。

### 5.3 CNN 还是 ViT

现代系统经常组合或按预训练模型选择。不要用“ViT 一定更好”作结论，应比较数据规模、输入分辨率、延迟、硬件 kernel 与任务指标。

若任务是边缘摄像头上的低延迟分类、标注数据较少，轻量 CNN 的局部先验和成熟 kernel 可能更合适；若拥有大规模预训练模型、需要全局关系和多模态对齐，ViT 常更方便。很多检测器与 VLM 还会使用卷积 Stem、分层窗口 Transformer 等混合结构。

工程选型应在同一设备与同一输入尺寸下比较准确率、小目标切片、峰值显存、batch=1 延迟和吞吐。模型名字更新很快，能解释输入分辨率、特征尺度和部署约束比争论架构标签更重要。

## 6. P0：视觉—语言对齐与 CLIP

CLIP 类方法分别编码图像和文本，并通过对比学习让匹配图文在共享空间更接近：

```text
image → vision encoder → image embedding
text  → text encoder   → text embedding
                     ↓ cosine similarity
```

可用于：

- 零样本分类；
- 图搜文/文搜图；
- 多模态 RAG 的图像检索；
- 作为生成/理解模型的视觉或文本条件。

限制：全局 embedding 可能丢失细粒度位置、计数和 OCR 信息。需要定位时使用检测/grounding，需要文字时结合 OCR，需要复杂推理时交给 VLM。

## 7. P0：VLM 架构

常见结构：

```text
Image
  ↓ Vision Encoder
visual features
  ↓ Projector / Resampler / Q-Former
visual tokens in LLM hidden space
  ↓ 与 text tokens 组合
LLM Decoder
  ↓
text / boxes / actions
```

### 7.1 视觉编码器

视觉编码器先把原始像素变成一串特征向量。以 ViT 为例，图片切成 patch 后可能输出 `[576, 1024]`：576 个视觉位置，每个位置 1024 维。这些向量已经包含对象、纹理与空间上下文，但还不一定与语言模型 4096 维 hidden state 兼容。

它常由 ViT/CLIP 类模型初始化。部署时输入尺寸、切片规则、Normalize 和视觉 special token 必须与该 checkpoint 的 processor 一致；视觉编码器不是看到原始 JPEG 字节，而是看到处理后的像素张量。

### 7.2 Projector/Adapter

Projector 把视觉特征维度映射到 LLM 可接收的隐藏维度。例如把每个 1024 维视觉向量变成 4096 维：

```text
Vision Encoder: [576, 1024]
Projector:      1024 → 4096
LLM receives:  [576, 4096]
```

若直接把 576 个视觉 token 全送给 LLM，细节较多但 Prefill 很贵。Resampler/Q-Former 等结构还会把可变数量视觉特征压缩成例如 64 个 token。压缩提高速度，却可能丢失小字、密集计数或精确定位信息。

因此 Projector 不只是数据类型转换。它要在视觉空间和语言空间之间学习对齐，还决定多少视觉信息进入 LLM。只训练连接层、冻结两侧模型，是常见的早期对齐方式之一；后续再用多模态指令数据让 LLM 学会根据视觉 token 回答。

### 7.3 LLM

利用语言预训练能力处理视觉 token 与文本 token，生成描述、答案、坐标或工具调用。

视觉 token 会被插入文本序列中的图像占位位置。例如文本 token 问“图中有几个人”，Attention 可以让这些文本位置读取视觉特征，LLM 再自回归生成答案。LLM 并不是直接读取 RGB，也不会自动保留原始像素坐标；若需要输出框，训练数据和模板必须教会它坐标表示，或调用专用检测工具。

语言模型带来了指令理解、知识和多轮对话能力，也会带来语言模型式幻觉：视觉证据不足时仍可能生成听起来合理的描述。因此高风险结论要附区域、OCR 坐标或检测器结果。

### 7.4 训练阶段

常见思路：

1. 视觉—语言连接/对齐；
2. 多模态指令微调；
3. 偏好、安全、grounding 或任务专项后训练。

不同模型实现差异大，面试讲通用结构后再说明具体模型需查 model card。

第一阶段常冻结视觉编码器和 LLM，只训练 Projector，让视觉特征先能进入语言空间；第二阶段使用图文问答、描述、OCR、定位等指令数据，使模型学会按用户要求处理视觉输入；第三阶段再用偏好、安全或 grounding 数据修正拒答、幻觉和坐标能力。

并非所有模型严格采用三段式，有的会联合解冻部分视觉/语言层。解冻越多，适配能力越强，但显存和灾难性遗忘风险也更高。阅读 model card 时应确认哪些模块训练过、图片分辨率、视觉 token 策略和数据能力边界。

## 8. P0：多模态 Chat Template 与 Processor

文本模型通常由 tokenizer 处理；多模态模型通常使用 processor，把 tokenizer 与 image/video/audio processor 组合起来。

当前 Transformers 的多模态消息中，`content` 通常是不同类型条目的列表：

```python
messages = [
    {
        "role": "user",
        "content": [
            {"type": "image", "url": "file:///path/to/image.jpg"},
            {"type": "text", "text": "图片中有哪些安全隐患？"},
        ],
    }
]
```

最小推理骨架：

```python
import torch
from transformers import pipeline

pipe = pipeline(
    "image-text-to-text",
    model="your-vlm-model",
    device_map="auto",
    dtype="auto",
)

result = pipe(text=messages, max_new_tokens=256)
print(result[0]["generated_text"][-1]["content"])
```

重点：

- 多模态模板通常在 processor，不只在 tokenizer；
- 模板先产生模型所需 image/video 占位 token，processor 再扩展和处理真实媒体；
- 图片顺序必须和占位符一致；
- 多图、多轮缓存行为依模型和框架而不同；
- 远程 URL 需防 SSRF、超大文件、内容类型伪造和下载超时。

## 9. P1：VLM 常见能力与边界

### 9.1 VQA 与图像描述

适合整体语义、场景描述、问答。评测要区分：开放式答案、选择题、是非题和需要 OCR/计数的切片。

“描述这张图”允许很多合理表达，不能只用 Exact Match；“红灯是否亮起”则可用明确标签。评测集还要区分只需常识的问题与必须看图的问题，否则模型可能不看图也能凭语言先验答对。可加入同一问题配不同图片、图片缺失和反事实图片来验证视觉依赖。

### 9.2 OCR 与文档理解

VLM 可以直接读图中文字，但小字、密集表格和长文档更适合“专用 OCR/版面模型 + VLM/LLM”。

VLM 适合用户偶尔上传一张清晰截图并问语义问题；批量票据、百页 PDF 则更需要 OCR 的坐标、置信度与可复现文本。组合方式通常是 OCR 先输出 `text+bbox+page`，VLM/LLM 再根据结构回答，必要时裁剪原区域复核。这样既便于全文检索，也能回到原图证据。

### 9.3 Grounding

要求回答和图像区域对应，例如输出框或点。坐标格式、原图/缩放图和归一化必须统一。语言描述正确不代表定位正确。

例如模型说“安全帽在左上角”语义正确，但输出框落在墙上，Grounding 仍然失败。必须明确坐标是 `xyxy` 还是中心点 `xywh`、使用 0～1 归一化还是原图像素，并把模型输入图上的 Resize/Letterbox 结果映射回原图。评测可使用 box IoU 或 point-in-region，而不只让 Judge 看文字。

### 9.4 计数与空间关系

VLM 容易受遮挡、密集目标、分辨率和视觉 token 压缩影响。高风险场景应使用检测器计数，再让 VLM 解释。

密集人群中，相邻目标可能被压进同一视觉 token；遮挡又会让“一个人还是两个人”模糊。可先用检测器输出每个实例框和 score，NMS 后按区域计数，再把结构化结果交给 VLM 解释“左侧有3人、其中1人未戴帽”。对“在桌子后面”等空间关系，还要保留坐标和深度/遮挡线索，不能只依靠对象类别列表。

### 9.5 多图比较

要明确图片编号并保证处理顺序。模型可能混淆“图 1/图 2”，可以在输入中加入可视标签或逐图提取结构化特征后再比较。

例如比较合同修改前后两页，可以先分别抽取 `图1字段表` 与 `图2字段表`，再由 LLM 比较字段，而不是一次塞入两张密集页面要求自由描述。程序需确认消息中的图片顺序与 processor 输入列表一致；在图片上叠加不可歧义的 A/B 标签，并要求输出 `image_id`，能降低指代混乱。

## 10. P1：OCR 与文档智能

### 10.1 OCR 主流程

```text
图像/PDF
  ↓ 方向、去噪、矫正
文字检测（区域）
  ↓
文字识别（字符序列）
  ↓
方向/阅读顺序/版面分析
  ↓
表格、标题、段落、图注、公式
  ↓
结构化文档 + 置信度 + 坐标
```

每一阶段解决的问题不同。文字检测先找出“哪里可能有字”，输出矩形或多边形区域；文字识别再把每个区域转成字符序列；版面分析最后判断这些区域是标题、正文、表格还是页脚，并恢复阅读顺序。

以一张发票为例，只有纯文本：

```text
总金额 100.00 税额 5.00 某某公司 日期 2026-07-16
```

仍然无法确定哪个数字对应总金额、哪个属于税额。结构化结果应保留：

```json
{
  "text": "总金额",
  "bbox": [82, 510, 156, 538],
  "page": 1,
  "block_type": "key",
  "confidence": 0.98
}
```

这样下游模型才能利用相邻位置匹配字段，也能在回答时回到原页面高亮证据。

### 10.2 预处理

- 旋转/方向检测；
- 透视矫正；
- 去噪、对比度；
- 超大页面切片；
- 扫描 PDF 与可复制文本 PDF 分流。

不要对所有图片统一二值化；彩色印章、浅色文字和复杂背景可能因此丢失。

### 10.3 版面与阅读顺序

只把 OCR 行按 y 坐标从小到大排序，在双栏论文中会把左栏第一行、右栏第一行、左栏第二行交叉拼接；表格中还会把同一行不同列错误串成句子。

```text
视觉上正确顺序：左栏从上到下 → 右栏从上到下
简单 y 排序：    左1 → 右1 → 左2 → 右2 → ...
```

版面模型需要先识别列、标题、段落、表格、图注等 block，再在 block 之间和内部建立 reading order。文档 RAG 应保留 `page`、`block_type`、`bbox`、`reading_order`、`table_cell`、标题层级。检索到一句话后，系统便能同时返回它属于哪一节、哪一页、哪个区域，而不是只有失去上下文的文本碎片。

### 10.4 表格

表格理解不仅是 OCR：还要识别行列、合并单元格和表头关系。可输出 HTML/Markdown/JSON，但必须保留原图区域用于回溯。

假设 OCR 识别出了“产品A、100、200、产品B、50、80”，若不知道列标题是“成本/售价”，这些数字无法正确配对。表格结构模型要恢复 cell 的行列坐标、rowspan/colspan 和多级表头关系，再把单元格文字放回结构。

Markdown 对简单表格方便，但难表达复杂合并单元格；HTML 或 JSON cell graph 更适合保真存储。进入 RAG 时可以生成按行的可检索文本，同时保存原始 cell 坐标与截图，回答数字问题后可核对来源。

### 10.5 OCR 评测

- 字符错误率 CER；
- 单词错误率 WER；
- 检测 precision/recall/Hmean；
- 阅读顺序；
- 表格结构相似度；
- 下游问答准确率。

CER 以字符为单位计算插入、删除、替换错误占参考字符数的比例。例如参考“安全帽”，识别为“安会帽”，发生 1 次替换，CER 为 `1/3`。中文通常用 CER 更直接；英文可同时看 WER，因为一个字符错误可能影响整词。

仅 CER 低不代表文档系统可用：文字检测漏掉整行时、双栏阅读顺序错乱时、表格 cell 关联错误时，都可能让下游问答失败。因此至少分层报告检测、识别、版面/表格结构和最终问答，并按小字、倾斜、扫描噪声等切片。

### 10.6 与 RAG 结合

```text
OCR/layout → 结构化 block → 按标题/段落/表格分块
→ 文本/图像 embedding → 检索 → 返回文本 + page/bbox
→ VLM/LLM 基于证据回答
```

只存 OCR 纯文本会失去版面证据；只存页面图片又难以低成本检索。生产中常做双索引或分层索引。

## 11. P1：视频处理基础

### 11.1 视频是什么

视频由帧、时间戳、帧率、编码、音频流组成。不要假设 `frame_index / fps` 永远等于准确时间戳；可变帧率和解码跳帧会影响。

视频文件通常保存压缩码流，不是逐张完整 JPEG。关键帧保存较完整画面，其他帧可能只保存相对变化；要读取第 1000 帧，解码器可能需要从前一个关键帧开始解码。容器还可以同时封装音频、字幕和多个时间基。

固定帧率视频中 `frame_index/fps` 可做近似，但可变帧率、丢帧或转码后应使用解码得到的 presentation timestamp。告警与证据回放要保存真实时间戳，而不是只保存帧编号。

### 11.2 为什么不能把所有帧都送给 VLM

一小时 25 FPS 视频约 90,000 帧。全部处理会造成巨大的解码、视觉 token、显存和推理成本，还包含大量重复。

若每帧被编码为 256 个视觉 token，一小时就是约 2,304 万视觉 token，远超普通上下文并产生巨大 Prefill 成本。相邻 40 毫秒的两帧往往几乎相同，重复编码没有对应信息增益。正确做法是让便宜的采样、运动检测、目标检测或场景切分先压缩时间，再让昂贵 VLM 精读少量候选片段。

当前 Transformers 多模态模板可以通过 `num_frames`、`fps` 或预先解码的帧列表控制视频输入；若特定接口未设置采样参数，可能尝试加载整个视频。实际使用必须查看目标 checkpoint 预训练支持的最大帧数，并在送入 processor 前显式限制时长、帧数和像素预算。

### 11.3 采样策略

采样不是简单地“少拿几帧”，而是在漏掉短事件与控制成本之间做设计。

假设 10 分钟视频为 25 FPS，共 15,000 帧，其中有人跌倒只持续 1 秒：

- 每 10 秒取 1 帧只处理 60 帧，成本很低，但很可能完全错过那 1 秒；
- 每秒取 5 帧处理 3,000 帧，召回提高，成本也增大；
- 场景切分适合镜头内容变化，却不一定能发现固定摄像头中的小动作；
- 运动/检测触发可在有人进入区域时提高采样率，但依赖前置检测器的召回。

常见两阶段方案是：

```text
全视频每秒1帧 + 轻量运动/人员检测
             ↓ 找到 12:03:20 附近有异常运动
对 12:03:15～12:03:25 按 10 FPS 精扫
             ↓ VLM/行为模型复核跌倒事件
```

检测/跟踪驱动还能只保留含目标的 clip。评测采样策略时，应把“事件是否至少命中一帧/一个 clip”作为召回，而不只是统计处理帧数。

### 11.4 时间建模

单帧模型无法理解动作顺序。可使用：

- 多帧堆叠/3D CNN；
- Video Transformer；
- 每帧特征 + temporal aggregator；
- VLM 的 video processor；
- 先提取结构化事件，再由 LLM 推理。

### 11.5 视频检索

推荐层级：

```text
video → shots/clips → keyframes + transcript + OCR + objects/actions
→ clip embeddings + metadata/time range
→ query retrieval → 精读候选 clip
```

结果必须返回时间区间和证据帧，便于回看。

## 12. P1：视频监控场景

### 12.1 典型架构

```text
RTSP/视频流
  ↓ 解码与抽帧
检测/跟踪/行为识别
  ↓ 结构化事件
事件存储 + 向量检索 + 原视频索引
  ↓
Agent/VLM 复核与自然语言解释
  ↓
告警、工单、人工确认
```

### 12.2 为什么专用模型在前、VLM 在后

持续流每秒处理大量帧，直接调用大 VLM 成本和时延过高。专用检测器负责高频筛选，VLM 只复核候选片段、解释复杂关系。

例如人员检测器可在每秒多帧上判断“禁区是否有人”，并产生候选 10 秒 clip；VLM 只在候选上判断“此人是工作人员正常巡检，还是异常闯入”。前者追求高召回和低成本，后者处理上下文与语言解释。若前置检测器漏掉事件，VLM 根本没有机会复核，所以要按阶段分别评测召回。

### 12.3 告警治理

- 防抖：事件持续 N 帧才触发；
- 冷却：同类事件短期不重复告警；
- 轨迹合并：避免一个人多次触发；
- 置信度分层：高分自动、低分人工；
- 保存证据片段与模型版本；
- 隐私遮挡、访问审计和保留期限。

### 12.4 评测

除了帧级 precision/recall，还要看事件级：漏报率、误报/小时、告警延迟、重复告警、ID switch、人工确认率。

一个持续 30 秒的入侵事件可能跨 750 帧。模型漏掉其中 100 帧，但仍及时产生一次正确告警，事件级任务可能成功；反过来，它在每帧都告警，会造成 750 条重复工单。应先定义事件匹配窗口和开始/结束容差，再统计每个真实事件是否被至少一次正确命中、首次告警延迟及每小时误报数。

## 13. P1：Diffusion 文生图原理

### 13.1 前向加噪与反向去噪

训练时先拿一张真实图像，在随机时间步向它加入已知噪声。模型同时接收带噪图、时间步和文本条件，例如“雨夜街道”，学习预测这次加入的噪声或等价目标。

```text
真实图 x0 + 随机噪声 ε
          ↓ 按时间步 t 混合
带噪图 xt + 文本条件 + t
          ↓ 去噪网络
预测噪声 ε̂，与真实 ε 计算 loss
```

因为训练时我们自己采样了噪声，所以知道正确答案 ε。生成时没有真实图，从随机噪声 `xT` 开始，调度器让模型重复多步去掉预测噪声，图像结构逐渐显现。

扩散模型不是从数据库里直接找一张图，也不是一次前向就画完。它在多个时间步反复调用去噪网络，因此采样步数、分辨率和去噪主干会直接影响延迟。

### 13.2 Latent Diffusion

不直接在高分辨率像素空间扩散，而是：

```text
image ↔ VAE latent
text → text encoder
noise latent → U-Net/DiT denoise conditioned on text
→ VAE decode → image
```

如果直接在 `1024×1024×3` 像素空间做几十步去噪，计算与显存非常高。VAE Encoder 先把图像压缩到更小的 latent，例如空间尺寸缩小 8 倍；去噪网络在 latent 中迭代，最后 VAE Decoder 再还原为 RGB 图像。

```text
1024×1024 图像
   ↓ VAE编码（示意）
128×128 latent
   ↓ 多步扩散去噪
128×128 干净latent
   ↓ VAE解码
1024×1024 图像
```

latent 空间显著降低计算，但 VAE 的压缩能力也形成质量上限：极细文字、细线和纹理可能在压缩或解码时失真。

### 13.3 U-Net 与 DiT

- U-Net：多尺度卷积结构，扩散模型经典主干；
- DiT：使用 Transformer 在 latent patch 上建模；
- 新模型架构变化快，理解“去噪主干 + 条件 + scheduler”比死记某个类名更重要。

U-Net 先逐级下采样获取大范围语义，再逐级上采样恢复空间细节，并通过 skip connection 把早期高分辨率特征传给解码侧。文本条件常通过 Cross-Attention 注入。

DiT 把 noisy latent 切成 patch token，使用 Transformer Block 建模，并通过时间步和文本条件调节各层。无论主干是卷积还是 Transformer，它在每个扩散时间步的职责都是根据当前 noisy latent 与条件预测去噪目标；VAE 管像素与 latent 转换，Scheduler 管迭代步伐。

### 13.4 Scheduler

Scheduler 决定从高噪声走向低噪声时选哪些时间步、每一步怎样利用模型预测更新 latent。模型负责“预测去掉什么”，scheduler 负责“按什么步伐走”。

同一 checkpoint 使用 20 步和 50 步，去噪网络调用次数不同；更多步通常更慢，却不保证无限提高质量，有些模型专门蒸馏为少步生成。比较 scheduler 时要固定 seed、prompt、分辨率和 guidance，再看质量与耗时。

### 13.5 Classifier-Free Guidance

生成每一步可以分别得到“有文本条件”的预测与“弱化/无文本条件”的预测，再把二者差异放大：

```text
guided = uncond + scale × (cond - uncond)
```

`scale` 较大时，结果更努力遵循 prompt；但过大可能颜色过饱和、边缘异常、构图僵硬并降低多样性。它不是“画质强度”，也不是所有新模型都使用完全相同范围。参数应依据具体 pipeline 的 model card 调整。

## 14. P1：图像编辑、ControlNet 与 LoRA

### 14.1 Image-to-Image

先将参考图编码成 latent，再根据 `strength` 加入一定程度噪声，随后按新 prompt 去噪。噪声越少，原图结构保留越多；噪声越多，模型有越大空间重新构图。

例如把白天街景改成夜景，较低 strength 可能保留建筑和道路布局，只改变光照；很高 strength 可能连建筑形状和车辆位置都重画。`strength` 的精确定义与可用范围依 pipeline，不能跨模型机械照搬。

### 14.2 Inpainting

Inpainting 同时输入原图、mask 和 prompt。常见约定是白色区域允许重绘、黑色区域保留：

```text
原图：一面墙有破损
mask：只把破损处涂白
prompt：clean intact wall surface
结果：主要重绘白色区域，并与周围墙面融合
```

mask 边缘太硬可能留下接缝，工程上常适度羽化或扩大重绘区域，让模型拥有融合上下文。mask 黑白语义、是否自动裁剪和 strength 行为必须以具体 pipeline 为准；若黑白反了，模型会重画本来要保留的区域。

### 14.3 ControlNet/Adapter

使用边缘、深度、姿态、分割等空间条件约束生成：

```text
prompt + control image → 保留布局/姿态的生成
```

文本只描述“画什么”，不容易精确规定每个对象的位置。ControlNet/Adapter 额外接收空间条件，例如 Canny 边缘、深度图、人体姿态骨架或语义分割图，并把这些控制特征注入去噪网络。

例如输入人物姿态骨架后，prompt 可以改变服装与画风，同时尽量保持手脚位置。控制强度过高，结果可能机械贴合线条、缺少自然变化；过低则可能忽略姿态。还要确保 control 模型与 base checkpoint 系列、通道含义和预处理方式兼容，否则即使代码能运行，约束也可能失效。

### 14.4 LoRA

用少量参数学习风格、人物或概念，可加载/切换多个 adapter。需要管理 base checkpoint、触发词、权重和许可证；过拟合会导致构图单一或概念污染。

扩散 LoRA 常插入去噪网络 Attention 等线性层，有时也训练文本编码器部分层。训练数据把目标概念与 caption/触发词绑定；推理时在兼容 base 上加载 adapter 并设置权重，例如 0.6 与 1.0 会呈现不同影响强度。

数据过少或 caption 单一时，模型可能把“人物”与固定背景、服装一起记住，导致任何 prompt 都出现类似构图。验收应测试不同场景、姿态、种子和负面概念，并记录 base model 版本；跨不兼容 base 加载即使不报错，效果也可能失真。

### 14.5 最小 Diffusers 结构

```python
import torch
from diffusers import AutoPipelineForInpainting
from diffusers.utils import load_image

pipe = AutoPipelineForInpainting.from_pretrained(
    "your-inpainting-checkpoint",
    torch_dtype=torch.float16,
)
pipe.enable_model_cpu_offload()

image = load_image("input.png")
mask = load_image("mask.png")

result = pipe(
    prompt="replace the damaged area with clean material",
    image=image,
    mask_image=mask,
    strength=0.9,
    guidance_scale=7.0,
    num_inference_steps=30,
).images[0]
```

API、模型架构和推荐参数变化很快，以当前 Diffusers 与 model card 为准。

## 15. P0/P1：多模态 Agent 设计

### 15.1 工具化，不把所有能力塞进一个模型

可提供：

- `ocr_document(file_id)`；
- `detect_objects(image_id, classes)`；
- `search_video(query, time_range)`；
- `inspect_frames(video_id, timestamps)`；
- `edit_image(image_id, mask_id, prompt)`；
- `generate_image(prompt, policy)`。

Agent 负责选择工具和组合结果；专用模型负责可验证感知。

### 15.2 状态设计

不要把大图片 base64 反复写入 Agent state。保存受控对象引用和元数据：

```json
{
  "asset_id": "img_123",
  "sha256": "...",
  "mime": "image/jpeg",
  "width": 1920,
  "height": 1080,
  "owner": "tenant_a"
}
```

工具服务按权限读取对象，返回结构化结果和证据引用。

### 15.3 多阶段推理

```text
用户上传监控视频并提问
  ↓
Agent 调用视频检索定位候选片段
  ↓
检测/跟踪给出对象轨迹
  ↓
VLM 精读关键帧和时间关系
  ↓
Agent 汇总并引用时间戳
```

### 15.4 安全

- 文件类型魔数校验，不能只信扩展名；
- 限制像素数、帧数、时长、压缩炸弹；
- 远程 URL allowlist/网络隔离，防 SSRF；
- 生成与编辑内容安全检查；
- 人脸、车牌和隐私脱敏；
- 资产按租户隔离，缓存键包含租户和版本；
- 图片中的文字也可能包含提示注入，不能把它当系统指令执行。

## 16. P0：多模态评测

### 16.1 不同任务不同指标

| 任务 | 指标示例 |
|---|---|
| 分类 | accuracy、macro-F1、AUROC |
| 检测 | mAP、AP50、召回、小目标 AP |
| 分割 | mIoU、Dice |
| 跟踪 | HOTA、MOTA、IDF1、ID switch |
| OCR | CER、WER、检测 Hmean、版面顺序 |
| VQA | exact/soft accuracy、人工/模型评审 |
| Grounding | box IoU、point accuracy |
| 视频事件 | 事件召回、误报/小时、告警延迟 |
| 生成图 | 人工偏好、文本一致性、结构约束、安全、重复性 |

### 16.2 切片评测

- 分辨率与压缩；
- 小目标、遮挡、夜间、逆光；
- 中文/英文、小字、手写；
- 长视频和短事件；
- 图表、表格、公式；
- 多图和顺序；
- 对抗文本、隐私和不安全内容。

### 16.3 VLM 幻觉

要求输出：

- 可见事实；
- 推断；
- 不确定性；
- 证据区域/页码/时间戳。

对“图片中没有的信息”设计负样本，检查模型是否承认不可见，而不是合理化编造。

可以要求结构化输出把内容拆成 `visible_facts`、`inferences`、`uncertainty` 和 `evidence_regions`。例如“画面中可见湿地面”是事实，“刚下过雨”只是推断；若无法看清胸牌，应输出不可判定而不是编造姓名。

负样本包括模糊图、关键区域被遮挡、问题询问画外信息以及与语言常识相反的图片。评测不仅看最终答案，还要核对证据区域是否真的包含所述对象，防止模型用正确措辞掩盖未看图。

### 16.4 端到端指标

最终项目还要测：任务成功率、工具选择、延迟、GPU 成本、失败恢复和人工确认率。单个检测器 mAP 高不代表完整 Agent 可用。

例如检测器 mAP 提升，但阈值配置使候选片段数量翻倍，VLM 成本和误报工单也可能上升。端到端验收应从用户任务出发：事件是否找到、时间戳和证据是否正确、回答是否可审计、每小时处理成本和告警延迟是否达标，以及工具超时后能否降级。子模型指标用于定位，业务成功率才决定系统是否可用。

## 17. 综合项目：视频监控多模态检索 Agent

## 18. 常见故障与排查

### 18.1 颜色异常

检查 RGB/BGR、alpha 通道、ICC/profile、值域和 Normalize。先保存预处理后的可视化图片，而不是只看 tensor 数字。

### 18.2 检测框偏移

检查原图与模型输入尺寸、letterbox padding、坐标格式、归一化、后处理缩放和 EXIF 旋转。

### 18.3 VLM 看不清文字

- 输入被缩得过小；
- 单页信息过密；
- processor 限制视觉 token；
- OCR 更适合该任务；
- 先裁剪相关区域并保留全局上下文。

### 18.4 多图顺序混乱

检查消息内容顺序、模板占位符、processor 输入列表、batch 对齐；在图上添加编号并要求结构化逐图回答。

### 18.5 视频漏掉短事件

提高候选区域采样率，使用运动/检测触发或两阶段采样；不要只提高全视频均匀采样导致成本失控。

### 18.6 OCR 文本顺序错误

引入 layout/reading order 模型；按 block 和列处理；保存 bbox 与页面；表格走专用结构识别。

### 18.7 图像生成不遵循结构

调整 prompt、guidance、steps；使用 ControlNet/pose/depth/edge 或 inpainting；确认 checkpoint 与控制模型兼容；固定 seed 做对比。

### 18.8 显存不足

- 降低分辨率/帧数/batch；
- 使用混合精度和 attention 优化；
- CPU offload/模型量化；
- 缓存视觉编码结果；
- 将检测与 VLM 放在独立服务；
- 防止同一媒体在多轮中重复编码。

## 19. 高频面试题

### 19.1 VLM 如何把图片交给 LLM？

视觉编码器将图片变成视觉特征，经 projector/resampler 映射或压缩为 LLM 可接收的视觉 token，再与文本 token 一起进入语言模型。

### 19.2 为什么 OCR 不能完全被 VLM 替代？

密集小字、版面、表格、坐标和可追溯性需要专用 OCR/layout 链路；VLM 擅长语义理解和推理。二者组合通常更稳定、便宜、可审计。

### 19.3 目标检测与图像分类区别？

分类为整张图给标签；检测为每个目标输出类别和位置。检测需要框匹配、IoU、NMS/mAP 等额外机制。

### 19.4 视频为什么要关键帧采样？

全帧成本极高且重复。关键帧/事件触发保留主要信息；短事件需再用高频精扫补充，采样是召回与成本的权衡。

### 19.5 CLIP 能直接做复杂 VQA 吗？

CLIP 主要把图文映射到共享 embedding 空间，适合相似度和零样本分类；复杂生成式问答通常需要连接 LLM 的 VLM。

### 19.6 Diffusion 为什么在 latent 空间运行？

VAE 将图像压缩为较小 latent，在其中迭代去噪显著降低计算，再解码回像素。

### 19.7 多模态 Agent 如何防提示注入？

把图片/OCR 内容当不可信数据，不提升为系统指令；工具权限独立校验；限制 URL、文件与副作用；关键动作需策略或人工确认。

### 19.8 怎么评估多模态系统？

先按分类/检测/OCR/VQA/视频等子任务指标评测，再测 Agent 端到端成功率、证据、延迟、成本、安全，并按小目标、夜间、长视频等切片分析。
