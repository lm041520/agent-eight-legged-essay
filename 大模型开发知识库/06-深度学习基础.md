## 0. 零基础导读：一句话进入大模型后，到底发生了什么

第一次学习深度学习时，经常会立刻遇到张量、矩阵、梯度、Attention等术语。先暂时不推公式，沿着一句话的完整路径建立地图。

用户输入：

```text
杭州今天需要带伞吗？
```

大模型不会直接“看到”汉字。完整过程可以先简化为：

```text
文本
→ Tokenizer切成Token并转换成整数ID
→ Embedding把每个ID查成向量
→ 多层Transformer在Token之间传递信息
→ 输出词表中每个候选Token的分数Logits
→ 采样或选择下一个Token
→ 把新Token接到序列后继续生成
```

### 第1步：文本变成Token ID

假设为了演示，我们把文本切成：

```text
["杭州", "今天", "需要", "带伞", "吗", "？"]
```

每个Token在词表中有一个整数编号：

```text
[3812, 927, 615, 8021, 73, 12]
```

真实Tokenizer不一定按完整中文词切分，同一句话在不同模型中可能得到不同Token。这就是为什么上下文长度和计费通常按Token而不是字符计算。

### 第2步：整数ID变成向量

编号`3812`只是索引，本身没有“杭州”的数学含义。Embedding层像一张巨大的查找表：

```text
3812 → [0.12, -0.43, 0.08, ...]
927  → [-0.20, 0.31, 0.55, ...]
```

如果模型隐藏维度是4096，每个Token就会变成4096个数。6个Token形成的张量形状是：

```text
[sequence_length, hidden_size] = [6, 4096]
```

加入batch维以后是`[B,S,H]`。例如同时处理4句话，每句补齐到6个Token，形状就是`[4,6,4096]`。

所谓张量，先把它理解为“带有形状的一组数字”。每一维都必须有业务含义，不能为解决报错随意reshape。

### 第3步：Attention让Token读取其他Token的信息

仅有Embedding时，“带伞”向量还不知道前面出现了“杭州”和“今天”。Self-Attention允许每个位置根据当前任务，从其他位置聚合信息。

以“带伞”为例，可以直觉化为：

```text
当前位置提出Query：哪些词与是否带伞有关？
每个历史位置提供Key：我包含什么可匹配特征？
匹配分数较高的位置提供Value：把我的信息传过去。
```

可能得到的注意力权重只是示意：

```text
杭州 0.25
今天 0.20
需要 0.08
带伞 0.30
吗   0.10
？   0.07
```

模型不是人工写死这些比例，而是在训练中学习怎样投影Q、K、V。

### 第4步：为什么需要很多层

一层Attention只能进行一次信息混合。经过多层以后，Token表示会逐步包含更复杂的上下文关系：

```text
早期层：字词和局部模式
中间层：句法、实体和语义关系
更深层：任务相关的组合和预测线索
```

这是一种帮助理解的概括，不代表每一层有固定的人类可读职责。

### 第5步：模型输出Logits

最后一个位置的隐藏向量经过LM Head，得到词表中每个Token的分数。假设词表只有五个候选：

```text
"建议"  8.2
"不"    6.1
"今天"  2.3
"苹果" -1.4
"结束"  0.5
```

这些未归一化分数叫Logits。Softmax把它们转换成概率。模型选择“建议”后，序列变成：

```text
杭州今天需要带伞吗？建议
```

然后再预测下一个Token。生成是逐Token进行的，不是一次把整段答案从某个数据库中取出来。

### 第6步：训练时模型怎样知道自己错了

假设训练样本中的正确下一个Token是“建议”，模型却只给它10%概率。交叉熵损失会产生较大惩罚；如果模型给了90%，损失较小。

训练循环可以简化为：

```text
前向传播：输入 → 预测概率 → 计算Loss
反向传播：从Loss计算每个参数对错误的贡献梯度
优化器更新：沿着降低Loss的方向微调参数
重复大量样本和步骤
```

梯度不是“正确答案本身”，而是告诉每个参数：如果稍微增大或减小，Loss会朝哪个方向变化。

### 一个只有一个参数的训练例子

先看最简单函数：

\[
\hat{y}=w x
\]

训练样本是`x=2, y=10`。若初始`w=3`：

```text
预测值 = 3 × 2 = 6
误差 = 6 - 10 = -4
平方损失 = (-4)² = 16
```

为了让预测靠近10，需要让`w`增大。反向传播计算出梯度，优化器把`w`从3更新到更大的值。经过多步，`w`会逐渐接近5。

```python
import torch

w = torch.tensor(3.0, requires_grad=True)
x = torch.tensor(2.0)
y = torch.tensor(10.0)

prediction = w * x
loss = (prediction - y) ** 2
loss.backward()

print(prediction.item())  # 6.0
print(loss.item())        # 16.0
print(w.grad.item())      # -16.0
```

梯度为负，按照`w = w - learning_rate * gradient`更新时，减去负数会让`w`增大。

大模型拥有数十亿参数、复杂矩阵和大量样本，但“前向计算—Loss—反向梯度—优化器更新”的主线没有改变。

### 训练与推理先分清

| 阶段 | 是否有标准答案 | 是否计算梯度 | 是否更新参数 | 主要目标 |
|---|---|---|---|---|
| 训练 | 有训练标签 | 是 | 是 | 学习参数 |
| 推理 | 通常没有 | 否 | 否 | 使用已有参数生成结果 |

推理时使用`torch.inference_mode()`，因为不需要保存反向传播所需的计算图和激活，可以减少内存与开销。

### 后续术语放回这张地图

| 术语 | 它在完整流程中的位置 |
|---|---|
| Tokenizer | 文本转Token ID |
| Embedding | Token ID转隐藏向量 |
| Q/K/V | Attention中的信息匹配与聚合 |
| Logits/Softmax | 隐藏向量转词表概率 |
| Loss | 衡量预测与训练目标差距 |
| Backpropagation | 计算参数梯度 |
| Optimizer | 根据梯度更新参数 |
| KV Cache | 推理生成时复用历史K/V |
| LoRA | 冻结大部分参数，只训练低秩增量 |

带着这条链路再学习下面的数学和PyTorch，每个概念都会有明确位置。

## 2. P0：张量、向量和矩阵

### 2.1 标量、向量、矩阵与高维张量

- 标量：一个数，例如学习率 `0.0001`。
- 向量：一组有顺序的数，例如一个 token 的 4096 维表示。
- 矩阵：二维数表，例如线性层权重 `[out_features, in_features]`。
- 张量：对标量、向量、矩阵的统一称呼，也可以有三维及以上。

大模型常见形状：

| 张量 | 常见形状 | 含义 |
|---|---:|---|
| `input_ids` | `[B, S]` | B 个样本，每个样本 S 个 token |
| hidden states | `[B, S, H]` | 每个 token 有 H 维隐藏表示 |
| attention scores | `[B, heads, S, S]` | 每个头中，各 token 对其他 token 的注意力分数 |
| logits | `[B, S, V]` | 每个位置对 V 个词表 token 的未归一化分数 |

其中：

- `B`：batch size；
- `S`：sequence length；
- `H`：hidden size；
- `V`：vocabulary size。

工程中遇到 shape mismatch，第一步不是乱加 `reshape`，而是逐层写清楚每个维度的语义。

### 2.2 点积为什么重要

两个向量的点积：

\[
x \cdot y = \sum_i x_i y_i
\]

它同时承担三类作用：

1. 线性层计算：输入向量与权重做加权求和；
2. 相似度：方向越接近，点积通常越大；
3. Attention：Query 与 Key 的匹配程度通过点积得到。

余弦相似度进一步消除向量长度的影响：

\[
\cos(x,y)=\frac{x\cdot y}{\|x\|\|y\|}
\]

RAG 中 embedding 检索常用余弦相似度或点积。是否需要归一化，要看模型说明和向量数据库的距离定义，不能默认所有 embedding 都一样。

### 2.3 矩阵乘法的形状规则

若：

```text
X: [B, in]
W: [in, out]
```

则：

```text
X @ W -> [B, out]
```

PyTorch 的 `nn.Linear(in, out)` 内部权重通常保存为 `[out, in]`，调用时等价于 `x @ weight.T + bias`。面试中说清“数学写法”和“框架存储形状”不同即可。

## 3. P0：概率、Softmax 与损失函数

### 3.1 Logits、概率与 Softmax

模型输出的 `logits` 不是概率，可以是任意实数。Softmax 将其转换为和为 1 的概率：

\[
p_i=\frac{e^{z_i}}{\sum_j e^{z_j}}
\]

大模型生成时，每个位置会得到整个词表的 logits，再结合 temperature、top-k、top-p 等规则选择下一个 token。

### 3.2 Temperature 改变什么

采样前通常使用：

\[
p_i=\text{softmax}(z_i/T)
\]

- `T < 1`：分布更尖锐，更确定；
- `T > 1`：分布更平坦，随机性更强；
- 极低 temperature 不等于模型“更聪明”，只是更偏向高分 token；
- 某些推理接口在 `temperature=0` 时直接使用 greedy decoding，具体行为需查接口文档。

### 3.3 交叉熵损失

若真实答案是类别 `y`，交叉熵可以理解为：

\[
L=-\log p_y
\]

真实 token 的预测概率越低，惩罚越大。语言模型训练通常是“预测下一个 token”：

```text
输入:  我 喜欢 学习
标签:  喜欢 学习 <EOS>
```

实现中往往由模型内部完成 logits 与 labels 的错位对齐，但阅读代码时必须确认框架约定。

### 3.4 KL 散度

KL 散度衡量一个概率分布相对于另一个分布的偏离：

\[
D_{KL}(P\|Q)=\sum_i P(i)\log\frac{P(i)}{Q(i)}
\]

在后训练中，它常用来约束新策略不要偏离参考模型过远；在知识蒸馏中，也可用于让学生模型拟合教师模型的输出分布。

例如参考模型对三个 token 的概率是 `P=[0.7, 0.2, 0.1]`，新模型变成 `Q=[0.2, 0.7, 0.1]`。两者最可能的 token 已经互换，KL 会明显增大；若 Q 只变成 `[0.68, 0.21, 0.11]`，偏离较小。

KL 不是普通距离：`D_KL(P||Q)` 通常不等于 `D_KL(Q||P)`，并且当 Q 给 P 认为可能的事件分配接近 0 的概率时，惩罚会很大。后训练中的 KL penalty 可以理解为一根“安全绳”：奖励推动策略学新偏好，KL 约束阻止它为追逐奖励而突然遗忘原有语言能力或改变过大。系数太强会几乎学不动，太弱则可能奖励过优化。

## 4. P0：前向传播、反向传播与梯度下降

### 4.1 一个神经元做了什么

最简单的线性计算：

\[
z=Wx+b
\]

再经过激活函数：

\[
h=f(z)
\]

多层网络就是不断重复“线性变换 + 非线性变换”。如果没有非线性激活，多层线性层仍可合并为一个线性变换，表达能力不会真正增加。

假设输入是 `[温度=30, 湿度=0.8]`，权重为 `[0.1, 2.0]`，偏置为 `-1`：

```text
z = 30×0.1 + 0.8×2.0 - 1 = 3.6
h = ReLU(3.6) = 3.6
```

权重表示每个输入对当前特征的重要方向，偏置让激活阈值可以平移。真实网络不是一个神经元，而是把很多输入样本组成矩阵，一次计算整层输出：`[batch, in_features] @ [in_features, out_features]`。Transformer 中的 Q/K/V 投影和 FFN 本质上也大量使用这种线性层。

非线性为什么必要？若连续两层都只有线性变换，`W2(W1x+b1)+b2` 仍可整理成新的 `Wx+b`，增加层数没有产生真正弯曲的决策边界。ReLU、SiLU、GELU 等激活让网络能够表示更复杂关系。

### 4.2 常见激活函数

- ReLU：简单高效，但负区间梯度为 0；
- GELU：Transformer 中常见，变化更平滑；
- SiLU/Swish：现代大模型常用；
- SwiGLU：将门控机制引入前馈网络，很多现代 LLM 使用其变体。

面试不必背全部曲线，但要知道激活函数提供非线性，门控变体可以控制信息流。

### 4.3 链式法则和反向传播

若损失 `L` 依赖中间变量 `z`，而 `z` 又依赖参数 `w`：

\[
\frac{\partial L}{\partial w}
=\frac{\partial L}{\partial z}
\frac{\partial z}{\partial w}
\]

反向传播就是从 loss 沿计算图反向应用链式法则，得到每个可训练参数的梯度。PyTorch autograd 会记录参与计算的操作并自动求导。

### 4.4 参数更新

最基本的梯度下降：

\[
w \leftarrow w-\eta\nabla_w L
\]

`η` 是学习率。学习率过大可能震荡或出现 NaN，过小则训练缓慢甚至停滞。

若 `w=2`、当前梯度 `∂L/∂w=3`、学习率 `η=0.1`，更新后为 `2-0.1×3=1.7`。梯度为正意味着增大 w 会让 loss 上升，所以沿负梯度方向减小 w。

一次更新只利用当前 batch 对总体目标的近似。不同 batch 的梯度会有噪声，因此训练会呈波动下降而不是每一步都更好。学习率过大时可能从最优点一侧跨到另一侧并不断震荡；过小时每步移动很短。Warmup、学习率调度和 AdamW 都是在基本更新规则上控制步长与历史信息。

### 4.5 SGD、Adam 与 AdamW

优化器要解决的问题是：已经通过反向传播知道了每个参数应该往哪个方向改，接下来究竟改多少。

先看只有一个参数 `w` 的例子。假设当前 `w=3`，梯度是 `-4`，学习率是 `0.1`，最普通的一次更新是：

```text
新参数 = 旧参数 - 学习率 × 梯度
       = 3 - 0.1 × (-4)
       = 3.4
```

梯度为负，说明增大 `w` 能让 loss 下降，所以更新后 `w` 从 3 变成了 3.4。

**SGD** 基本上就是按当前梯度更新。它的逻辑简单，但某个 batch 的噪声可能让方向左右摇摆。Momentum 会额外保存一份“过去若干步的移动趋势”：如果最近一直朝同一方向走，就继续加速；如果梯度突然反向，则不会马上完全掉头。这很像推购物车，已有速度不会瞬间消失。

**Adam** 同时记录两类历史信息：

1. 梯度的一阶矩，可粗略理解为最近的平均方向；
2. 梯度的二阶矩，可粗略理解为最近梯度幅度有多大。

因此，不同参数会得到不同的自适应步长。某个参数的梯度长期很大时，Adam 会适当缩小它的实际步长；梯度较小的参数则可能获得相对更大的步长。它不是“不需要学习率”，而是在全局学习率基础上再为参数调整尺度。

**AdamW** 是 Transformer 训练中更常见的选择。它把 weight decay 从 Adam 的梯度计算中解耦，先按 Adam 更新参数，再单独让部分权重轻微衰减，从而更明确地控制正则化效果。

```python
from torch.optim import AdamW

optimizer = AdamW(
    model.parameters(),
    lr=2e-5,
    weight_decay=0.01,
)
```

不要把 weight decay 简单理解成“给所有参数加 L2”。实践中常把 bias 和 LayerNorm/RMSNorm 参数排除在 weight decay 之外，因为这些参数主要负责平移或缩放，盲目衰减可能伤害训练稳定性。面试时至少要能说清：学习率控制每步更新强度，优化器决定怎样利用历史梯度，weight decay 用于抑制权重无限变大。

### 4.6 `zero_grad()` 为什么必须调用

PyTorch 默认累加梯度：

```python
optimizer.zero_grad()
loss.backward()
optimizer.step()
```

若忘记清零，当前 batch 的梯度会叠加到之前的梯度上。梯度累积正是有意识地利用这一行为，但必须按设定步数缩放 loss 并更新。

## 5. P0：训练过程中的核心概念

### 5.1 Batch、Step 与 Epoch

- sample：一个训练样本；
- batch：一次前向/反向处理的一组样本；
- step：一次参数更新；
- epoch：完整遍历一次训练集。

如果使用梯度累积：

```text
micro_batch_size = 2
gradient_accumulation_steps = 8
data_parallel_size = 4
effective_batch_size = 2 × 8 × 4 = 64
```

### 5.2 训练集、验证集和测试集

三份数据的区别，不在于文件名，而在于**模型开发过程中是否允许利用它们做决定**。

假设有 10,000 条客服问答数据，可以先按业务实体或时间切分为：

| 数据 | 例子数量 | 什么时候使用 | 是否更新参数 |
|---|---:|---|---|
| 训练集 | 8,000 | 每个训练 step 计算 loss、反向传播 | 是 |
| 验证集 | 1,000 | 每个 epoch 后比较模型、选学习率和 checkpoint | 否 |
| 测试集 | 1,000 | 方案全部确定后做一次最终报告 | 否 |

训练过程可能出现下面的结果：

```text
epoch 1：训练准确率 78%，验证准确率 75%
epoch 2：训练准确率 86%，验证准确率 82%
epoch 3：训练准确率 92%，验证准确率 81%
```

第 3 轮训练集继续变好，但验证集已经下降，说明模型可能开始记忆训练样本。此时通常保留第 2 轮 checkpoint，而不是第 3 轮。

为什么不能反复看测试集再改模型？因为每看一次测试结果并据此修改提示词、数据或超参数，就已经间接把测试信息用于开发。久而久之，方案会专门适应这份测试集，测试分数便不再代表真实新请求。

LLM 数据还容易出现更隐蔽的泄漏：

- 同一篇文档切出的相邻段落，一部分进入训练集、另一部分进入测试集；
- 同一个问题只换了几个字，在两份数据中同时出现；
- 标准答案或判断标签已经出现在 prompt 中；
- 按模板生成的数据随机切分后，训练集和测试集拥有几乎相同的表达；
- 线上未来数据被错误混入了训练时间范围。

因此切分时常按用户、文档、任务或时间分组，而不是简单逐行随机。一个实用原则是：测试样本应尽量模拟模型部署后真正遇到的“没见过的数据”。

### 5.3 欠拟合与过拟合

| 现象 | 训练集 | 验证集 | 可能原因 |
|---|---|---|---|
| 欠拟合 | 表现差 | 表现差 | 模型/训练不足、数据噪声、学习率不合适 |
| 过拟合 | 持续变好 | 先好后差 | 数据少、训练过久、正则不足 |
| 数据分布漂移 | 好 | 特定场景差 | 训练数据与真实请求不同 |

常见缓解方法：更多高质量数据、weight decay、dropout、数据增强、早停、降低训练轮数、冻结部分参数。

### 5.4 梯度消失、梯度爆炸与裁剪

深层网络的梯度要利用链式法则从最后一层一路乘回前面的层。连续相乘会产生两种极端情况：

```text
0.5 × 0.5 × 0.5 × ...  -> 越来越接近 0
2.0 × 2.0 × 2.0 × ...  -> 越来越大
```

前一种对应**梯度消失**：靠前层几乎收不到学习信号，参数看似在训练，实际上长时间不动。后一种对应**梯度爆炸**：一次更新就把参数推得很远，loss 突然升高，甚至出现 `inf` 或 `NaN`。

排查时可以记录总梯度范数：

```python
loss.backward()

total_norm = torch.nn.utils.clip_grad_norm_(
    model.parameters(),
    max_norm=1.0,
)
print("裁剪前的梯度范数:", float(total_norm))

optimizer.step()
```

如果总范数原本是 20，而 `max_norm=1.0`，PyTorch 会按比例缩小所有梯度，使整体方向基本不变、长度降到 1 左右。这像给汽车加限速器，可以阻止某一步突然失控。

但梯度裁剪只是保护措施。如果每一步都在剧烈裁剪，真正的问题可能是学习率过高、异常样本导致 loss 极大、混合精度溢出、初始化不合理，或训练代码中存在错误。残差连接为梯度提供更短的传播路径，LayerNorm/RMSNorm 控制激活尺度，合理初始化则让前向值和反向梯度一开始就处在可训练范围内。

## 6. P0：Tokenization 与 Embedding

### 6.1 为什么不能直接按汉字或单词训练

固定词表面临两个矛盾：

- 词表太小：很多词无法表示，序列变长；
- 词表太大：Embedding 和输出层参数量膨胀，低频词学习不足。

子词算法在字符和完整词之间折中。常见思想包括 BPE、WordPiece、Unigram/SentencePiece。面试重点不是背训练算法，而是理解：文本先被切为 token id，模型处理的是 id 序列而非原始字符串。

### 6.2 特殊 token

常见特殊 token：

- BOS：序列开始；
- EOS：序列结束；
- PAD：批处理补齐；
- UNK：未知 token；
- 模型特定的 system/user/assistant、工具调用或图像占位 token。

不同模型模板不同。直接自己拼 `"User: ... Assistant:"` 可能破坏模型训练时使用的格式。

### 6.3 Attention Mask 与 Label Mask

二者经常同时出现，但回答的是两个完全不同的问题：

- **attention mask**：当前位置计算表示时，允许读取哪些 token？
- **label mask**：训练计算总 loss 时，哪些位置需要被评分？

先看 batch 补齐。两个句子的 token 长度分别是 5 和 3，为了组成矩阵，第二句要补两个 PAD：

```text
input_ids:
样本A [11, 12, 13, 14, 15]
样本B [21, 22, 23,  0,  0]

attention_mask:
样本A [ 1,  1,  1,  1,  1]
样本B [ 1,  1,  1,  0,  0]
```

末尾两个 0 告诉模型：这些只是为了对齐矩阵而添加的位置，不应被当成真实内容。Decoder-only 模型内部还会叠加 causal mask，使第 3 个位置只能看第 1～3 个 token，不能偷看未来答案。

再看 SFT 的 label mask。假设训练文本是：

```text
用户：北京天气怎样？ 助手：今天晴，最高 28 度。
```

我们希望模型阅读用户问题，却只因助手答案预测得好坏而受到奖惩。可以把标签概念化为：

```text
tokens: [用户, ：, 北京, 天气, 怎样, ？, 助手, ：, 今天, 晴, ...]
labels: [-100,-100,-100,-100,-100,-100,-100,-100, 今天, 晴, ...]
```

`-100` 是 Transformers/PyTorch 常用的忽略标记，这些位置仍然参与前向计算，也能被后面的助手 token 注意到，只是不计入交叉熵 loss。若把用户问题也错误纳入 loss，模型会花能力学习复述输入格式；若把助手 token 也全部设为 `-100`，则没有有效监督信号，loss 可能变成异常值或训练完全无效。

记忆方式：attention mask 管“能不能看”，label mask 管“算不算错”。

### 6.4 Chat Template

Hugging Face tokenizer 可通过 `apply_chat_template` 将消息列表转换为模型所需 token 格式：

```python
messages = [
    {"role": "system", "content": "你是严谨的助手。"},
    {"role": "user", "content": "解释 KV Cache。"},
]

text = tokenizer.apply_chat_template(
    messages,
    tokenize=False,
    add_generation_prompt=True,
)
```

`add_generation_prompt=True` 通常用于推理，表示下一段应由 assistant 开始；训练数据是否添加要遵循模型与训练框架约定。工具调用、RAG documents 等模板能力也是模型相关的，不能假设所有 tokenizer 都支持。

### 6.5 Embedding 层

Embedding 可以理解为一张可训练查找表：

```text
token id -> H 维向量
```

位置编码再为每个 token 注入位置信息。LLM 中常见 RoPE（旋转位置编码），它把相对位置信息融入 Query/Key。长上下文扩展通常涉及 RoPE scaling、训练分布与注意力计算，不能只改一个最大长度参数就认为效果不变。

## 7. P0：Transformer 核心机制

### 7.1 整体结构

Decoder-only LLM 的主干可以简化为：

```text
token ids
  ↓ Embedding + position information
hidden states
  ↓ [Attention + residual + normalization]
  ↓ [Feed Forward + residual + normalization]
  ↓ 重复 N 层
final hidden states
  ↓ LM head
vocabulary logits
```

### 7.2 Query、Key、Value

输入隐藏状态 `X` 经过三个线性投影：

\[
Q=XW_Q,\quad K=XW_K,\quad V=XW_V
\]

直觉：

- Query：当前位置想找什么；
- Key：每个位置能提供什么索引特征；
- Value：真正要汇总的信息。

Scaled Dot-Product Attention：

\[
Attention(Q,K,V)=softmax(\frac{QK^T}{\sqrt{d_k}}+mask)V
\]

除以 `sqrt(d_k)` 是为了避免维度增大后点积幅度过大，使 Softmax 过度饱和、梯度变差。

### 7.3 Causal Mask

自回归模型训练时，第 `t` 个位置不能看到未来 token。Causal mask 会屏蔽注意力矩阵的右上角：

```text
位置 1 可看: 1
位置 2 可看: 1,2
位置 3 可看: 1,2,3
```

虽然训练时整段序列可并行计算，但 mask 保证每个位置只利用历史信息。

### 7.4 Multi-Head Attention

单头注意力只在一套 Q、K、V 投影空间里比较 token。多头注意力则把隐藏表示投影成多组较小的 Q、K、V，让不同组独立寻找关系，最后再拼接起来。

例如 hidden size 为 512，使用 8 个头，则每个头的 head dimension 通常为 `512 / 8 = 64`：

```text
输入 [batch, seq, 512]
  ├─ head 1: [batch, seq, 64]
  ├─ head 2: [batch, seq, 64]
  ├─ ...
  └─ head 8: [batch, seq, 64]
          ↓ 每个头独立做注意力
拼接回 [batch, seq, 512]
          ↓ 输出投影
新的 token 表示
```

“不同头学习不同关系”是一种直觉解释，并不保证某个头固定负责语法、另一个头固定负责实体。真正可确认的是：多个头拥有不同投影参数，因此可以在不同表示子空间中建立关联。

推理时，Query 只用于当前计算，历史 Key/Value 则要进入 KV Cache。因此现代模型会减少 KV 头数量来节省显存：

| 结构 | Query 头与 KV 头关系 | KV Cache | 常见取舍 |
|---|---|---|---|
| MHA | 每个 Query 头有自己的 K/V 头 | 最大 | 表达能力充分，缓存成本高 |
| MQA | 所有 Query 头共享一组 K/V | 最小 | 推理省显存，但共享程度最高 |
| GQA | 若干 Query 头共享一组 K/V | 居中 | 质量和推理成本的常见折中 |

假设有 32 个 Query 头，MHA 也有 32 个 KV 头；若 GQA 只有 8 个 KV 头，同精度和同序列长度下，K/V 缓存中“头”这一维大约可降到四分之一。

### 7.5 Feed Forward Network

Attention 让不同 token 交换信息，FFN 则对每个 token 的表示分别做一次更强的非线性变换。二者分工可以粗略记成：Attention 负责“去哪里取信息”，FFN 负责“拿到信息后怎样加工”。

最简单的 FFN 由升维、激活、降维组成：

```text
[seq, hidden=4096]
    ↓ 线性层升维
[seq, intermediate=11008]
    ↓ SiLU/GELU 等非线性激活
[seq, intermediate=11008]
    ↓ 线性层降维
[seq, hidden=4096]
```

对同一层来说，第 1 个 token 和第 20 个 token 使用相同的 FFN 参数，但二者在 FFN 中不会互相读取；它们之前的信息交换已经由 Attention 完成。Llama 等模型常使用带门控的 SwiGLU 变体，它会生成两路中间结果，用一路控制另一路保留多少信息。由于中间维度通常远大于 hidden size，FFN 往往占据 Transformer 的大量参数和矩阵乘计算。

### 7.6 残差连接与归一化

如果一个子层必须从头生成完整的新表示，几十层连续训练会很困难。残差连接把子层输出与原输入相加：

```text
output = x + sublayer(x)
```

这样子层只需学习“在原有表示上增加什么”。即使 `sublayer(x)` 在训练初期接近 0，信息仍能沿着 `x` 直接向后传，梯度也拥有更短的返回路径。

归一化解决的是数值尺度问题。若某一层输出数值越来越大，后续注意力分数、激活和梯度都可能不稳定。LayerNorm 会利用当前 token 隐藏维度的均值和方差做标准化；RMSNorm 主要利用均方根缩放，计算更简洁，现代 LLM 中很常见。

Pre-Norm 和 Post-Norm 描述归一化放在子层的哪个位置：

```text
Pre-Norm:  x -> Norm -> Attention -> +x
Post-Norm: x -> Attention -> +x -> Norm
```

现代 Decoder-only LLM 常采用 Pre-Norm 或其变体，因为深层训练通常更稳定。归一化不是把每个 token 变成相同内容，而是调整各隐藏维度的整体尺度，token 之间的信息差异仍然保留。

### 7.7 Decoder-only 为什么适合生成

它使用因果注意力，不断根据已有 token 预测下一个 token：

```text
prompt -> token_1 -> token_2 -> ... -> EOS
```

Agent 的“思考、工具参数、最终回答”从模型视角都是 token 序列，只是外部框架会解析其中的结构并执行工具。

## 8. P0/P1：Prefill、Decode 与 KV Cache

### 8.1 两个推理阶段

**Prefill**：一次处理整个提示词，计算所有输入 token 的隐藏状态和 KV。计算量大但并行度高，主要影响 TTFT（首 token 延迟）。

**Decode**：每次生成一个新 token。每步只需要计算新 token 的 Query，并与历史 KV 做注意力；并行度低但重复很多次，影响 TPOT（每输出 token 时间）。

### 8.2 为什么需要 KV Cache

如果每生成一个 token 都重新计算全部历史 token 的 K、V，会大量重复。KV Cache 保存每层历史 token 的 Key 和 Value，后续步骤直接复用。

代价是显存随以下因素增长：

```text
层数 × KV 头数 × head_dim × 序列长度 × batch/并发 × 数据精度
```

因此长上下文和高并发往往先受 KV Cache 显存限制，而不只是模型权重。

### 8.3 FlashAttention、PagedAttention 分别解决什么

这两个名称都含有 Attention，但解决的是不同层面的问题。

标准注意力的概念公式会先形成一个 `[序列长度 × 序列长度]` 的分数矩阵。长序列下，这个中间矩阵很大，而且 GPU 不得不反复把数据在高带宽显存和计算单元之间搬运。**FlashAttention** 重新组织计算顺序，将 Q、K、V 分块放入更快的片上存储，在块内完成分数、softmax 和加权求和，并避免完整保存巨大的中间矩阵。最终数学结果仍是注意力，重点是减少 IO 和中间存储。

可以把它理解为：不是先把全班每两个人的关系都写在一张巨表上再统计，而是每次处理一小组、保留必要的累计结果，最后得到相同答案。

**PagedAttention** 面向在线推理中的 KV Cache 管理。不同请求的长度不一样，而且会随着 Decode 不断增长。如果每个请求预先申请一块连续且足够大的显存，会出现两类浪费：申请太大导致空闲，申请太小又难以扩展。PagedAttention 把 KV Cache 切成固定大小的 block，再用映射表把一个请求的逻辑连续序列连接到多个不必物理连续的 block：

```text
请求A的逻辑页: [0, 1, 2]
实际显存块:     [7, 3, 12]

请求B的逻辑页: [0, 1]
实际显存块:     [5, 9]
```

因此请求结束后可以回收其块，新 token 到来时也能按需增加块，减少显存碎片并方便连续批处理。

最终区别是：FlashAttention 优化一次注意力算子“怎么算”；PagedAttention 优化大量在线请求的 KV Cache“怎么存、怎么分配”。它们不冲突，同一个推理服务可以同时使用二者。

## 9. P1：MoE 基础

Mixture of Experts 用多个 FFN 专家替代单一 FFN，并由路由器为每个 token 选择少数专家：

```text
token hidden state
  ↓ router
top-k experts
  ↓ expert computation
weighted combine
```

优势：总参数量可以很大，但每个 token 只激活部分参数，计算量相对可控。

代价：

- 路由负载可能不均；
- 跨设备专家通信复杂；
- 权重仍需存储；
- 推理吞吐与延迟受并行策略影响。

Agent 开发岗知道原理即可；训练/推理岗需进一步理解 expert parallel、负载均衡损失和通信开销。

## 10. P0：PyTorch 张量与自动求导

### 10.1 最小示例

```python
import torch

x = torch.tensor([[1.0, 2.0]], requires_grad=False)
w = torch.randn(2, 1, requires_grad=True)
b = torch.zeros(1, requires_grad=True)

y_pred = x @ w + b
loss = (y_pred - 1.0).pow(2).mean()
loss.backward()

print("loss:", loss.item())
print("w.grad:", w.grad)
print("b.grad:", b.grad)
```

`loss.backward()` 之后，叶子参数的 `.grad` 中保存梯度。推理阶段应使用 `torch.inference_mode()` 或 `torch.no_grad()`，避免构建无用计算图。

### 10.2 Device 与 dtype

```python
device = torch.device("cuda" if torch.cuda.is_available() else "cpu")
x = torch.randn(4, 8, device=device, dtype=torch.float32)
```

常见问题：

- 模型在 GPU，输入在 CPU；
- 一部分张量是 FP32，另一部分是 FP16；
- 索引张量应为整数类型；
- NumPy 转换后的 dtype 与模型不一致。

排查时打印：

```python
print(tensor.shape, tensor.dtype, tensor.device)
```

### 10.3 `nn.Module`

```python
from torch import nn

class TinyClassifier(nn.Module):
    def __init__(self, input_dim: int, hidden_dim: int, num_classes: int):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(input_dim, hidden_dim),
            nn.GELU(),
            nn.Dropout(0.1),
            nn.Linear(hidden_dim, num_classes),
        )

    def forward(self, x):
        return self.net(x)
```

把层赋值为 Module 属性后，PyTorch 才能注册参数、迁移设备并保存 state dict。普通 Python list 中的子层不会自动注册，应使用 `nn.ModuleList`。

## 11. P0：Dataset、DataLoader 与训练循环

### 11.1 数据集

```python
from torch.utils.data import Dataset

class VectorDataset(Dataset):
    def __init__(self, features, labels):
        self.features = features
        self.labels = labels

    def __len__(self):
        return len(self.labels)

    def __getitem__(self, index):
        return self.features[index], self.labels[index]
```

`DataLoader` 负责批处理、打乱、并行加载和内存固定：

```python
from torch.utils.data import DataLoader

loader = DataLoader(
    dataset,
    batch_size=32,
    shuffle=True,
    num_workers=0,
    pin_memory=torch.cuda.is_available(),
)
```

Windows 上增加 `num_workers` 时注意主入口保护，并测试数据处理是否可序列化。不是 worker 越多越快，瓶颈可能在磁盘、CPU、GPU 或 Python 预处理。

### 11.2 完整训练与验证骨架

```python
import torch
from torch import nn

def train_one_epoch(model, loader, optimizer, device):
    model.train()
    total_loss = 0.0

    for features, labels in loader:
        features = features.to(device)
        labels = labels.to(device)

        optimizer.zero_grad(set_to_none=True)
        logits = model(features)
        loss = nn.functional.cross_entropy(logits, labels)
        loss.backward()
        torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)
        optimizer.step()

        total_loss += loss.item() * features.size(0)

    return total_loss / len(loader.dataset)


@torch.inference_mode()
def evaluate(model, loader, device):
    model.eval()
    correct = 0
    total = 0

    for features, labels in loader:
        features = features.to(device)
        labels = labels.to(device)
        predictions = model(features).argmax(dim=-1)
        correct += (predictions == labels).sum().item()
        total += labels.numel()

    return correct / total
```

关键点：

- `model.train()` 开启 Dropout 等训练行为；
- `model.eval()` 切换为评估行为，但它不会自动关闭梯度；
- `inference_mode()` 关闭 autograd，进一步减少开销；
- loss 应按样本数正确聚合，最后一个 batch 可能不足 batch size。

### 11.3 保存与恢复

推荐保存状态而不是直接 pickle 整个模型对象：

```python
torch.save(
    {
        "model": model.state_dict(),
        "optimizer": optimizer.state_dict(),
        "epoch": epoch,
        "best_metric": best_metric,
    },
    "checkpoint.pt",
)
```

恢复训练还应保存 scheduler、随机数状态和数据采样位置。仅恢复模型权重不等于无缝续训。

## 12. P1：混合精度、梯度累积与显存优化

### 12.1 FP32、FP16、BF16

| 精度 | 范围/精度特点 | 常见用途 |
|---|---|---|
| FP32 | 范围和有效位较充足 | 基准、部分敏感计算 |
| FP16 | 范围较小，可能溢出/下溢 | 支持广、常配合 loss scaling |
| BF16 | 指数范围接近 FP32，有效位更少 | 支持时通常更稳定 |

混合精度不是把所有操作强制改成低精度，而是让适合的操作使用低精度，敏感操作保留更高精度。

### 12.2 AMP 示例

```python
scaler = torch.amp.GradScaler("cuda")

for features, labels in loader:
    optimizer.zero_grad(set_to_none=True)

    with torch.autocast(device_type="cuda", dtype=torch.float16):
        logits = model(features.cuda(non_blocking=True))
        loss = torch.nn.functional.cross_entropy(logits, labels.cuda())

    scaler.scale(loss).backward()
    scaler.unscale_(optimizer)
    torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
    scaler.step(optimizer)
    scaler.update()
```

具体 API 会随 PyTorch 版本调整，使用时以当前 `torch.amp` 官方文档为准。若硬件原生支持 BF16，通常不需要 FP16 的动态 loss scaling，但仍需实测。

### 12.3 梯度累积

```python
accumulation_steps = 8
optimizer.zero_grad(set_to_none=True)

for step, batch in enumerate(loader, start=1):
    loss = compute_loss(batch) / accumulation_steps
    loss.backward()

    if step % accumulation_steps == 0:
        optimizer.step()
        optimizer.zero_grad(set_to_none=True)
```

注意最后不足一个累积周期的 batch、分布式梯度同步、学习率与有效 batch size 的变化。

### 12.4 Gradient Checkpointing

训练的反向传播需要知道前向计算时产生的中间激活。普通做法是把每一层激活都保留在显存中，等反向时直接使用。模型层数多、序列长、batch 大时，这部分显存可能比想象中更大。

Gradient checkpointing 不保存所有层的激活，只保留若干“检查点”。例如 12 层模型只保存第 0、4、8、12 层：

```text
普通方式：保存 L0 L1 L2 L3 L4 L5 L6 L7 L8 L9 L10 L11 L12
开启后：  保存 L0          L4          L8             L12
```

反向传播需要 L5～L7 的中间值时，程序会从保存的 L4 再执行一次前向计算，临时恢复这些激活。这样显存占用降低，但同一部分前向计算做了不止一次，训练速度会变慢。

```python
model.gradient_checkpointing_enable()
```

它适合“显存不够，愿意用更多计算时间交换”的情况，不能减少模型参数或优化器状态本身。还要区分两个容易混淆的词：

- gradient checkpointing：训练中的激活重计算技术；
- model checkpoint：保存在磁盘上的权重、优化器状态和训练进度文件。

### 12.5 多卡训练的最小认知

- Data Parallel/DDP：每张卡有完整模型，处理不同数据，聚合梯度；
- FSDP/ZeRO：将参数、梯度、优化器状态分片；
- Tensor Parallel：把单层矩阵计算分到多卡；
- Pipeline Parallel：把不同层分到不同阶段；
- Expert Parallel：MoE 专家分布到不同设备。

应用岗能区分即可；训练岗需理解通信、显存、吞吐、容错与 checkpoint 格式。

## 13. P0/P1：Hugging Face Transformers 与 Datasets

### 13.1 加载 tokenizer 和模型

```python
import torch
from transformers import AutoModelForCausalLM, AutoTokenizer

model_name = "your-model-id"

tokenizer = AutoTokenizer.from_pretrained(model_name)
model = AutoModelForCausalLM.from_pretrained(
    model_name,
    torch_dtype="auto",
    device_map="auto",
)

messages = [{"role": "user", "content": "用一句话解释反向传播。"}]
inputs = tokenizer.apply_chat_template(
    messages,
    add_generation_prompt=True,
    return_tensors="pt",
    return_dict=True,
).to(model.device)

with torch.inference_mode():
    output_ids = model.generate(
        **inputs,
        max_new_tokens=128,
        do_sample=False,
    )

new_tokens = output_ids[0, inputs["input_ids"].shape[1]:]
print(tokenizer.decode(new_tokens, skip_special_tokens=True))
```

真实使用前检查：

- 模型仓库是否需要 `trust_remote_code`；开启它意味着执行仓库代码，应评估来源；
- 模型许可证和商用限制；
- chat template 是否存在；
- dtype、device map 和显存需求；
- 模型版本/revision 是否固定，避免线上悄然变化。

### 13.2 `generate` 常用参数

- `max_new_tokens`：最多新生成多少 token；
- `do_sample=False`：通常走 greedy；
- `temperature`：概率分布温度；
- `top_p`：只在累计概率范围内采样；
- `top_k`：只在最高的 k 个 token 中采样；
- `repetition_penalty`：抑制重复，但过大会损害正常复述；
- `eos_token_id`：终止 token。

不要同时修改一堆参数后只看一个样例。固定 seed、数据集和版本，逐项做实验。

### 13.3 Datasets

```python
from datasets import load_dataset

dataset = load_dataset(
    "json",
    data_files={
        "train": "train.jsonl",
        "validation": "validation.jsonl",
    },
)

print(dataset["train"].column_names)
print(dataset["train"][0])
```

Hugging Face Datasets 基于 Arrow 组织数据，支持映射、过滤、缓存和 streaming。处理大数据时要注意：

- `map` 后是否命中旧缓存；
- 数据类型是否自动推断错误；
- streaming 数据不能像普通 Dataset 一样任意随机访问；
- 数据仓库 revision 是否固定；
- tokenization 是否在训练前离线完成，还是由 collator 动态完成。

## 15. 常见故障与排查顺序

### 15.1 Shape mismatch

排查：

1. 从输入开始打印 shape；
2. 标注每个维度语义；
3. 检查 `transpose`、`view/reshape`、batch 维；
4. 检查 tokenizer padding 与 collator；
5. 不要为了“跑通”随意 `squeeze`，batch size 为 1 时可能误删 batch 维。

### 15.2 CUDA out of memory

按优先级检查：

- 是否残留旧模型/计算图引用；
- batch size、sequence length 是否过大；
- 是否忘记关闭梯度；
- 是否保存了带计算图的 loss/tensor；
- 是否可用混合精度、梯度累积、checkpointing；
- 推理时并发和 KV Cache 是否过高；
- 显存碎片是否只是表象，核心仍是峰值需求过大。

`torch.cuda.empty_cache()` 只释放缓存分配器中未占用块，不能释放仍被张量引用的显存。

### 15.3 Loss 不下降

- 标签错位或全部被 mask；
- 学习率过大/过小；
- 参数被冻结或未交给 optimizer；
- 数据标签错误、类别极不平衡；
- 模型输出与 loss 输入格式不匹配；
- `model.eval()`/`train()` 状态错误；
- 梯度为 0、NaN 或未更新。

先尝试让模型过拟合几十个样本。如果连极小数据都无法拟合，优先怀疑实现而不是模型容量。

### 15.4 NaN/Inf

- 降低学习率；
- 检查输入数据和 loss 是否含异常值；
- 打印梯度范数；
- 使用 BF16 或正确的 FP16 loss scaling；
- 检查除零、对 0 取 log、非法标签；
- 暂时关闭可疑优化，定位最早出现非有限值的层。

### 15.5 训练结果无法复现

需要同时控制：随机种子、数据顺序、数据版本、代码和依赖版本、模型 revision、硬件与非确定性算子。完全逐 bit 一致不总是现实，工程目标应是指标在合理容差内可复现。

## 16. 高频面试题与回答骨架

### 16.1 为什么 Attention 要除以 `sqrt(d_k)`？

维度增大时点积方差会增大，Softmax 容易进入过度尖锐的饱和区，梯度变小。缩放让分数尺度更稳定。

### 16.2 训练和推理有什么核心差异？

训练通常整段并行计算并反向传播，保存激活和梯度；自回归推理通常分 prefill 与逐 token decode，只做前向，并通过 KV Cache 复用历史 K/V。

### 16.3 `model.eval()` 和 `no_grad()` 一样吗？

不一样。`eval()` 改变 Dropout、BatchNorm 等模块行为；`no_grad()`/`inference_mode()` 控制是否记录自动求导图。评估通常两者都需要。

### 16.4 FP16 与 BF16 如何选择？

BF16 指数范围接近 FP32，一般更稳定；FP16 有更多尾数精度但范围小，常需 loss scaling。最终取决于硬件支持、模型和实测性能。

### 16.5 KV Cache 缓存什么，有什么代价？

缓存每层历史 token 的 Key 和 Value，避免 decode 时重复计算。代价是显存随层数、序列长度、并发、KV 头数和精度增长。

### 16.6 Attention mask 与 label mask 的区别？

前者控制某位置能关注哪些 token，后者控制哪些 token 计入训练损失。SFT 中 user token 可以被模型看到，但不一定参与 loss。

### 16.7 为什么梯度累积能模拟大 batch？

多次 micro-batch 反向累加梯度后再更新一次参数，使一次更新覆盖更多样本；但 BatchNorm、随机性和优化器步数等细节不一定与真正的大 batch 完全相同。
