## 1.1 手写生成器：分批读取数据

> 面试优先级：★★★★☆｜学习难度：★★☆☆☆｜适用岗位：Python、RAG、数据处理  
> 掌握要求：解释 `yield`、惰性计算和状态保存

### 题目与思路

生成器使用 `yield` 按需产生数据，不必一次把全部结果放进内存。它适合大文件、分页数据和流式处理，核心是理解暂停与恢复执行。

**题目**

将序列按固定大小分批返回，不能一次复制所有批次。

**原理**

调用生成器函数不会立即执行完整函数，而是返回生成器对象。每次 `next()` 执行到 `yield` 暂停，并保存局部变量和指令位置；下次从暂停点继续。

### 代码

```python
from collections.abc import Iterable, Iterator
from typing import TypeVar

T = TypeVar("T")

def batched(items: Iterable[T], batch_size: int) -> Iterator[list[T]]:
    if batch_size <= 0:
        raise ValueError("batch_size must be positive")

    batch: list[T] = []
    for item in items:
        batch.append(item)
        if len(batch) == batch_size:
            yield batch
            batch = []

    if batch:
        yield batch
```

调用时只有在迭代生成器后才会真正执行：

```python
result = list(batched(range(7), 3))
# result == [[0, 1, 2], [3, 4, 5], [6]]
```

### 复杂度与边界

总时间 O(n)，除当前返回批次外，额外空间 O(batch_size)。`batch_size <= 0` 应直接拒绝；空输入应正常结束且不产生批次。生成器对象只能继续向后消费，耗尽后不能自动重置。

### 面试准备

**推荐回答**

> 生成器通过 yield 惰性产生值并保留执行状态，适合大文件、流式 Token 和批量 Embedding，避免把全部结果一次放入内存。这里总时间是 O(n)，但内存上限与 batch_size 相关，而不是输入总长度。

**常见错误与迁移**

常见错误是把 `yield` 当成普通 `return`、忘记处理最后一个不足 batch_size 的批次，或认为创建生成器对象时函数已经完整执行。迁移练习可以改为逐行读取大文件、分页拉取数据库结果或分批调用 Embedding API。

## 1.2 手写装饰器：统计同步函数耗时

> 面试优先级：★★★★☆｜学习难度：★★★☆☆｜适用岗位：Python、后端  
> 掌握要求：解释闭包、`*args/**kwargs` 和 `wraps`

### 题目与思路

装饰器接收函数并返回包装后的新函数，可在不修改原函数主体的情况下统一增加计时、日志或鉴权；`functools.wraps` 用于保留原函数元数据。

为任意同步函数增加耗时统计，同时保留原函数元数据，并保证函数抛异常时仍能记录耗时。

**关键点**

- 装饰器接收函数并返回新函数；
- `wrapper` 通过闭包保存 `func`；
- `wraps` 保留原函数名称、文档和签名元数据；
- `finally` 保证函数抛异常也记录耗时；
- 异步函数需要单独写 `async def wrapper` 并 `await func(...)`。

### 代码

```python
from collections.abc import Callable
from functools import wraps
from time import perf_counter
from typing import Any, TypeVar

R = TypeVar("R")

def timed(func: Callable[..., R]) -> Callable[..., R]:
    @wraps(func)
    def wrapper(*args: Any, **kwargs: Any) -> R:
        start = perf_counter()
        try:
            return func(*args, **kwargs)
        finally:
            elapsed = perf_counter() - start
            print(f"{func.__name__} took {elapsed:.4f}s")

    return wrapper
```

### 复杂度与边界

包装本身只加常数级开销，真正耗时取决于被包裹函数，`perf_counter` 两次读取是 O(1)。边界上要用 `try/finally` 保证函数抛异常时仍记录耗时；用 `wraps` 保留原函数名与签名，否则元数据被覆盖。`wrapper` 不跨调用保存状态，要累计耗时需引入外部计数器。同步版本不能直接套到协程，异步函数得单独写 `async def wrapper` 并 `await func(...)`。

### 面试准备

**推荐回答**

> 装饰器本质是高阶函数：接收原函数，返回一个包装函数，在不改原函数代码的前提下统一加计时、日志或鉴权。wrapper 通过闭包持有 func，用 `try/finally` 保证即使抛异常也记录耗时，用 `functools.wraps` 把原函数名字和签名复制过来，否则被装饰后元数据会丢失。

**常见错误与迁移**

常见错误是只演示正常返回、用 `except` 吞掉异常导致耗时统计丢失，或忘记 `wraps` 让被装饰函数的元数据被覆盖。迁移练习：把打印换成日志或指标上报、加上调用参数摘要，或改写成统计协程耗时的异步装饰器。

## 1.3 手写上下文管理器：可靠释放资源

> 面试优先级：★★★★☆｜学习难度：★★★☆☆｜适用岗位：Python、数据库、后端  
> 掌握要求：解释 `__enter__/__exit__` 和异常路径清理

### 题目与思路

上下文管理器把资源获取和释放绑定到 `with` 代码块，即使中间抛出异常也会执行退出逻辑，适合文件、锁、连接和临时资源。

`__exit__` 返回 `True` 会表示异常已处理；默认不应随意吞掉异常。数据库 Session、文件、锁和 HTTP Client 都适合上下文管理器。

实现资源的进入与退出协议，确保正常返回和异常退出两条路径都会释放资源。

### 代码

```python
class ManagedResource:
    def __init__(self, name: str) -> None:
        self.name = name
        self.opened = False

    def __enter__(self) -> "ManagedResource":
        self.opened = True
        print(f"open {self.name}")
        return self

    def use(self) -> None:
        if not self.opened:
            raise RuntimeError("resource is closed")
        print(f"use {self.name}")

    def __exit__(self, exc_type, exc, traceback) -> bool:
        self.opened = False
        print(f"close {self.name}")
        return False  # 不吞掉异常
```

```python
with ManagedResource("db") as resource:
    resource.use()
```

### 复杂度与边界

进入和退出都是 O(1)，核心不在复杂度而在异常路径。要验证正常返回和 `with` 块内抛异常两条路径都会执行 `__exit__` 释放资源；`__exit__` 返回 `False` 才不吞异常。`opened` 状态随对象保存，重复进入同一实例需自行判断是否可重入。异步资源应实现 `__aenter__/__aexit__` 并用 `async with`。

### 面试准备

**推荐回答**

> 上下文管理器把资源的获取和释放绑定到 `with` 块：`__enter__` 拿资源，`__exit__` 无论正常结束还是抛异常都会执行释放。`__exit__` 返回 `False` 表示不拦截异常，让它继续向上抛；返回 `True` 才会吞掉异常，一般不这么做。它适合文件、锁、数据库 Session、临时目录这类必须成对获取释放的资源。

**常见错误与迁移**

常见错误是把清理逻辑写在 `__enter__` 之后的普通语句里（异常时不执行）、`__exit__` 误返回 `True` 静默吞掉异常，或对异步资源套用同步协议。迁移练习：文件句柄、数据库 Session、线程锁、临时目录，都可用同一进入/退出骨架实现。

## 1.4 手写协程并发与并发上限

> 面试优先级：★★★★★｜学习难度：★★★☆☆｜适用岗位：Agent、后端  
> 掌握要求：能控制并发、超时和部分失败

### 题目与思路

协程并发适合同时等待多个 I/O，但无限创建任务可能压垮下游。通常用 Semaphore 限制在途数量，并明确异常、超时和部分成功语义。

并发执行多个 I/O 任务，同时限制在途数量、设置单任务超时，并明确部分失败如何返回。

### 代码

```python
import asyncio
from collections.abc import Awaitable, Callable
from typing import TypeVar

T = TypeVar("T")
R = TypeVar("R")

async def map_limited(
    items: list[T],
    worker: Callable[[T], Awaitable[R]],
    limit: int,
    timeout: float,
) -> list[R | Exception]:
    if limit <= 0:
        raise ValueError("limit must be positive")

    semaphore = asyncio.Semaphore(limit)

    async def run_one(item: T) -> R:
        async with semaphore:
            async with asyncio.timeout(timeout):
                return await worker(item)

    return await asyncio.gather(
        *(run_one(item) for item in items),
        return_exceptions=True,
    )
```

### 复杂度与边界

总时间取决于最慢任务而非任务数量，Semaphore 把在途并发压到 `limit`，`asyncio.timeout` 给单任务设上限。边界要处理 `limit<=0`、空输入（返回空列表），以及 `return_exceptions=True` 时调用方必须逐项判断结果是正常值还是异常。若要求任一失败即取消同组，应改用 `TaskGroup`。

### 面试准备

**推荐回答**

> `gather` 并发等待所有任务，Semaphore 限制同时进入下游的数量，timeout 控制单任务时间。`return_exceptions=True` 表示允许部分成功，但调用方必须逐项检查异常，不能当成正常结果。若要求任何一个失败就取消同组任务，更适合 TaskGroup。

**常见错误与迁移**

常见错误是不设并发上限压垮下游、把 gather 返回的异常对象当成正常结果使用，或漏设单任务超时导致整体卡死。迁移练习：并发拉取多个 URL、批量调用 Embedding、并发查询多个数据源并保留部分成功。

## 2.1 链表

> 面试优先级：★★★★☆｜学习难度：★★★☆☆  

### 题目与思路

链表由节点和指针连接，随机访问慢，但已知节点附近的插入删除只需修改指针。手写题的重点是保存下一节点、处理空链表和用 Dummy 统一头节点边界。

链表节点不连续存储，已知节点插入/删除可 O(1)，但按下标访问 O(n)。高频操作：反转、快慢指针、合并、环、K 组处理。

掌握节点定义、遍历、反转和 Dummy 节点，重点处理空链表、单节点和头节点变化。

**反转链表**

不变量：`previous` 始终是已经反转好的前缀头节点。

### 代码

```python
from dataclasses import dataclass

@dataclass
class ListNode:
    val: int
    next: "ListNode | None" = None
```

```python
def reverse_list(head: ListNode | None) -> ListNode | None:
    previous = None
    current = head

    while current is not None:
        next_node = current.next
        current.next = previous
        previous = current
        current = next_node

    return previous
```

### 复杂度与边界

反转链表遍历一次，时间 O(n)、额外空间 O(1)；按下标访问是 O(n)，已知节点处插入删除是 O(1)。边界要覆盖空链表（直接返回 None）、单节点、以及反转后头节点会变化。用 Dummy 可以统一头节点被删除或被插入的情形。

### 面试准备

**推荐回答**

> 反转链表时我维护三个指针：previous 指向已反转好的前缀头，current 是当前待处理节点，next_node 暂存后继防止断链。每步把 current.next 指回 previous，再整体右移；current 走到 None 时 previous 就是新头。遍历一次 O(n)，原地修改指针 O(1)。

**常见错误与迁移**

常见错误是反转时忘记先用临时变量保存 next_node 导致断链、没有 Dummy 而在删除头节点时出错、或返回了旧的 head。迁移练习：合并两个有序链表、快慢指针找中点或判环、K 个一组翻转。

## 2.2 栈、队列和双端队列

> 面试优先级：★★★★☆｜学习难度：★★☆☆☆  

### 题目与思路

三者的区别主要在“从哪里取出元素”：栈后进先出，队列先进先出，双端队列允许两端增删。选数据结构前先看题目要求的访问顺序，不要只因为都会存数据就随意替换。

- 栈：括号匹配、表达式、DFS、单调栈；
- 队列：BFS、任务调度；
- 双端队列：滑动窗口、双端增删。

不要用列表 `pop(0)` 实现队列，因为会移动后续元素，时间 O(n)。

根据后进先出或先进先出的访问顺序选择结构，并能用 deque 写出 O(1) 的两端操作。

### 代码

```python
from collections import deque

stack: list[int] = []
stack.append(1)
stack.pop()

queue: deque[int] = deque()
queue.append(1)
queue.popleft()
```

### 复杂度与边界

栈的 `append/pop` 和 deque 的两端 `append/appendleft/pop/popleft` 都是均摊 O(1)；用 `list.pop(0)` 当队列则是 O(n)。边界要考虑空栈或空队列弹出（会抛异常，需先判空），以及是否需要限制容量。

### 面试准备

**推荐回答**

> DFS、括号匹配等需要回到最近状态时用栈；BFS 按层扩展使用队列；需要维护窗口两端候选时用双端队列。Python 中栈可直接用 list，队列优先用 `collections.deque`，避免 `list.pop(0)` 的线性移动成本。

**常见错误与迁移**

常见错误是用 `list.pop(0)` 实现队列造成线性移动、或在需要两端操作时仍用普通 list。迁移练习：用栈做括号匹配和单调栈，用队列做 BFS，用双端队列维护滑动窗口最大值。

## 2.3 哈希表与集合

> 面试优先级：★★★★★｜学习难度：★★☆☆☆  

### 题目与思路

哈希表通过 Key 的哈希值快速定位存储位置，适合“我是否见过它”“它出现了几次”“它对应哪个下标”这类问题。集合只保存 Key，字典保存 Key 到 Value 的映射。

平均查找、插入、删除 O(1)，最坏情况与哈希冲突有关。适合计数、去重、建立值到位置映射。

Key 必须可哈希。列表和字典可变，不能直接作为普通 dict Key；元组只有内部元素均可哈希时才可用。

**一个最小例子**

两数之和中，遍历到 `value` 时先查询 `target - value` 是否已在字典；如果存在即可得到答案，否则记录当前值和下标。这样用额外 O(n) 空间把双重循环的 O(n²) 降为平均 O(n)。

### 代码

```python
from collections import Counter, defaultdict

counts = Counter("aab")
positions: dict[str, list[int]] = defaultdict(list)
```

### 复杂度与边界

查找、插入、删除平均 O(1)，最坏在大量哈希冲突时退化到 O(n)；计数、去重、建映射都是用 O(n) 空间换时间。边界要注意 Key 必须可哈希（list、dict 不能作 Key），以及需要有序遍历或范围查询时哈希表并不合适。

### 面试准备

**推荐回答**

> 当题目需要频繁判断存在性、计数或建立值到位置映射时，我会优先考虑哈希表。平均查询和写入是 O(1)，但需要额外空间，Key 还必须可哈希；如果题目要求有序遍历或范围查询，普通哈希表就不一定合适。

**常见错误与迁移**

常见错误是用可变对象作 Key、在遍历字典时增删键、或忽略最坏的冲突退化。迁移练习：两数之和、字母异位词分组、用 defaultdict 建倒排、用 Counter 统计词频。

## 2.4 堆与 Top-K

> 面试优先级：★★★★☆｜学习难度：★★★☆☆  

### 题目与思路

堆只保证堆顶是最小或最大元素，不维护整体有序。求 Top-K 时只维护 K 个候选，可把全量排序的 O(n log n) 降为 O(n log k)。

Python `heapq` 是小根堆，取最小值 O(1)，插入和弹出 O(log n)。维护最大 K 个元素时，用大小 K 的小根堆保存当前 Top-K：

时间 O(n log k)，空间 O(k)。

维护当前最重要的 K 个元素；数据量大而 K 较小时，使用大小为 K 的堆避免对全部元素排序。

### 代码

```python
import heapq

def top_k_largest(nums: list[int], k: int) -> list[int]:
    if k <= 0:
        return []
    if k >= len(nums):
        return sorted(nums, reverse=True)

    heap = nums[:k]
    heapq.heapify(heap)

    for value in nums[k:]:
        if value > heap[0]:
            heapq.heapreplace(heap, value)

    return sorted(heap, reverse=True)
```

### 复杂度与边界

`heapify` 是 O(n)，单次 `heappush/heappop/heapreplace` 是 O(log k)；维护大小为 k 的堆求 Top-K 总时间 O(n log k)、空间 O(k)，优于全量排序的 O(n log n)。边界要处理 `k<=0`（返回空）、`k>=n`（直接排序）和重复值。

### 面试准备

**推荐回答**

> 求 Top-K 最大值时，我用一个大小为 k 的小根堆保存当前候选，堆顶是这 k 个里最小的。新元素大于堆顶才替换堆顶，否则丢弃；这样始终只维护 k 个元素，总时间 O(n log k)，比排序全部的 O(n log n) 更省。Python 的 heapq 是小根堆，用它当门槛正好求最大 K 个。

**常见错误与迁移**

常见错误是求最大 K 个却去维护全部元素的大根堆、忘记先 heapify、或不处理 k 与 n 的边界关系。迁移练习：数据流中位数（双堆）、合并 K 个有序链表、前 K 高频元素。

## 2.5 树与图

### 题目 1：删除链表倒数第 N 个节点

> LeetCode 19｜面试优先级：★★★★★｜学习难度：★★★☆☆  
> 掌握要求：会快慢指针、Dummy Node 和边界证明

#### 核心思路

快慢指针保持固定距离：让 fast 先走 n+1 步，之后同步移动，fast 到尾部时 slow 正好位于待删除节点的前驱；Dummy 用于统一删除头节点。

**题目与边界**

给定链表头节点 `head` 和正整数 `n`，删除链表倒数第 `n` 个节点，返回头节点。假设 `n` 合法。

```text
1 → 2 → 3 → 4 → 5, n=2
结果：1 → 2 → 3 → 5
```

**基线思路**

先遍历得到长度 `L`，再走到第 `L-n` 个前驱并删除。时间 O(n)，两次遍历。它是正确基线，不应因为不是“一趟”就否定。

**一趟快慢指针如何想到**

倒数第 N 个节点意味着：当快指针到达尾部时，慢指针与目标保持 N 的距离。为了统一删除头节点，创建 Dummy：

让 `fast` 先从 Dummy 走 `n+1` 步，随后 fast/slow 同时走。当 fast 为 `None`，slow 位于目标前驱。

**为什么 Dummy 重要**

删除头节点时，真实头节点没有前驱。Dummy 为所有真实节点提供统一前驱，返回 `dummy.next` 即可。

**补充推导**

```text
dummy → 1 → 2 → 3 → 4 → 5
```

#### Python 代码

**代码**

为了面试代码更简洁，在题目保证 `n` 合法时可以去掉异常检查。

```python
def remove_nth_from_end(
    head: ListNode | None,
    n: int,
) -> ListNode | None:
    dummy = ListNode(0, head)
    fast: ListNode | None = dummy
    slow: ListNode = dummy

    for _ in range(n + 1):
        if fast is None:
            raise ValueError("n is larger than the list length")
        fast = fast.next

    while fast is not None:
        fast = fast.next
        slow = slow.next  # type: ignore[assignment]

    if slow.next is not None:
        slow.next = slow.next.next

    return dummy.next
```

#### 手动执行与复杂度

**手动执行**

链表长度 5，`n=2`：

1. fast 先走 3 步，指向节点 3；slow 在 Dummy；
2. 二者一起走：`fast=4, slow=1`；
3. `fast=5, slow=2`；
4. `fast=None, slow=3`；
5. `slow.next` 是 4，删除 4。

**复杂度**

- 时间 O(L)；
- 额外空间 O(1)。

#### 常见错误

- fast 只先走 n 步，却仍按“slow 是前驱”删除；
- 没有 Dummy，单独处理删除头节点导致边界混乱；
- 循环条件写成 `fast.next`，对不同步数模板不一致；
- 修改后返回旧的 `head`，删除头节点失效。

#### 面试表达与迁移

**推荐表达**

> 我需要找到待删除节点的前驱。先放一个 Dummy 统一头节点边界，让 fast 比 slow 多走 n+1 步。之后同时移动，fast 到 None 时 slow 正好停在倒数第 n 个节点的前驱，修改一次 next 即可。时间 O(L)，空间 O(1)。

**迁移练习**

练习：链表中点、判断环、寻找环入口。迁移时先问两个指针之间应保持怎样的距离或速度关系。

### 题目 2：接雨水

> LeetCode 42｜面试优先级：★★★★☆｜学习难度：★★★★☆  
> 掌握要求：从前后缀最大值推导对撞指针

#### 核心思路

位置 i 的积水由左侧最高柱和右侧最高柱中的较低者决定。双指针维护两侧最大值，每次结算边界较低的一侧，因为该侧水位已经确定。

**题目与边界**

给定非负整数数组 `height` 表示柱高，计算下雨后能接多少水。

```text
height = [0,1,0,2,1,0,1,3,2,1,2,1]
答案 = 6
```

**基线思路**

基线做法是对每个位置分别向左、向右扫描最高柱子，再计算该位置水量；每个位置扫描 O(n)，总时间 O(n²)。也可以预计算左右最大值，用 O(n) 额外空间把时间降到 O(n)。

**单个位置能接多少水**

位置 `i` 的水位由左右最高柱中较低者决定：

暴力为每个位置向左右扫描，O(n²)。预计算左右最大值可 O(n) 时间、O(n) 空间。

**为什么能优化为双指针**

维护：

- `left_max`：从左到当前见过的最高柱；
- `right_max`：从右到当前见过的最高柱。

如果 `height[left] <= height[right]`，对于 left 位置，右侧至少存在 `height[right]` 这根不低于它的柱子。此时 left 的可接水量可以由 `left_max` 决定；对称地处理 right。

另一种等价写法比较 `left_max <= right_max`。面试中选一种模板并保持证明与代码一致。

**不变量**

当 `left_max <= right_max` 时，左侧当前水位上限由较小的 `left_max` 确定，右侧已经有至少 `right_max` 的边界；因此可以安全结算 left。反之结算 right。

**补充推导**

```text
water[i] = max(0, min(left_max[i], right_max[i]) - height[i])
```

#### Python 代码

**代码**

```python
def trap(height: list[int]) -> int:
    left = 0
    right = len(height) - 1
    left_max = 0
    right_max = 0
    water = 0

    while left <= right:
        if left_max <= right_max:
            left_max = max(left_max, height[left])
            water += left_max - height[left]
            left += 1
        else:
            right_max = max(right_max, height[right])
            water += right_max - height[right]
            right -= 1

    return water
```

#### 手动执行与复杂度

**手动执行**

用 `[2,0,2]` 检查：左右指针从两端开始，两侧最大值均为 2；处理下标 1 时可接 `min(2,2)-0=2`。手算时每轮记录 left、right、left_max、right_max 和累计水量。

**复杂度**

- 时间 O(n)，每个位置处理一次；
- 额外空间 O(1)。

#### 常见错误

- 用两边“当前柱高”与“历史最大值”的推导混在同一模板；
- 先移动指针再计算，漏位置；
- 水量写成 `min(left_max,right_max)` 却忘记减柱高；
- 把负值加入结果。

#### 面试表达与迁移

**推荐表达**

> 位置 i 的积水由它左右两侧最高柱中较低的一根决定。我用 left、right 双指针从两端向内，同时维护 left_max 和 right_max。每次比较这两个最大值，结算较低的一侧：因为那一侧的水位已被较小的 max 锁定，另一侧再高也不会改变结果，算完就移动该指针。一趟扫描 O(n)，只用常数变量 O(1)。

**迁移总结**

双指针不是“看到数组就左右夹”。核心是：根据局部比较能证明某一侧答案已经确定，移动该侧不会丢失最优解。

**迁移练习**

- 环形链表：同向快慢指针；
- 盛最多水的容器：对撞指针，移动短板；
- 三数之和：排序 + 对撞指针；
- 删除有序数组重复项：读写指针。

### 题目 1：无重复字符的最长子串

> LeetCode 3｜面试优先级：★★★★★｜学习难度：★★★☆☆  
> 掌握要求：会“窗口非法时收缩”的最长窗口模板

#### 核心思路

使用滑动窗口维护“窗口内没有重复字符”的不变量。右指针扩张，出现重复时移动左指针排除冲突，并在每一步更新最长长度。

**题目与边界**

返回字符串中不含重复字符的最长连续子串长度。

```text
"abcabcbb" → 3，子串 "abc"
```

**基线思路**

枚举所有子串并检查重复，最坏 O(n³)；使用集合增量检查可到 O(n²)。重复工作在于相邻子串共享大量字符。

**窗口状态**

窗口 `[left,right]` 始终不含重复字符。右指针加入字符；若重复，移动 left 直到合法；每次合法后更新最大长度。

**补充推导**

```text
right=0, a: [a], best=1
right=1, b: [a,b], best=2
right=2, b重复:
  移除a，仍有b
  移除旧b，left=2
  加入新b，窗口[b]
right=3, a: [b,a], best=2
```

#### Python 代码

**写法一：集合，最直观**

**写法二：记录最后位置，直接跳**

条件 `last_index[char] >= left` 很重要：哈希表中的旧位置可能已在窗口左侧，不能让 left 倒退。

```python
def length_of_longest_substring(s: str) -> int:
    seen: set[str] = set()
    left = 0
    best = 0

    for right, char in enumerate(s):
        while char in seen:
            seen.remove(s[left])
            left += 1

        seen.add(char)
        best = max(best, right - left + 1)

    return best
```

```python
def length_of_longest_substring_jump(s: str) -> int:
    last_index: dict[str, int] = {}
    left = 0
    best = 0

    for right, char in enumerate(s):
        if char in last_index and last_index[char] >= left:
            left = last_index[char] + 1
        last_index[char] = right
        best = max(best, right - left + 1)

    return best
```

**手动执行 `abba`**

**复杂度**

时间 O(n)，每个字符最多加入/移除一次；空间 O(min(n,字符集大小))。

#### 常见错误

常见错误是用 if 而不是 while 收缩、遇到重复只移动一格导致窗口里仍含重复；跳跃写法里忘记 `last_index[char] >= left` 判断，让 left 回退到已经划过的区域；以及漏掉空串（应返回 0）。

#### 面试表达与迁移

**推荐表达**

> 这是最长连续子串，且窗口是否有效可由字符集合维护，所以用可变滑动窗口。右边界扩张，遇到重复时移动左边界直到重复字符被移出，再更新合法窗口长度。整个过程中左右指针都只向右，因此 O(n)。

### 题目 2：最小覆盖子串

> LeetCode 76｜面试优先级：★★★★☆｜学习难度：★★★★★  
> 掌握要求：会带重复计数的“满足后尽量收缩”模板

#### 核心思路

窗口先向右扩张直到覆盖目标字符及数量，再不断移动左边界缩小；一旦不再满足条件，就继续扩张。关键是维护满足了多少类需求。

**题目与边界**

给定字符串 `s` 和 `t`，返回 `s` 中覆盖 `t` 全部字符及重复次数的最短子串。

```text
s="ADOBECODEBANC", t="ABC" → "BANC"
s="AAAB", t="AAB" → "AAB"
```

**基线思路**

暴力枚举所有子串，再逐个统计是否覆盖目标字符，时间至少 O(n²)。大量相邻子串共享统计结果，因此应维护可增量扩张和收缩的窗口。

**与上一题的关键区别**

- 最长无重复：窗口非法时收缩，合法后更新最长；
- 最小覆盖：窗口满足时持续收缩，并在仍满足时更新最短。

**状态设计**

- `need[c]`：目标字符 c 需要次数；
- `window[c]`：当前窗口次数；
- `formed`：已经满足次数要求的字符种类数；
- `required=len(need)`：需要满足的字符种类数。

只有当 `window[c] == need[c]` 时，c 这一种字符刚好变为满足。

**为什么先更新答案再移除 left**

进入 `while` 时当前窗口满足覆盖。我们先记录这个可行窗口，再尝试去掉最左字符。如果去掉后不满足，循环退出；去掉后仍满足，则下一轮记录更短窗口。

#### Python 代码

**代码**

```python
from collections import Counter, defaultdict

def min_window(s: str, t: str) -> str:
    if not s or not t:
        return ""

    need = Counter(t)
    window: dict[str, int] = defaultdict(int)
    required = len(need)
    formed = 0

    left = 0
    best_start = 0
    best_length = float("inf")

    for right, char in enumerate(s):
        window[char] += 1
        if char in need and window[char] == need[char]:
            formed += 1

        while formed == required:
            current_length = right - left + 1
            if current_length < best_length:
                best_length = current_length
                best_start = left

            left_char = s[left]
            window[left_char] -= 1
            if left_char in need and window[left_char] < need[left_char]:
                formed -= 1
            left += 1

    if best_length == float("inf"):
        return ""
    return s[best_start : best_start + int(best_length)]
```

#### 手动执行与复杂度

**手动执行**

以 `s=ADOBECODEBANC，t=ABC` 为例：右端扩到首次满足时得到 `ADOBEC`，随后收缩；继续扩张和收缩，最终保留更短的 `BANC`。每轮只维护 need、window 和 valid。

**复杂度**

- 时间 O(|s|+|t|)；
- 空间 O(字符种类数)。

#### 常见错误

- 用集合而不是计数，无法处理 `t="AAB"`；
- `formed` 记录字符总数，却与字符种类 `required` 比较；
- `window[c] >= need[c]` 时反复增加 formed；
- 收缩后没有在跌破需求时减少 formed；
- 更新答案放在错误位置。

#### 面试表达与迁移

**推荐表达**

> 这是满足字符计数约束的最短连续子串。我用 need 记录目标次数，window 记录当前次数，formed 记录已经满足要求的字符种类。右指针扩张直到全部满足，然后左指针尽量收缩；每次收缩前记录当前可行最短窗口，某个字符数量跌破需求时停止收缩。左右指针单调前进，所以总时间 O(n)。

**滑动窗口迁移表**

| 题型 | 收缩条件 | 更新答案时机 |
|---|---|---|
| 最长合法窗口 | 窗口非法 | 恢复合法后 |
| 最短满足窗口 | 窗口满足 | 收缩过程中 |
| 固定长度窗口 | 长度超过 K | 维持长度 K 时 |
| 计数窗口 | 根据频次/和/不同元素数 | 取决于最长或最短 |

**迁移练习**

- 长度最小的子数组；
- 字符串的排列；
- 找到所有字母异位词；
- 至多 K 个不同字符的最长子串。

> 掌握要求：稳定写出左闭右闭模板

#### 核心思路

二分查找每次利用有序性排除一半区间。写代码前先确定闭区间或左闭右开区间，并让循环条件、边界更新和返回值始终遵守同一个不变量。

**题目与边界**

在升序且元素不重复的数组中查找 target，返回下标，否则 -1。

**基线思路**

基线是从左到右线性扫描，时间 O(n)。数组有序意味着一次比较就能排除一半候选区间，因此可以降为 O(log n)。

**为什么是 `left <= right`**

当 `left == right` 时区间还有一个候选，必须检查。排除 mid 后使用 `mid+1` 或 `mid-1`，否则可能死循环。

#### Python 代码

**左闭右闭模板**

搜索区间始终是 `[left,right]`，两端均可能包含答案：

```python
def binary_search(nums: list[int], target: int) -> int:
    left = 0
    right = len(nums) - 1

    while left <= right:
        mid = left + (right - left) // 2

        if nums[mid] == target:
            return mid
        if nums[mid] < target:
            left = mid + 1
        else:
            right = mid - 1

    return -1
```

#### 手动执行与复杂度

**手动执行**

以 `[1,3,5,7]` 查 5 为例：初始 `[0,3]`，mid=1 对应 3，因此 left=2；随后 mid=2 命中。再用空数组、首元素和不存在元素检查边界。

**复杂度**

时间 O(log n)，空间 O(1)。

#### 常见错误

- 左闭右闭却初始化 `right=len(nums)`；
- 排除 mid 时只写 `left=mid`；
- `while left < right` 后没有检查剩余元素；
- 数组无序仍使用二分。

#### 面试表达与迁移

**推荐表达**

> 我使用左闭右闭区间，循环不变量是如果目标存在，一定在 `[left,right]`。每次检查 mid；目标更大时 mid 已排除，所以 left=mid+1，反之 right=mid-1。区间为空即 left>right，返回 -1。

**迁移练习**

练习：第一个等于目标的位置、最后一个不小于目标的位置。迁移时先明确搜索区间定义和答案是否可能保留在 mid。

### 题目 2：旋转排序数组中的最小值

> LeetCode 153｜面试优先级：★★★★☆｜学习难度：★★★★☆  
> 掌握要求：理解局部有序和与右端比较

#### 核心思路

旋转数组仍由两个有序片段组成。比较 mid 与 right 可以判断最小值位于哪一侧，并保留 mid 可能就是答案的情况逐步收缩边界。

**题目与边界**

一个严格升序数组在某点旋转，元素不重复，找最小值。

```text
[4,5,6,7,0,1,2] → 0
[1,2,3] → 1
```

**基线思路**

基线是扫描全部元素取最小值，时间 O(n)。旋转数组仍由两个有序段组成，可以通过中点与右端点的关系判断最小值在哪一半。

**观察**

数组由两段升序组成，最小值是第二段开头。比较 `nums[mid]` 与 `nums[right]`：

- `nums[mid] > nums[right]`：mid 位于左侧大值段，最小值在 `(mid,right]`；
- `nums[mid] < nums[right]`：mid 到 right 有序，mid 可能就是最小值，答案在 `[left,mid]`。

**为什么 `right=mid` 而不是 `mid-1`**

当 `nums[mid] < nums[right]`，mid 可能就是最小值，不能排除。

**为什么循环是 `left < right`**

目标不是查到某值立即返回，而是不断缩小到唯一候选；`left==right` 时结束。

**有重复元素怎么办**

如果 `nums[mid] == nums[right]` 无法判断哪侧有最小值，可 `right -= 1`，最坏退化 O(n)。这对应 LeetCode 154/剑指 Offer 的重复版本。

#### Python 代码

**代码**

**二分三类模板**

```python
def find_min_rotated(nums: list[int]) -> int:
    if not nums:
        raise ValueError("nums must not be empty")

    left = 0
    right = len(nums) - 1

    while left < right:
        mid = left + (right - left) // 2
        if nums[mid] > nums[right]:
            left = mid + 1
        else:
            right = mid

    return nums[left]
```

#### 手动执行与复杂度

**手动执行**

以 `[4,5,6,1,2,3]` 为例：mid=2 的 6 大于右端 3，令 left=3；随后在 `[1,2,3]` 中不断收缩右边界，最终 left=right=3。

**复杂度**

无重复 O(log n) 时间、O(1) 空间。

#### 常见错误

常见错误是拿 nums[mid] 和 nums[left] 比较（旋转点落在右半时会误判）、命中 `nums[mid] < nums[right]` 时写成 `right = mid - 1` 把可能的最小值排除、以及用 `left <= right` 配合 `right = mid` 造成死循环。有重复元素时 `nums[mid] == nums[right]` 无法判向，只能 `right -= 1`，最坏退化 O(n)。

#### 面试表达与迁移

**推荐表达**

> 旋转后的数组由两段升序组成，最小值是第二段的起点。我用 left、right 二分，拿 nums[mid] 和 nums[right] 比较：mid 比右端大说明最小值在 mid 右侧，令 left=mid+1；否则 mid 到右端有序，最小值在 mid 及其左侧，令 right=mid（不能排除 mid 自己）。循环用 left<right 收敛到唯一候选即答案。无重复时 O(log n)、O(1)。

**迁移练习**

- 排序数组中第一个/最后一个目标；
- 搜索旋转排序数组；
- x 的平方根；
- 最小运载能力/最大最小距离等答案二分。

### 题目 1：岛屿数量

> LeetCode 200｜面试优先级：★★★★★｜学习难度：★★★☆☆  
> 掌握要求：会把网格抽象成图，并写 DFS/BFS 两种实现

#### 核心思路

每遇到一个尚未访问的陆地，就用 DFS 或 BFS 标记与它连通的全部陆地，并把岛屿数加一；本质是在网格中统计连通分量。

**题目与边界**

二维网格中 `'1'` 表示陆地、`'0'` 表示水，陆地上下左右相连形成岛屿，返回岛屿数量。

**基线思路**

基线仍要扫描每个格子；如果每遇到陆地都重新搜索且不记录访问状态，会重复访问甚至死循环。正确做法是在发现新陆地后做一次遍历，并把整座岛标记为已访问。

**图抽象**

每个陆地格子是节点，上下左右相邻陆地之间有边。题目要求图中连通分量数量。

外层扫描：每遇到一个未访问陆地，岛屿数加一，并通过 DFS/BFS 标记整个连通块。

**为什么入队时标记**

如果出队时才标记，同一格可能被多个邻居重复加入队列，增加空间和处理次数。

#### Python 代码

**DFS 原地标记**

原地把陆地改成水相当于 visited。如果不允许修改输入，使用 `visited: set[tuple[int,int]]`。

**BFS 实现**

```python
def num_islands_dfs(grid: list[list[str]]) -> int:
    if not grid or not grid[0]:
        return 0

    rows = len(grid)
    cols = len(grid[0])

    def dfs(row: int, col: int) -> None:
        if row < 0 or row >= rows or col < 0 or col >= cols:
            return
        if grid[row][col] != "1":
            return

        grid[row][col] = "0"
        dfs(row - 1, col)
        dfs(row + 1, col)
        dfs(row, col - 1)
        dfs(row, col + 1)

    islands = 0
    for row in range(rows):
        for col in range(cols):
            if grid[row][col] == "1":
                islands += 1
                dfs(row, col)

    return islands
```

```python
from collections import deque

def num_islands_bfs(grid: list[list[str]]) -> int:
    if not grid or not grid[0]:
        return 0

    rows = len(grid)
    cols = len(grid[0])
    islands = 0
    directions = ((-1, 0), (1, 0), (0, -1), (0, 1))

    for row in range(rows):
        for col in range(cols):
            if grid[row][col] != "1":
                continue

            islands += 1
            grid[row][col] = "0"  # 入队时就标记，避免重复入队
            queue = deque([(row, col)])

            while queue:
                current_row, current_col = queue.popleft()
                for delta_row, delta_col in directions:
                    next_row = current_row + delta_row
                    next_col = current_col + delta_col
                    if (
                        0 <= next_row < rows
                        and 0 <= next_col < cols
                        and grid[next_row][next_col] == "1"
                    ):
                        grid[next_row][next_col] = "0"
                        queue.append((next_row, next_col))

    return islands
```

#### 手动执行与复杂度

**手动执行**

在一个 3×3 网格上，从首个陆地开始把相连的上下左右陆地依次标记；回到外层扫描时，这些格子不再增加计数。遇到下一块未标记陆地时，计数才加一。

**复杂度**

- 时间 O(rows×cols)，每格最多处理常数次；
- 空间：DFS 最坏递归 O(rows×cols)，BFS 队列最坏同阶。

#### 常见错误

- 忘记边界检查；
- 把对角线也当相邻；
- 外层每遇到陆地只加一，没有淹没整个岛；
- BFS 重复入队；
- 修改输入却没有告知。

#### 面试表达与迁移

**推荐表达**

> 我把网格看成图，岛屿就是陆地节点的连通分量。外层扫描每遇到一个未访问陆地，计数加一，再用 DFS 或 BFS 标记整个连通块。每个格子最多访问一次，所以时间 O(mn)。如果不允许修改输入，我使用 visited 集合。

**迁移练习**

练习：岛屿最大面积、被围绕的区域、图的连通分量。迁移时明确节点、边和 visited 的含义。

### 题目 2：二叉树层序遍历

> LeetCode 102｜面试优先级：★★★★★｜学习难度：★★★☆☆  
> 掌握要求：理解 BFS 队列与“当前层长度快照”

#### 核心思路

层序遍历使用 BFS 队列。每轮先记录当前队列长度，只弹出这一层的节点，并把它们的子节点加入队尾，从而得到按层分组的结果。

**题目与边界**

按层返回二叉树节点：

```text
      3
     / \
    9  20
      /  \
     15   7

结果：[[3], [9,20], [15,7]]
```

**基线思路**

可以给每个节点携带层号后统一遍历，再按层号分组；更直接的做法是使用队列，并在每轮开始时记录当前层节点数。

**为什么要先保存 `level_size`**

处理当前层时会把下一层节点加入队列。开始时的队列长度正好是当前层节点数，保存快照后只循环这么多次，下一层留到下轮。

#### Python 代码

**代码**

```python
from collections import deque

def level_order(root: TreeNode | None) -> list[list[int]]:
    if root is None:
        return []

    result: list[list[int]] = []
    queue = deque([root])

    while queue:
        level_size = len(queue)
        level: list[int] = []

        for _ in range(level_size):
            node = queue.popleft()
            level.append(node.val)

            if node.left is not None:
                queue.append(node.left)
            if node.right is not None:
                queue.append(node.right)

        result.append(level)

    return result
```

#### 手动执行与复杂度

**手动执行**

以根 1、子节点 2 和 3 为例：第一轮 level_size=1，只弹出 1 并压入 2、3；第二轮开始时 level_size=2，因此 2、3 被放进同一层结果。

**复杂度**

时间 O(n)，空间 O(w)，`w` 为树最大宽度。

#### 常见错误

常见错误是循环开始时不先保存 level_size，导致把下一层节点混进当前层；忘记处理空树（应返回空列表）；以及只用一个列表收集所有节点而丢失分层信息。

#### 面试表达与迁移

**推荐表达**

> 层序遍历本质是 BFS。我用队列存待处理节点，每轮开始先记录当前队列长度 level_size，它正好是这一层的节点数；只弹出这么多个节点组成一层结果，同时把它们的左右孩子入队留给下一轮，这样天然按层分组。每个节点进出队各一次，时间 O(n)，空间是树的最大宽度 O(w)。

**BFS/DFS 迁移**

- 岛屿最大面积：DFS 返回面积或 BFS 计数；
- 腐烂的橘子：多源 BFS + 层数；
- 无权图最短路：BFS；
- 二叉树最大深度：DFS 返回子树信息或 BFS 数层；
- 工作流依赖：图遍历 + 拓扑排序。

### 基础模板或模式总结

### 题目 1：全排列

> LeetCode 46｜面试优先级：★★★★☆｜学习难度：★★★☆☆  
> 掌握要求：会 used 数组、撤销和 path.copy

#### 核心思路

回溯维护当前路径和已使用元素集合：选择一个未使用元素、递归探索、再撤销选择。路径长度等于元素数量时得到一个完整排列。

**题目与边界**

输入不重复整数数组，返回全部排列。

```text
[1,2,3]
→ [1,2,3], [1,3,2], [2,1,3], ... 共 6 个
```

**基线思路**

可以生成所有长度为 n 的位置选择序列，再过滤同一元素被重复使用的非法序列，但会产生大量无效分支。回溯在构造过程中维护 used 状态，提前阻止非法选择。

**决策树**

第一层选择第一个位置，第二层从未使用元素中选择第二个位置，直到路径长度为 n。

**为什么要 `path.copy()`**

`path` 是同一个可变列表，后续会继续 pop/append。直接保存 `path` 会让结果中的所有引用最终指向同一个状态。

**为什么需要撤销**

递归返回后，要恢复到“做选择前”的状态，才能尝试下一个兄弟分支。遗漏 `path.pop()` 或 `used=False` 会污染其他排列。

#### Python 代码

**代码**

```python
def permute(nums: list[int]) -> list[list[int]]:
    result: list[list[int]] = []
    path: list[int] = []
    used = [False] * len(nums)

    def backtrack() -> None:
        if len(path) == len(nums):
            result.append(path.copy())
            return

        for index, value in enumerate(nums):
            if used[index]:
                continue

            used[index] = True
            path.append(value)

            backtrack()

            path.pop()
            used[index] = False

    backtrack()
    return result
```

#### 手动执行与复杂度

**手动执行**

以 `[1,2,3]` 为例：先选 1，再选 2、3 得到一个答案；撤销 3 后回到 `[1,2]`，再逐层撤销，才能继续探索 `[1,3,2]` 和以 2、3 开头的分支。

**复杂度**

共有 n! 个结果，每个结果复制长度 n，时间 O(n·n!)；递归和 path 额外 O(n)，不计结果存储。

#### 常见错误

常见错误是把 path 直接 append 进结果而不 copy，最终所有结果指向同一个被清空的列表；递归返回后忘记 `path.pop()` 或 `used[index]=False` 撤销选择，污染后续分支；以及用 `value in path` 判重带来额外 O(n) 开销而不用 used 数组。

#### 面试表达与迁移

**推荐表达**

> 我把排列看成决策树，每层确定一个位置。path 保存当前排列，used 表示某个下标是否已使用。路径长度达到 n 时复制保存；每次递归前做选择，返回后撤销，使状态恢复给下一个分支。

**迁移练习**

练习：全排列 II、子集。迁移时明确路径、可选集合、终止条件和撤销动作。

### 题目 2：组合总和

> LeetCode 39｜面试优先级：★★★★☆｜学习难度：★★★★☆  
> 掌握要求：理解组合去重、重复使用和排序剪枝

#### 核心思路

回溯通过起始下标避免不同顺序产生重复组合；允许重复使用当前元素时递归仍传入当前下标，排序后可在剩余值不足时提前剪枝。

**题目与边界**

给定不重复正整数 `candidates` 和目标 `target`，每个数字可重复使用，返回所有和为 target 的不同组合。

```text
candidates=[2,3,6,7], target=7
→ [[2,2,3], [7]]
```

**基线思路**

可以枚举所有可能长度的候选序列再筛选总和，但搜索空间巨大且会产生排列重复。回溯通过起点索引消除顺序重复，并在和超过目标时剪枝。

**为什么不用 used**

这是组合，不考虑顺序。使用 `start` 保证后续只选择当前位置及之后的数，避免 `[2,3,2]` 与 `[2,2,3]` 重复。

同一数字可重复使用，所以递归时传 `index`，而不是 `index+1`。

**剪枝为什么成立**

数组排序后，如果当前 `value > remaining`，后面的值只会更大，都不可能加入当前组合，所以 `break`。

这个剪枝依赖候选为正数；若存在负数，remaining 不再单调减少，可能无限递归或剪枝失效。

#### Python 代码

**代码**

**排列、组合、子集的模板区别**

| 类型 | 循环起点 | 是否 used | 何时记录 |
|---|---|---|---|
| 排列 | 每层从 0 | 通常需要 | 路径满足长度/条件 |
| 组合 | 从 start | 通常不需要 | 满足目标 |
| 子集 | 从 start | 通常不需要 | 每个节点都可记录 |

```python
def combination_sum(
    candidates: list[int],
    target: int,
) -> list[list[int]]:
    candidates = sorted(candidates)
    result: list[list[int]] = []
    path: list[int] = []

    def backtrack(start: int, remaining: int) -> None:
        if remaining == 0:
            result.append(path.copy())
            return

        for index in range(start, len(candidates)):
            value = candidates[index]
            if value > remaining:
                break

            path.append(value)
            backtrack(index, remaining - value)
            path.pop()

    backtrack(0, target)
    return result
```

#### 手动执行与复杂度

**推荐表达**

> 这是可重复选取、结果无序的组合问题。我先排序，用 start 下标保证只往后选，避免 [2,3,2] 和 [2,2,3] 这类顺序重复；因为允许重复使用当前数，递归时传 index 而不是 index+1。remaining 记录还差多少，减到 0 就记录一个组合；因为已排序，一旦 value > remaining 就 break 剪枝。这个剪枝依赖候选全为正数。

```python
def rob(nums: list[int]) -> int:
    if not nums:
        return 0
    if len(nums) == 1:
        return nums[0]

    dp = [0] * len(nums)
    dp[0] = nums[0]
    dp[1] = max(nums[0], nums[1])

    for index in range(2, len(nums)):
        dp[index] = max(
            dp[index - 1],
            dp[index - 2] + nums[index],
        )

    return dp[-1]
```

```python
def rob_optimized(nums: list[int]) -> int:
    prev_two = 0
    prev_one = 0

    for money in nums:
        current = max(prev_one, prev_two + money)
        prev_two = prev_one
        prev_one = current

    return prev_one
```

#### Python 代码

**代码**

```python
def min_distance(word1: str, word2: str) -> int:
    rows = len(word1) + 1
    cols = len(word2) + 1
    dp = [[0] * cols for _ in range(rows)]

    for row in range(rows):
        dp[row][0] = row
    for col in range(cols):
        dp[0][col] = col

    for row in range(1, rows):
        for col in range(1, cols):
            if word1[row - 1] == word2[col - 1]:
                dp[row][col] = dp[row - 1][col - 1]
            else:
                delete_cost = dp[row - 1][col]
                insert_cost = dp[row][col - 1]
                replace_cost = dp[row - 1][col - 1]
                dp[row][col] = 1 + min(
                    delete_cost,
                    insert_cost,
                    replace_cost,
                )

    return dp[-1][-1]
```

#### 手动执行与复杂度

**手动执行**

**复杂度**

- 时间 O(mn)；
- 空间 O(mn)，可以压缩为 O(min(m,n))，但面试先写清晰二维版。

- 插入和删除方向混淆；

- 只会背公式，解释不了三个邻居。

#### 面试表达与迁移

**推荐表达**

> 我定义 dp[i][j] 为两个前缀的编辑距离。空串边界分别需要 i 次删除或 j 次插入。最后字符相同就继承左上；不同则枚举最后一步是删除、插入或替换，对应上、左、左上三个状态加一。遍历顺序从小前缀到大前缀，时间和空间都是 O(mn)。

**DP 迁移练习**

## 4.1 稳定 Softmax

> 面试优先级：★★★★★｜学习难度：★★★☆☆｜适用岗位：算法、推理  
> 掌握要求：解释减最大值与数值稳定

### 题目与思路

Softmax 把 Logits 转成概率。计算前减去每行最大值不会改变结果，却能防止指数溢出；实现时还要沿正确维度归一化。

实现数值稳定的 Softmax：先减去最大值，再指数化和归一化，避免大数上溢。

**为什么减最大值不改变结果**

选择 `c=max(x)` 后所有指数输入不大于 0，减少上溢。极小值仍可能下溢为 0，但通常比整体上溢安全。

### 代码

```python
import numpy as np

def softmax(x: np.ndarray, axis: int = -1) -> np.ndarray:
    shifted = x - np.max(x, axis=axis, keepdims=True)
    exp_x = np.exp(shifted)
    return exp_x / np.sum(exp_x, axis=axis, keepdims=True)
```

```text
exp(x_i-c) / Σexp(x_j-c)
= exp(x_i)exp(-c) / [exp(-c)Σexp(x_j)]
= exp(x_i) / Σexp(x_j)
```

### 复杂度与边界

时间和空间都是 O(元素数)：一次求最大值、一次指数、一次求和。数值上减每行最大值把指数输入压到不大于 0 避免上溢；极小值可能下溢为 0，但比整体上溢安全。实现要沿正确的 axis 且 `keepdims=True` 才能正确广播相减，Attention 里通常沿 Key 维做。

### 面试准备

**推荐回答**

> Softmax 把 Logits 转成和为 1 的分布。直接 exp 大数会溢出，所以每行先减最大值；平移不会改变归一化结果，因为公共因子会约掉。实现时 axis 和 keepdims 要正确，Attention 通常沿 Key 维做 softmax。

**常见错误与迁移**

常见错误是忘记减最大值直接 exp 造成溢出、softmax 的 axis 选错、或 `keepdims=False` 导致广播维度错位。迁移练习：交叉熵里的 log-softmax、带温度系数的 softmax、带 Mask 的 softmax。

## 4.2 手写 Scaled Dot-Product Attention

> 面试优先级：★★★★★｜学习难度：★★★★☆｜适用岗位：算法、推理  
> 掌握要求：会张量形状、缩放和 Mask

### 题目与思路

Attention 先计算 Q 与 K 的缩放相似度，加入 Mask 后做 Softmax，再用权重对 V 加权。缩放用于控制分数方差，Mask 用于阻止读取非法位置。

根据 Q、K、V 计算缩放点积分数、Mask、Softmax 和加权求和，并检查张量形状。

**Causal Mask**

全被 Mask 的一行可能产生异常，应保证每个有效 Query 至少能看一个 Key，或在实现中专门处理。

### 代码

```python
import math
import torch

def scaled_dot_product_attention(
    query: torch.Tensor,
    key: torch.Tensor,
    value: torch.Tensor,
    mask: torch.Tensor | None = None,
) -> tuple[torch.Tensor, torch.Tensor]:
    """
    query: [..., query_len, head_dim]
    key:   [..., key_len, head_dim]
    value: [..., key_len, value_dim]
    mask:  可广播到 [..., query_len, key_len]，True表示允许读取
    """
    head_dim = query.size(-1)
    scores = query @ key.transpose(-2, -1)
    scores = scores / math.sqrt(head_dim)

    if mask is not None:
        scores = scores.masked_fill(~mask, torch.finfo(scores.dtype).min)

    weights = torch.softmax(scores, dim=-1)
    output = weights @ value
    return output, weights
```

```text
Q: [..., Q, D]
K: [..., K, D]
QK^T: [..., Q, K]
Weights×V: [..., Q, Vdim]
```

```python
def causal_mask(length: int, device: torch.device) -> torch.Tensor:
    return torch.tril(
        torch.ones(length, length, dtype=torch.bool, device=device)
    )
```

### 复杂度与边界

分数矩阵是 Q_len×K_len，时间和显存都随序列长度平方增长，这也是长上下文的瓶颈。缩放除以 sqrt(head_dim) 控制点积方差、防止 softmax 饱和；Mask 用 dtype 最小值填充而不是 0，否则 softmax 后仍留权重。要检查 Q/K/V 形状能否 matmul、Mask 能否广播到 [..., Q_len, K_len]，以及某一行被全部 Mask 时的异常。

### 面试准备

**推荐回答**

> Attention 先算 Q 与每个 K 的点积得到相似度，除以 sqrt(head_dim) 缩放，加上 Mask 后沿 Key 维做 softmax 得到权重，再用权重对 V 加权求和。缩放是为了让点积方差不随维度变大而把 softmax 推到饱和区；Mask 用极小值填充非法位置，softmax 后它们权重趋近 0。复杂度随序列长度平方增长。

**常见错误与迁移**

常见错误是忘记缩放、Mask 用 0 填充而不是负无穷、softmax 的 dim 选成 Query 维、或 K 转置的维度写错。迁移练习：加 Causal Mask 的自回归注意力、多头拆分、以及带 KV Cache 的增量注意力。

## 4.3 手写 Multi-Head Attention 核心

> 面试优先级：算法岗★★★★★；应用岗★★★☆☆｜学习难度：★★★★★  
> 掌握要求：会拆头、转置、合头和输出投影

### 题目与思路

Multi-Head Attention 把隐藏维度拆成多个头并行计算注意力，再拼接并线性投影。手写重点是掌握 reshape、transpose 后各维度的含义。

把隐藏维度拆为多个 Head 并行计算注意力，再拼接投影回原维度，重点掌握 reshape 与 transpose。

**为什么 `contiguous`**

`transpose` 改变张量步长，内存不一定连续；在 `view` 前调用 `contiguous()` 保证布局可解释。也可使用能处理布局的 `reshape`，但仍应理解复制可能性。

### 代码

```python
import torch
from torch import nn

class SimpleMultiHeadAttention(nn.Module):
    def __init__(self, hidden_size: int, num_heads: int) -> None:
        super().__init__()
        if hidden_size % num_heads != 0:
            raise ValueError("hidden_size must be divisible by num_heads")

        self.hidden_size = hidden_size
        self.num_heads = num_heads
        self.head_dim = hidden_size // num_heads

        self.q_proj = nn.Linear(hidden_size, hidden_size, bias=False)
        self.k_proj = nn.Linear(hidden_size, hidden_size, bias=False)
        self.v_proj = nn.Linear(hidden_size, hidden_size, bias=False)
        self.o_proj = nn.Linear(hidden_size, hidden_size, bias=False)

    def _split_heads(self, x: torch.Tensor) -> torch.Tensor:
        batch, seq_len, _ = x.shape
        x = x.view(batch, seq_len, self.num_heads, self.head_dim)
        return x.transpose(1, 2)  # [B, H, S, Dh]

    def forward(
        self,
        x: torch.Tensor,
        mask: torch.Tensor | None = None,
    ) -> torch.Tensor:
        query = self._split_heads(self.q_proj(x))
        key = self._split_heads(self.k_proj(x))
        value = self._split_heads(self.v_proj(x))

        attended, _ = scaled_dot_product_attention(
            query, key, value, mask
        )

        batch, _, seq_len, _ = attended.shape
        merged = attended.transpose(1, 2).contiguous().view(
            batch, seq_len, self.hidden_size
        )
        return self.o_proj(merged)
```

### 复杂度与边界

把 hidden 拆成 num_heads×head_dim，各头并行做注意力再拼回。关键是形状变换：view 成 [B,S,H,Dh] 后 transpose 成 [B,H,S,Dh]，合头时 transpose 回来必须先 `contiguous()` 再 view，否则步长不连续会报错或结果错乱。边界要保证 hidden_size 能被 num_heads 整除。

### 面试准备

**推荐回答**

> 多头注意力把隐藏维度平均拆成 num_heads 个头，每个头在低维子空间里独立算注意力，让模型关注不同的关系模式，最后拼接并用输出投影融合。手写关键是记住每一步形状：拆头 view+transpose 到 [B,H,S,Dh]，算完注意力再 transpose 回来、contiguous 后 view 合并，最后过 o_proj。

**常见错误与迁移**

常见错误是拆头后忘记 transpose 让头维和序列维混淆、合头前漏 `contiguous()`、或 hidden_size 不整除 num_heads。迁移练习：GQA/MQA 让多个 Query 头共享少量 KV 头、加入旋转位置编码 RoPE、以及接入 KV Cache。

## 4.4 手写 LayerNorm

> 面试优先级：★★★★☆｜学习难度：★★★★☆｜适用岗位：算法、推理  
> 掌握要求：理解按最后维归一化和 epsilon

### 题目与思路

LayerNorm 对每个 Token 的隐藏维度计算均值和方差，再标准化并使用可学习的缩放和平移。它不依赖 Batch 大小，适合 Transformer。

这里使用总体方差形式（`unbiased=False` 的等价思想）。RMSNorm 不减均值，主要按均方根缩放。

在每个样本的特征维上计算均值和方差，再归一化并施加可学习缩放与偏置。

### 代码

```python
import torch
from torch import nn

class SimpleLayerNorm(nn.Module):
    def __init__(self, hidden_size: int, eps: float = 1e-5) -> None:
        super().__init__()
        self.weight = nn.Parameter(torch.ones(hidden_size))
        self.bias = nn.Parameter(torch.zeros(hidden_size))
        self.eps = eps

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        mean = x.mean(dim=-1, keepdim=True)
        variance = ((x - mean) ** 2).mean(dim=-1, keepdim=True)
        normalized = (x - mean) / torch.sqrt(variance + self.eps)
        return normalized * self.weight + self.bias
```

### 复杂度与边界

对每个 token 在最后的特征维上求均值和方差，时间 O(元素数)。它不依赖 batch 大小，因此推理和变长序列都稳定。eps 加在方差开方里防止除零。这里用总体方差（除以 n）。边界要确认归一化维度是最后一维、weight/bias 形状等于 hidden_size。

### 面试准备

**推荐回答**

> LayerNorm 对单个样本的特征维做归一化：算这一维的均值和方差，标准化后再乘可学习的 weight、加 bias。它和 BatchNorm 的区别是统计量只在特征维、不跨样本，所以不受 batch 大小影响，适合变长的 Transformer 序列。eps 防止方差为 0 时除零。RMSNorm 则省去减均值，只按均方根缩放。

**常见错误与迁移**

常见错误是把归一化维度写成 batch 维、忘记 eps 导致数值不稳、或漏掉可学习的 weight/bias。迁移练习：实现 RMSNorm、比较 Pre-Norm 与 Post-Norm、以及在混合精度下用 fp32 做归一化统计。

## 4.5 余弦相似度与 Top-K

> 面试优先级：★★★★★｜学习难度：★★★☆☆｜适用岗位：RAG、算法  
> 掌握要求：处理零向量并返回排序结果

### 题目与思路

余弦相似度比较两个向量方向，先做 L2 归一化后可用点积计算。Top-K 只需要选出最大 K 个分数，不必总是完整排序全部候选。

`argpartition` 找 Top-K 候选平均更高效，但候选内部无序，因此还要局部排序。

计算查询向量与候选向量的余弦相似度，并返回分数最高的 K 个结果，注意零向量和归一化。

### 代码

```python
import numpy as np

def cosine_similarity(a: np.ndarray, b: np.ndarray) -> float:
    denominator = np.linalg.norm(a) * np.linalg.norm(b)
    if denominator == 0:
        return 0.0
    return float(np.dot(a, b) / denominator)

def vector_top_k(
    query: np.ndarray,
    documents: np.ndarray,
    k: int,
) -> list[tuple[int, float]]:
    if k <= 0 or len(documents) == 0:
        return []

    query_norm = np.linalg.norm(query)
    doc_norms = np.linalg.norm(documents, axis=1)
    denominators = doc_norms * query_norm

    scores = np.zeros(len(documents), dtype=float)
    valid = denominators > 0
    scores[valid] = (documents[valid] @ query) / denominators[valid]

    k = min(k, len(documents))
    candidate_indices = np.argpartition(scores, -k)[-k:]
    sorted_indices = candidate_indices[
        np.argsort(scores[candidate_indices])[::-1]
    ]
    return [(int(index), float(scores[index])) for index in sorted_indices]
```

### 复杂度与边界

余弦相似度是 O(d)，对 n 个候选批量算是 O(nd)。取 Top-K 用 `argpartition` 平均 O(n) 划出 k 个候选、再对这 k 个排序 O(k log k)，优于全量排序 O(n log n)。边界要处理零向量（分母为 0 返回 0，不能除）、k<=0 或候选为空、以及 k>=n 直接排序。

### 面试准备

**推荐回答**

> 余弦相似度衡量两个向量的方向夹角，与模长无关，等价于先做 L2 归一化再点积。批量检索时我先算查询和所有候选的范数，遇到零向量把分数置 0 避免除零；取 Top-K 用 argpartition 先划出最大的 k 个再局部排序，不必给全部候选排序。这也是向量检索里 recall 的基础。

**常见错误与迁移**

常见错误是不处理零向量导致除零、用 argpartition 后忘记对候选内部再排序、或把点积当余弦却没先归一化。迁移练习：批量矩阵化算相似度、结合 HNSW/IVF 近似检索、以及和 BM25 分数做 RRF 融合。

## 5.1 结构友好的文本切分

> 面试优先级：★★★★★｜学习难度：★★★☆☆｜适用岗位：RAG、应用  
> 掌握要求：理解字符示例与真实 Token 切分的差别

### 题目与思路

文本切分应优先保留标题、段落、条款等语义边界，超长时再按长度递归拆分，并用适量重叠降低边界信息丢失；Chunk 还要携带来源元数据。

下面是教学版字符切分器，优先按段落聚合，超长段落再滑窗；生产中应按模型 Tokenizer 计数并保留标题/页码元数据。

按标题、段落和句子边界切分文本，在块大小受控的同时尽量保留完整语义和重叠上下文。

### 代码

```python
def split_text(
    text: str,
    chunk_size: int = 500,
    overlap: int = 50,
) -> list[str]:
    if chunk_size <= 0:
        raise ValueError("chunk_size must be positive")
    if overlap < 0 or overlap >= chunk_size:
        raise ValueError("overlap must be in [0, chunk_size)")

    paragraphs = [part.strip() for part in text.split("\n\n") if part.strip()]
    chunks: list[str] = []
    current = ""

    def flush_current() -> None:
        nonlocal current
        if current:
            chunks.append(current)
            current = ""

    for paragraph in paragraphs:
        if len(paragraph) <= chunk_size:
            candidate = paragraph if not current else current + "\n\n" + paragraph
            if len(candidate) <= chunk_size:
                current = candidate
            else:
                flush_current()
                current = paragraph
            continue

        flush_current()
        step = chunk_size - overlap
        start = 0
        while start < len(paragraph):
            end = min(start + chunk_size, len(paragraph))
            chunks.append(paragraph[start:end])
            if end == len(paragraph):
                break
            start += step

    flush_current()
    return chunks
```

### 复杂度与边界

整体是一趟扫描加超长段落的滑窗，时间约 O(总字符数)、额外空间为输出块。边界要处理空文本（返回空列表）、单个超长段落（滑窗拆分并保留 overlap）、以及非法参数（chunk_size<=0、overlap>=chunk_size）。这是字符级教学版，真实系统应按 Tokenizer 计数并保留标题、页码等元数据。

### 面试准备

**推荐回答**

这段代码展示边界和 Overlap，不代表合同、表格和 PDF 都应固定长度切。真实系统先做结构解析，再按 Token 和语义递归处理。

**常见错误与迁移**

常见错误是按固定字符数硬切破坏句子和条款、overlap 设为 0 丢失跨块上下文、或切分后不携带来源元数据导致无法引用。迁移练习：按 Token 计数切分、按 Markdown 标题层级递归切分、给每个 Chunk 附上文档 ID 和页码。

## 5.2 BM25 简化实现

> 面试优先级：★★★★☆｜学习难度：★★★★☆｜适用岗位：RAG、搜索  
> 掌握要求：解释 TF 饱和、IDF 和长度归一化

### 题目与思路

BM25 根据查询词在文档中的词频、全库逆文档频率和文档长度计算相关度，既奖励命中又抑制高频词与超长文档的无效优势。

教学代码没有中文分词、字段权重、倒排表加速和查询词去重。生产搜索引擎不会每次遍历全部文档。

实现词项频率、逆文档频率和长度归一化，理解它为什么擅长编号、专有名词和原词匹配。

### 代码

```python
import math
from collections import Counter

class SimpleBM25:
    def __init__(
        self,
        documents: list[list[str]],
        k1: float = 1.5,
        b: float = 0.75,
    ) -> None:
        self.documents = documents
        self.k1 = k1
        self.b = b
        self.doc_count = len(documents)
        self.doc_lengths = [len(document) for document in documents]
        self.avg_doc_length = (
            sum(self.doc_lengths) / self.doc_count if self.doc_count else 0.0
        )
        self.term_frequencies = [Counter(document) for document in documents]

        document_frequency: Counter[str] = Counter()
        for document in documents:
            document_frequency.update(set(document))

        self.idf = {
            term: math.log(
                1 + (self.doc_count - frequency + 0.5) / (frequency + 0.5)
            )
            for term, frequency in document_frequency.items()
        }

    def score(self, query: list[str], doc_index: int) -> float:
        if not self.documents or self.avg_doc_length == 0:
            return 0.0

        frequencies = self.term_frequencies[doc_index]
        doc_length = self.doc_lengths[doc_index]
        score = 0.0

        for term in query:
            tf = frequencies.get(term, 0)
            if tf == 0:
                continue
            denominator = tf + self.k1 * (
                1 - self.b + self.b * doc_length / self.avg_doc_length
            )
            score += self.idf.get(term, 0.0) * tf * (self.k1 + 1) / denominator

        return score

    def search(self, query: list[str], k: int) -> list[tuple[int, float]]:
        scored = [
            (index, self.score(query, index))
            for index in range(self.doc_count)
        ]
        return sorted(scored, key=lambda item: item[1], reverse=True)[:k]
```

### 复杂度与边界

构建时统计词频和文档频率约 O(总词数)，单次打分 O(查询词数)，教学版 search 遍历全部文档是 O(文档数×查询词数)。k1 控制词频饱和、b 控制长度归一化。边界要处理空文档集、avg_doc_length 为 0（返回 0）和查询词不在库中。生产系统用倒排索引避免遍历全库。

### 面试准备

**推荐回答**

> BM25 给每个查询词打分再求和：IDF 抑制在很多文档里都出现的常见词，词频项带饱和（k1）让重复命中的收益递减，长度归一化（b）避免长文档仅因为词多就占便宜。它对编号、专有名词、原词匹配很强，因为是词项精确匹配；缺点是不理解同义改写，所以常和向量检索互补。

**常见错误与迁移**

常见错误是漏掉长度归一化让长文档虚高、IDF 公式写错导致负分、或没做分词就按空格切中文。迁移练习：加字段权重（标题比正文重）、用倒排表加速、以及和向量检索结果做 RRF 融合。

## 5.3 RRF 融合

> 面试优先级：★★★★★｜学习难度：★★☆☆☆｜适用岗位：RAG  
> 掌握要求：理解按排名而非原始分数融合

### 题目与思路

RRF 不直接比较不同检索器的原始分数，而是按每个文档在各结果列表中的排名累加倒数得分，因此适合融合 BM25 与向量检索。

RRF 不要求 BM25 分数和余弦分数同尺度。`rank_constant` 越大，头部排名差异被平滑得越多。

只使用多个检索器的排名而非原始分数进行融合，处理分数量纲不可比的问题。

### 代码

```python
from collections import defaultdict
from collections.abc import Hashable, Sequence

def reciprocal_rank_fusion(
    rankings: Sequence[Sequence[Hashable]],
    rank_constant: int = 60,
) -> list[tuple[Hashable, float]]:
    scores: dict[Hashable, float] = defaultdict(float)

    for ranking in rankings:
        for rank, document_id in enumerate(ranking, start=1):
            scores[document_id] += 1.0 / (rank_constant + rank)

    return sorted(scores.items(), key=lambda item: item[1], reverse=True)
```

### 复杂度与边界

只依赖排名，时间 O(所有列表长度之和)，空间 O(去重文档数)。rank_constant 越大，头部与尾部排名的得分差被压得越平。边界要处理空列表、同一文档在多个列表出现（得分累加）、以及不同列表长度不一致。

### 面试准备

**推荐回答**

> RRF 融合多路检索时不看原始分数，只看每个文档在各列表里的排名，累加 1/(rank_constant+rank)。这样 BM25 分数和余弦分数量纲不同也能融合，不需要归一化对齐。排名越靠前贡献越大，多个检索器都认可的文档自然排到前面。rank_constant 常取 60，用来平滑头部差异。

**常见错误与迁移**

常见错误是试图把不同检索器的原始分数直接相加、rank 从 0 开始导致首位得分被高估、或忘记对同一文档跨列表累加。迁移练习：加权 RRF、融合三路以上检索、以及在 RRF 之后接重排模型。

## 6.1 模型权重显存估算

> 面试优先级：★★★★★｜学习难度：★★★☆☆｜适用岗位：部署、微调

### 题目与思路

一个参数使用多少 bit 保存，决定了纯权重的理论下限。计算时先用“参数量 × 每参数位数 ÷ 8”得到字节，再换算成 GiB；但这个结果只代表权重，不是模型运行时的总显存。

例：7B 参数、16-bit，理论权重约：

实际推理还包括量化 Scale、KV Cache、激活、临时 Buffer、CUDA Context 和碎片；训练还包括梯度与优化器状态。

根据参数量和每参数字节数估算权重下限，并说明实际部署还需要 KV Cache、临时缓冲和运行时开销。

### 代码

```python
def weight_memory_gib(
    parameters: int,
    bits_per_parameter: float,
) -> float:
    return parameters * bits_per_parameter / 8 / (1024**3)
```

```text
7e9 × 16 / 8 / 1024³ ≈ 13.0 GiB
```

### 复杂度与边界

公式是 参数量 × 每参数位数 ÷ 8 换成字节再除 1024³ 得 GiB，计算本身 O(1)。关键是区分理论权重下限与运行峰值：实际还要加量化 Scale、KV Cache、激活、临时 Buffer、CUDA Context 和碎片，训练还要加梯度和优化器状态。精度变化（FP16/INT8/4-bit）直接按比例缩放权重大小。

### 面试准备

**推荐回答**

> 7B 模型用 FP16/BF16 保存时，纯权重约 14 GB，也就是约 13 GiB；4-bit 理论权重约四分之一。但部署还要为 KV Cache、临时 Buffer、运行时和量化元数据留空间，训练还会增加梯度与优化器状态，所以不能用纯权重大小直接判断显卡一定能运行。

**常见错误与迁移**

常见错误是把纯权重大小当成显卡够不够的唯一依据、漏算量化元数据、或混淆 GB 与 GiB。迁移练习：估算训练时权重+梯度+优化器状态的总量、估算不同量化位宽下的权重、以及结合 KV Cache 算总显存。

## 6.2 KV Cache 显存估算

> 面试优先级：★★★★★｜学习难度：★★★★☆｜适用岗位：推理部署  
> 掌握要求：能解释 GQA/MQA 如何改变公式

### 题目与思路

每一层都要为历史 Token 保存 K 和 V，因此 KV Cache 随层数、序列长度、Batch、KV Head 数和单元素字节数近似线性增长。GQA/MQA 减少的是 KV Head 数，所以能够显著降低这部分显存。

系数 2 是 K 和 V。实际引擎还存在 Block 对齐、并行分片和元数据。

根据层数、Batch、序列长度、KV Head、Head Dim、K/V 两份和数据类型估算缓存显存。

### 代码

```python
def kv_cache_gib(
    num_layers: int,
    sequence_length: int,
    num_kv_heads: int,
    head_dim: int,
    bytes_per_element: int,
    batch_size: int = 1,
) -> float:
    total_bytes = (
        2
        * num_layers
        * sequence_length
        * num_kv_heads
        * head_dim
        * bytes_per_element
        * batch_size
    )
    return total_bytes / (1024**3)
```

### 复杂度与边界

显存约 2 × 层数 × 序列长度 × KV Head 数 × Head Dim × 元素字节数 × Batch，随这些量线性增长，计算 O(1)。系数 2 是 K 和 V 两份。GQA/MQA 减少的正是 KV Head 数，所以长上下文、高并发时省显存明显。边界要检查是否漏乘层数或 K/V 两份，以及分页对齐和并行分片带来的额外开销。

### 面试准备

**推荐回答**

> 单请求 KV Cache 可以近似按 `2 × 层数 × 序列长度 × KV Head 数 × Head Dim × 元素字节数` 估算，再乘 Batch。MHA 中 KV Head 通常与 Query Head 相同，GQA/MQA 通过共享 K/V 减少 KV Head，因此长上下文和高并发时更省显存。实际容量还要考虑分页对齐、并行分片和引擎预留。

**常见错误与迁移**

常见错误是漏乘层数或 K/V 两份、用 Query Head 数代替 KV Head 数、或忘了乘 Batch。迁移练习：算 GQA 相对 MHA 省多少 KV 显存、估算给定显存下能支持的最大序列长度或并发数、以及 PagedAttention 的分块对齐开销。

## 6.3 TTFT、TPOT 与 ITL 统计

> 面试优先级：★★★★☆｜学习难度：★★★☆☆｜适用岗位：部署、平台  
> 掌握要求：正确处理只有一个输出 Token 的边界

### 题目与思路

延迟统计应基于请求开始、首 Token、每个 Token 和结束时间戳。TTFT 衡量首包等待，TPOT 是输出阶段平均间隔，ITL 保留逐 Token 抖动，只有一个 Token 时要处理除零边界。

TPOT 只在至少两个输出 Token 时有相邻间隔。应按输入/输出长度、并发和缓存命中切片。

根据请求时间戳计算首 Token 延迟、相邻 Token 间隔和平均输出 Token 时间，并正确处理只有一个输出 Token 的情况。

### 代码

```python
from dataclasses import dataclass

@dataclass
class LatencyMetrics:
    ttft: float
    tpot: float | None
    itl: list[float]
    e2e: float

def calculate_latency(
    request_start: float,
    token_timestamps: list[float],
    request_end: float,
) -> LatencyMetrics:
    if not token_timestamps:
        raise ValueError("at least one output token timestamp is required")

    ttft = token_timestamps[0] - request_start
    itl = [
        current - previous
        for previous, current in zip(token_timestamps, token_timestamps[1:])
    ]
    tpot = sum(itl) / len(itl) if itl else None
    e2e = request_end - request_start
    return LatencyMetrics(ttft=ttft, tpot=tpot, itl=itl, e2e=e2e)
```

### 复杂度与边界

基于时间戳做差，计算 O(输出 Token 数)。TTFT=首 Token 时间−请求开始；ITL 是相邻 Token 时间差的列表，保留抖动；TPOT 是 ITL 的平均。边界关键：只有一个输出 Token 时没有相邻间隔，ITL 为空、TPOT 应为 None 而不是除零。统计时还应按输入/输出长度、并发和缓存命中分桶。

### 面试准备

**推荐回答**

> 首 Token 延迟 TTFT 反映排队加 Prefill 的等待，是首包体验；TPOT 是输出阶段相邻 Token 的平均间隔，反映 Decode 稳态速度；ITL 保留每个间隔用来看抖动和长尾。我用请求开始、每个 Token 时间戳和结束时间计算，特别注意只有一个输出 Token 时没有相邻间隔，TPOT 要返回 None 避免除零。看整体要用 P95/P99 而不是平均。

**常见错误与迁移**

常见错误是只有一个 Token 时对空列表求平均导致除零、把 TPOT 平均值当成每个 Token 的真实间隔（掩盖抖动）、或只看均值不看 P99。迁移练习：按输入/输出长度分桶统计、计算吞吐（tokens/s）、以及区分流式与非流式的延迟口径。

## 7.1 Token Bucket 限流器

> 面试优先级：★★★★☆｜学习难度：★★★★☆｜适用岗位：后端、模型网关  
> 掌握要求：理解速率、容量和突发

### 题目与思路

Token Bucket 按固定速率补充令牌，请求消耗令牌；桶中积累的令牌允许短时突发，但长期平均速率受控。实现时要正确处理时间推进和并发安全。

- `rate`：每秒补充 Token；
- `capacity`：允许的最大突发；
- 大模型网关可让 cost 与输入/最大输出 Token 估算相关；
- 单进程锁只保护本实例，分布式限流需 Redis/网关等共享状态。

按时间补充令牌、请求到达时扣减令牌，用容量允许短时突发，用补充速率限制长期吞吐。

### 代码

```python
import threading
import time

class TokenBucket:
    def __init__(self, rate: float, capacity: float) -> None:
        if rate <= 0 or capacity <= 0:
            raise ValueError("rate and capacity must be positive")
        self.rate = rate
        self.capacity = capacity
        self.tokens = capacity
        self.updated_at = time.monotonic()
        self.lock = threading.Lock()

    def allow(self, cost: float = 1.0) -> bool:
        if cost <= 0:
            raise ValueError("cost must be positive")

        with self.lock:
            now = time.monotonic()
            elapsed = now - self.updated_at
            self.tokens = min(
                self.capacity,
                self.tokens + elapsed * self.rate,
            )
            self.updated_at = now

            if self.tokens < cost:
                return False
            self.tokens -= cost
            return True
```

### 复杂度与边界

每次 allow 是 O(1)：按流逝时间补充令牌、判断是否够扣。capacity 决定允许的突发上限，rate 决定长期平均速率。边界要处理 rate/capacity 非正、cost 非正，以及令牌补充后不能超过 capacity。锁只保护单进程本实例，多实例或分布式限流要用 Redis 等共享状态。

### 面试准备

**推荐回答**

> 令牌桶以固定 rate 往桶里加令牌，桶容量 capacity 决定能积攒多少、也就是允许多大的瞬时突发；请求到来时按 cost 扣令牌，不够就拒绝。它和漏桶的区别是允许突发。我用 monotonic 时间按流逝时长惰性补令牌，避免单独的定时器；大模型网关里 cost 可以按输入和最大输出 Token 估算。

**常见错误与迁移**

常见错误是用 wall clock 而非单调时钟导致校时抖动、补令牌后忘记封顶到 capacity、或以为单进程锁能做分布式限流。迁移练习：改成漏桶、用 Redis+Lua 做分布式限流、按 Token 成本而非请求数限流。

## 7.2 LRU Cache

> 面试优先级：★★★★☆｜学习难度：★★★★☆｜适用岗位：后端、算法  
> 掌握要求：理解哈希表 + 双向链表 O(1)

### 题目与思路

LRU 在容量满时淘汰最久没有访问的数据。高效实现需要哈希表提供 O(1) 查找，并用双向链表或 OrderedDict 维护访问顺序。

Python 标准库可用 `OrderedDict` 实现教学版：

面试官若要求底层实现，需要哈希表定位节点 + 双向链表 O(1) 移到头部和淘汰尾部。应用层还要考虑 TTL、并发、权限和版本，LRU 只解决容量淘汰。

在 O(1) 时间内完成读取、写入和淘汰最近最少使用项，理解哈希表与双向链表的组合。

### 代码

```python
from collections import OrderedDict
from typing import Generic, TypeVar

K = TypeVar("K")
V = TypeVar("V")

class LRUCache(Generic[K, V]):
    def __init__(self, capacity: int) -> None:
        if capacity <= 0:
            raise ValueError("capacity must be positive")
        self.capacity = capacity
        self.data: OrderedDict[K, V] = OrderedDict()

    def get(self, key: K) -> V | None:
        if key not in self.data:
            return None
        self.data.move_to_end(key)
        return self.data[key]

    def put(self, key: K, value: V) -> None:
        if key in self.data:
            self.data.move_to_end(key)
        self.data[key] = value

        if len(self.data) > self.capacity:
            self.data.popitem(last=False)
```

### 复杂度与边界

get/put/淘汰都要 O(1)：教学版用 OrderedDict，get 命中后 move_to_end 记为最近使用，put 超容量时 popitem(last=False) 淘汰最久未用；底层等价于哈希表定位加双向链表维护顺序。边界要处理 capacity<=0、更新已有 key（先移到末尾再赋值）。应用层的 TTL、并发、版本失效不在 LRU 职责内。

### 面试准备

**推荐回答**

> LRU 淘汰最久没被访问的项。要做到 O(1)，需要哈希表按 key 直接定位，再用双向链表维护访问顺序：命中就把节点移到头部，容量满就删尾部。Python 里 OrderedDict 的 move_to_end 和 popitem 正好封装了这两步。它只解决容量淘汰，过期和一致性要另加 TTL 和失效机制。

**常见错误与迁移**

常见错误是用普通 dict 加时间戳扫描导致淘汰变 O(n)、get 命中后忘记更新访问顺序、或更新已有 key 时不移到末尾。迁移练习：手写双向链表版 LRU、实现带 TTL 的缓存、以及 LFU 淘汰策略。

## 7.3 异步重试与指数退避

> 面试优先级：★★★★★｜学习难度：★★★★☆｜适用岗位：Agent、后端  
> 掌握要求：只重试可恢复错误，并加入抖动

### 题目与思路

重试只适用于可能恢复的临时错误，并应使用指数退避和随机抖动避免同时重试形成尖峰；有副作用操作还必须先保证幂等。

只对可重试错误进行有限次数重试，使用指数退避和抖动，避免瞬时故障放大为重试风暴。

**关键点**

- 参数错误、鉴权失败和业务拒绝通常不重试；
- 429、部分网络异常和部分 5xx 可能重试；
- 尊重 `Retry-After`；
- 副作用操作必须有幂等键；
- 总请求还要有 Deadline，不能每层各自重试导致重试风暴。

### 代码

```python
import asyncio
import random
from collections.abc import Awaitable, Callable
from typing import TypeVar

R = TypeVar("R")

async def retry_async(
    operation: Callable[[], Awaitable[R]],
    is_retryable: Callable[[Exception], bool],
    max_attempts: int = 3,
    base_delay: float = 0.5,
    max_delay: float = 8.0,
) -> R:
    if max_attempts <= 0:
        raise ValueError("max_attempts must be positive")

    for attempt in range(max_attempts):
        try:
            return await operation()
        except Exception as error:
            is_last = attempt == max_attempts - 1
            if is_last or not is_retryable(error):
                raise

            delay = min(max_delay, base_delay * (2**attempt))
            jittered_delay = random.uniform(0, delay)
            await asyncio.sleep(jittered_delay)

    raise RuntimeError("unreachable")
```

### 复杂度与边界

最多尝试 max_attempts 次，退避时间按 base×2^attempt 指数增长并封顶到 max_delay，再加 [0,delay) 随机抖动打散重试峰值。边界要区分可重试错误（429、部分 5xx、瞬时网络）和不可重试错误（参数错、鉴权失败、业务拒绝），最后一次失败必须抛出。整体还应有总 Deadline，避免各层各自重试叠加成风暴。

### 面试准备

**推荐回答**

> 重试只对可能自愈的临时错误有意义，参数错误、鉴权失败、业务拒绝重试只会浪费。我用 is_retryable 判断是否该重试，退避用指数增长加随机抖动，避免大量客户端同时重试形成尖峰；尊重服务端的 Retry-After。有副作用的操作必须带幂等键，否则重试会重复执行。

**常见错误与迁移**

常见错误是无脑重试所有异常（包括业务错误）、退避不加抖动导致同步重试风暴、或对非幂等操作重试造成重复副作用。迁移练习：加熔断器、区分幂等与非幂等操作、以及给整条调用链设统一 Deadline。

## 7.4 并发工具调用：保留部分成功

> 面试优先级：★★★★☆｜学习难度：★★★★☆｜适用岗位：Agent  
> 掌握要求：输出结构化结果，不吞异常

### 题目与思路

彼此独立的工具可并发以降低总延迟，但每个结果都应结构化记录成功或失败，并受统一超时和并发上限控制；是否允许部分成功由业务语义决定。

只有无数据依赖、无冲突副作用的工具可这样并行。错误结果要脱敏并转换为模型可理解的稳定错误码，不能把内部堆栈全部放进 Prompt。

并发调用多个独立工具，分别记录成功和失败，使一个工具异常不会丢失其他有效结果。

### 代码

```python
import asyncio
from dataclasses import dataclass
from typing import Any

@dataclass
class ToolResult:
    name: str
    ok: bool
    value: Any = None
    error: str | None = None

async def call_tool_safely(
    name: str,
    tool,
    timeout: float,
) -> ToolResult:
    try:
        async with asyncio.timeout(timeout):
            value = await tool()
        return ToolResult(name=name, ok=True, value=value)
    except Exception as error:
        return ToolResult(name=name, ok=False, error=repr(error))

async def call_independent_tools(tools: dict[str, Any]) -> list[ToolResult]:
    return await asyncio.gather(
        *(call_tool_safely(name, tool, 5.0) for name, tool in tools.items())
    )
```

### 复杂度与边界

并发总时间约等于最慢工具，用 gather 一起等待，每个工具单独 timeout。返回结构化的 ToolResult 而不是裸值或异常，让一个工具失败不影响其他结果。边界要明确是否允许部分成功，错误信息要脱敏并转成模型可理解的稳定错误码。只有无数据依赖、无冲突副作用的工具才能这样并行。

### 面试准备

**推荐回答**

> 彼此独立、没有数据依赖的工具可以并发调用来压低总延迟。我把每个工具包成 call_tool_safely，单独设超时，成功和失败都返回结构化 ToolResult，这样一个工具抛异常不会让整批丢失。是否允许部分成功由业务决定；返回给模型的错误要脱敏成稳定错误码，不能把内部堆栈塞进 Prompt。

**常见错误与迁移**

常见错误是用 gather 默认行为让一个异常中断全部、把异常对象直接当结果返回、或把原始堆栈暴露给模型。迁移练习：给并发加 Semaphore 上限、对有依赖的工具改成分阶段调用、以及对失败工具做选择性重试。
