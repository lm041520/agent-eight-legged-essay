# 06 多模态、OCR 与 CV

> 目标：理解图像如何变成视觉 Token、视觉编码器如何与 LLM 对齐，并能设计 OCR、版面、表格和多模态 RAG 场景。

## 0. 模块地图

```text
图片文件
→ 解码为像素矩阵
→ Resize/Crop/Normalize
→ 视觉编码器(CNN/ViT)
→ 视觉特征
→ Projector/Adapter/Q-Former
→ 映射为LLM可接收的视觉Token
→ 与文本Token组合
→ 多模态Transformer理解与生成
```

文档 OCR 主链：

```text
页面图像
→ 文本检测
→ 文字识别
→ 方向/阅读顺序
→ 版面与表格结构
→ 文本、坐标、置信度、层级
→ Chunk与多模态RAG
```

优先级：

- ★★★★★：ViT/视觉 Token、VLM 架构、OCR 检测识别、版面与表格、OCR-RAG；
- ★★★★☆：CLIP 对齐、多模态模板、Grounding、幻觉与评测；
- ★★★☆☆：视频采样、Diffusion/VAE/Latent、复杂生成式视觉。

# 第一部分：常规八股

## 1. 图片在计算机和模型中分别是什么？

> 面试优先级：★★★★☆｜学习难度：★★★☆☆｜适用岗位：多模态、CV、文档智能  
> 掌握要求：能从文件字节讲到张量

**一句话**：图片文件是 JPEG、PNG 等格式的压缩字节，解码后才变成 `[height, width, channels]` 的像素矩阵；模型真正接收的是按训练约定 Resize、Crop、Normalize 后的数值张量，再逐层转成视觉特征。

人看到的是物体和文字，计算机最初拿到的只是像素数值。模型不能直接对文件路径做卷积或 Attention，必须先把字节解码成像素，再转换成 Patch 或特征向量才能参与计算。理解这层转换，才能继续解释分辨率、归一化、视觉 Token 数量以及为什么同一图片缩放后效果会变化。

解码得到的像素数组用 RGB 三通道表示红、绿、蓝，不同库可能使用 BGR，顺序错误会导致颜色异常。之后按模型 Processor 的训练约定预处理：

- Resize：调整分辨率；
- Crop/Padding：满足模型输入形状并控制几何失真；
- Normalize：将像素按训练时均值/方差变换；
- Batch/Channel 转换：例如 `[B,C,H,W]`；
- 数据类型：uint8、FP16/FP32 等。

必须使用模型 Processor 的训练约定，不能随意改变缩放和归一化。

**面试怎么说**

> 图片文件首先是压缩字节，需要解码成 H×W×C 的像素矩阵，再按模型训练约定做颜色通道、Resize、Crop/Padding、Normalize 和张量布局。预处理错误会造成分布偏移，例如 OpenCV 的 BGR 与模型期望 RGB 不一致。进入视觉编码器后才变成高层视觉特征和视觉 Token。

**坑**

- 把颜色通道顺序搞反（BGR/RGB），导致颜色和识别异常；
- 擅自更改 Resize、归一化均值/方差，脱离训练分布；
- 以为模型直接吃文件或路径，忽略解码与张量化这一步。

## 2. CNN 和 ViT 有什么区别？

> 面试优先级：★★★★☆｜学习难度：★★★☆☆｜适用岗位：多模态、CV  
> 掌握要求：能比较归纳偏置、全局关系和数据规模

**一句话**：CNN 用局部卷积逐层提取边缘、纹理和形状，具有较强局部归纳偏置；ViT 把图片切成 Patch Token 用 Self-Attention 建模全局关系，结构更贴近语言 Transformer，但通常更依赖大规模预训练。

CNN 的卷积核在局部区域滑动，具有局部连接和权重共享，天然具备局部性和平移等归纳偏置，逐层扩大感受野，适合提取边缘、纹理和形状。ViT 把图像切成 Patch，每个 Patch 展平并线性投影为 Token，再用 Transformer 建模 Patch 之间关系；Self-Attention 更容易直接建立远距离交互，但标准 Attention 的成本随 Patch 数平方增长。因此小数据任务中 CNN 的局部先验可能更省样本，大规模预训练下 ViT 更容易统一到 Transformer 生态。

| 维度 | CNN | ViT |
|---|---|---|
| 基本单元 | 局部卷积 | Patch Token Attention |
| 归纳偏置 | 局部性强 | 相对弱，更依赖数据/预训练 |
| 全局关系 | 逐层扩大感受野 | Attention 直接交互 |
| 分辨率成本 | 与特征图有关 | Patch 数增加会显著增加 Attention |
| 现代实践 | 仍广泛用于检测/边缘 | 多模态视觉编码器常见 |

**面试怎么说**

> CNN 通过局部卷积和权重共享提取层级特征，具有较强局部归纳偏置；ViT 把图片切成 Patch Token，用 Self-Attention 建模全局关系，结构更容易与语言 Transformer 对接，但通常更依赖大规模预训练，而且高分辨率会带来更多 Patch 和注意力成本。实际并不是二选一，很多系统使用混合或层级视觉骨干。

**坑**

- 把 CNN 与 ViT 当成必须二选一，忽略混合/层级骨干；
- 忽略 ViT 高分辨率时 Patch 数和注意力成本的快速增长。

## 3. ViT 如何把图片变成视觉 Token？

> 面试优先级：★★★★★｜学习难度：★★★★☆｜适用岗位：多模态、VLM  
> 掌握要求：会计算 Patch 数和张量形状

### 先理解

ViT 先把图片切成固定大小 Patch，将每个 Patch 展平并线性投影到隐藏维度，再加入位置信息。这样每个图块就变成类似文本 Token 的向量，可送入 Transformer。

Transformer 接收的是向量序列，而原始图片是二维像素网格。ViT 必须先把图片切成 Patch、映射成固定维度向量并加入位置信息，才能让图像像文本 Token 一样进入多层 Attention。

**高分辨率为什么贵**

如果边长翻倍，Patch 数约变为 4 倍，标准视觉 Attention 的关系矩阵可能变为 16 倍。实际 VLM 可能使用动态切图、分块、降采样或层级 Token 控制成本。

### 原理与应用

#### Patchify

图片 `[H,W,C]`，Patch 大小 `P×P`，不重叠时 Patch 数：

```text
N = (H/P) × (W/P)
```

例如 `224×224` 图片、`P=16`：

```text
N = 14×14 = 196
```

每个 Patch 展平成 `P×P×C`，再线性投影到隐藏维度 `D`：

```text
[196, 16×16×3] → [196, D]
```

加入位置编码后经过 Transformer Encoder，得到上下文相关视觉表示。

### 面试准备

**推荐回答**

> ViT 把图像划分为固定 Patch，将每个 Patch 展平并线性映射成一个向量，加位置编码后作为 Token 序列送进 Transformer。Patch 数大致是 H/P 乘 W/P，因此分辨率上升会快速增加视觉 Token 和 Attention 成本。VLM 通常再通过 Projector 把这些特征映射到 LLM 隐藏空间。

## 4. 多模态大模型背后的典型架构是什么？

> 面试优先级：★★★★★｜学习难度：★★★★☆｜适用岗位：多模态、Agent  
> 掌握要求：能解释 Encoder、Adapter 和 LLM 三段

### 先理解

典型多模态模型由视觉编码器、连接层和语言模型组成：视觉编码器提取图片特征，Projector/Adapter 把维度与分布对齐到语言空间，LLM 再联合理解视觉 Token 与文本 Token。

LLM 原本只接收文本 Token，图片必须先由视觉编码器提取特征，再经过投影层对齐到语言模型隐藏维度。这个接口决定了模型究竟能看到 OCR 文字、图像区域还是视频帧，也解释了为什么只有文本提取能力的系统不一定是真正的视觉理解。

### 原理与应用

#### 三段式架构

1. **模态编码器**：图像用 ViT，音频用声学编码器等，提取该模态特征；
2. **连接模块**：Projector/Adapter/Q-Former 将特征维度、数量和分布转换为 LLM 可接收形式；
3. **LLM**：将视觉 Token 与文本 Token 一起建模并生成答案。

#### 连接方法

- 线性/MLP Projector：简单高效，直接映射维度；
- Q-Former/Query Token：用少量可学习 Query 从视觉特征提取信息，压缩 Token；
- Cross-Attention：LLM 层通过交叉注意力读取视觉特征；
- 直接拼接：映射后作为特殊位置的视觉 Token 与文本序列组合。

#### 训练阶段

常见思路：

```text
预训练视觉编码器和LLM
→ 训练连接层做图文对齐
→ 多模态指令微调
→ 偏好/安全对齐
```

不同模型可能冻结或联合训练不同组件。

#### 对“拼接即对齐”的修正

“任意模态编码后通过 Adapter 变为同维度并拼接给 Transformer”是常见抽象，但不是唯一实现。不同模态不仅要维度相同，还需要语义空间对齐、位置/时间结构、Token 数控制和多模态训练；有些模型使用 Cross-Attention 而不是简单拼接。

### 面试准备

**推荐回答**

> 典型 VLM 由视觉编码器、连接模块和 LLM 组成。视觉编码器把像素变成 Patch 特征，Projector 或 Q-Former 将其映射并压缩为 LLM 能理解的视觉 Token，再与文本 Token 通过拼接或 Cross-Attention 交互。真正的关键不只是维度对齐，还包括语义对齐、视觉位置、Token 数和多模态指令训练。

## 5. CLIP 如何对齐图像与文本？

> 面试优先级：★★★★☆｜学习难度：★★★★☆｜适用岗位：多模态、检索算法  
> 掌握要求：能解释双塔、对比学习和批内负样本

### 先理解

CLIP 使用图像编码器和文本编码器分别产生向量，通过对比学习拉近匹配图文、推远不匹配图文。它擅长跨模态检索和零样本分类，但本身不是逐 Token 生成答案的聊天模型。

图像编码器和文本编码器最初输出在不同空间，无法直接比较。CLIP 用大量图文对做对比学习，让匹配图文向量靠近、不匹配样本远离，因此可以进行零样本分类和跨模态检索，但它学习的是整体语义对齐，不等于精确 OCR 或复杂推理。

### 原理与应用

#### 双编码器

```text
image → Image Encoder → image embedding
text  → Text Encoder  → text embedding
```

一批图文对形成相似度矩阵。正确配对是正样本，批内其他组合是负样本。训练让对应图文向量接近、不对应远离。

#### 能做什么

- 图搜文、文搜图；
- Zero-shot 分类：把类别写成文本提示，与图像向量比较；
- 为 VLM 提供预训练视觉/对齐能力。

#### 不能直接等同复杂 VQA

CLIP 主要输出全局相似度表示，不能自动完成需要细粒度推理、OCR、计数和长答案生成的任务；通常需要更强视觉特征和生成式 LLM。

### 面试准备

**推荐回答**

> CLIP 使用图像和文本双塔编码器，把一批图文映射到同一向量空间，通过对比学习提高正确配对相似度、降低批内错误配对相似度。它适合跨模态检索和零样本分类，但全局对齐向量不等于能完成复杂视觉问答，后者还需要细粒度视觉 Token 与生成模型交互。

## 6. OCR 是神经网络吗？如何识别文字和版面？

> 面试优先级：★★★★★｜学习难度：★★★★☆｜适用岗位：文档智能、多模态 RAG  
> 掌握要求：能区分检测、识别、版面和结构恢复

### 先理解

现代 OCR 通常是多个神经网络与规则组成的流水线，而不是单一模型：先检测文字区域，再识别字符序列，随后用版面与表格模型恢复阅读顺序和结构。

OCR 不是简单查字典，而是先在图像中找到文字区域，再识别字符序列，并可进一步恢复段落、表格和阅读顺序。扫描件里同一个字会因字体、模糊和透视呈现不同像素，神经网络学习的是这些视觉模式到文字的映射。

### 原理与应用

#### OCR 不是一个单一网络

现代 OCR 通常是一套流水线，可包含多个神经网络和规则：

1. 图像预处理：去噪、矫正、增强；
2. 文本检测：找文字区域，输出框或多边形；
3. 方向与矫正：旋转、透视、竖排；
4. 文本识别：把区域图像转成字符序列；
5. 版面分析：标题、正文、列表、表格、图片等区域分类；
6. 阅读顺序恢复；
7. 表格结构识别：行、列、合并单元格；
8. 后处理：词典、语言模型、规则纠错。

#### 怎么“认出字”

训练数据包含文字图像和对应字符序列。识别网络学习从笔画、局部形状和上下文特征映射到字符概率序列，常见解码思想包括 CTC 或 Attention/Transformer 解码。它不是为每个字保存一张模板进行像素匹配。

#### 可以输出什么

```json
{
  "text": "第十八条 市内交通费",
  "polygon": [[120,300],[900,300],[900,350],[120,350]],
  "confidence": 0.97,
  "page": 8,
  "block_type": "heading",
  "reading_order": 12
}
```

有些系统可输出字级坐标，但字级定位、字符切分和置信度通常更难，是否支持取决于模型和引擎。

### 面试准备

**推荐回答**

> OCR 通常不是一个网络，而是检测、识别、方向、版面和结构恢复组成的系统。检测模型先定位文字区域，识别模型把区域特征解码成字符序列，版面模型再区分标题、正文、表格和图片并恢复阅读顺序。输出可包含文本、区域坐标、页码和置信度；表格还需恢复行列关系。RAG 入库时这些结构和坐标要一起保存，不能只留纯文本。

## 7. OCR 与多模态大模型有什么区别？

> 面试优先级：★★★★★｜学习难度：★★★☆☆｜适用岗位：多模态、RAG、应用  
> 掌握要求：能区分转录文字和理解视觉内容

**一句话**：OCR 的目标是尽量忠实地转录文字和位置，多模态大模型的目标是结合图像与语言进行开放理解和生成；文档系统常用 OCR 提供可定位证据，再让 VLM 处理图文关系和解释。

OCR 适合高吞吐、坐标定位、可检索和可审计的处理，例如发票字段抽取需要它的精确性和可追溯坐标。VLM 可以结合文字、物体、关系、布局和常识回答开放问题，例如“图中有哪些安全隐患”，但在密集小字、精确坐标和长表格上未必比专用 OCR 稳定，成本也更高。生产系统常把两者组合，而不是二选一。

判断一个产品“上传图片却只返回文字”属于哪种情况：可能是前端先 OCR 再把文本交给纯文本模型，可能是视觉能力有限或只优化文档 OCR 的模型，也可能是产品路由只开放了 OCR 工具。仅凭现象不能绝对断定模型架构，但如果完全无法回答非文字视觉关系，OCR 管线的可能性很高。

**面试怎么说**

> OCR 主要解决“图里写了什么以及写在哪里”，VLM 还要理解物体、空间关系和语义。生产文档系统通常先用 OCR/版面模型获得稳定文本、坐标和表格，再在需要开放理解时调用 VLM。二者互补，不是 VLM 一定取代 OCR。

**坑**

- 认定 VLM 一定取代 OCR，忽略密集小字和精确坐标场景专用 OCR 更稳；
- 仅凭“只返回文字”这一现象就断定模型架构。

## 8. 图片 URL、Base64 和模型输入是什么关系？

> 面试优先级：★★★☆☆｜学习难度：★★☆☆☆｜适用岗位：多模态应用开发  
> 掌握要求：理解传输表示与模型张量不是一回事

**一句话**：URL 和 Base64 都只是传输图片的方式，模型最终仍要把字节解码成像素并进行视觉预处理；二者都不是视觉 Token 本身。

Base64 用可打印字符表示二进制字节，方便嵌入 JSON，体积通常比原始二进制大约三分之一；它不是加密，也不是模型能直接理解的视觉向量。URL 则需要服务端再次下载，涉及网络权限和安全校验：

```text
校验协议和域名
→ 防SSRF
→ 下载字节
→ 校验大小与MIME
→ 解码图片
→ 预处理成张量
```

Base64 则先解码为字节，再走相同图片解码与预处理。并不是必须先把 URL 转成 Base64，二者只是 API 传输方式。

**面试怎么说**

> URL 和 Base64 都只是把图片交给服务的方式。URL 需要服务端安全下载，Base64 是二进制的文本编码，体积更大但便于放进 JSON。最终都要得到图片字节，解码成像素并经 Processor 变成张量，模型并不是对 Base64 字符串做视觉理解。

**坑**

- 以为 Base64 是加密，或以为它就是模型能理解的视觉向量；
- 以为必须先把 URL 转成 Base64；
- 服务端直接下载 URL 而不做 SSRF、大小和 MIME 校验。

## 9. Diffusion 为什么在 Latent 空间运行？VAE 做什么？

> 面试优先级：★★★☆☆；生成式视觉岗★★★★☆｜学习难度：★★★★☆｜适用岗位：多模态生成、CV  
> 掌握要求：能解释像素压缩、去噪和重建

**一句话**：高分辨率图片包含大量像素，直接在像素空间反复去噪非常昂贵；VAE 先把图片压缩成尺寸更小、信息更集中的 Latent 表示，Diffusion 在这个空间生成，最后再由 VAE Decoder 还原成图片。

Latent 是模型学习到的压缩表示，通常空间尺寸和/或通道组织比原始像素更紧凑，保留生成所需的高层信息，但不是简单“更粗糙的图片”。VAE 负责在像素空间和 Latent 空间之间转换：

```text
图像 → VAE Encoder → Latent
Latent → VAE Decoder → 图像
```

Diffusion 在 Latent 中反复加噪/去噪，最后由 Decoder 还原图像。元素数量大幅减少，因此每步去噪成本远低于直接在高分辨率像素空间运行；代价是压缩可能损失细节，VAE 质量也会限制最终图像。

**面试怎么说**

> Latent 是 VAE 学到的压缩特征空间，不是人工降采样。扩散模型需要进行很多次去噪迭代，如果直接处理高分辨率像素成本很高；先用 VAE Encoder 压缩，在 Latent 中去噪，再由 Decoder 还原，可以显著减少计算，同时尽量保留语义和视觉细节。代价是 VAE 压缩也可能损失细节或产生重建误差。

**坑**

- 把 Latent 理解成简单降采样后的粗糙图片；
- 忽略 VAE 压缩和重建误差会限制最终图像上限。

# 第二部分：高频场景题

> **本部分共通检查**：以下几点几乎每道多模态场景都要考虑，先在此集中说明，后面每个场景只写它专属的判断、澄清和处理。
>
> - **核心取舍**：在全局理解与局部细节、视觉 Token 数与准确率、专用模型稳定性与 VLM 开放能力之间权衡；常见做法是先检测/OCR 拿到可定位事实，再让 VLM 处理关系与解释。
> - **通用澄清**：输入是自然图片、扫描件、表格、视频还是多图序列；目标是逐字转录、目标检测、结构恢复还是开放问答；分辨率、延迟、成本、引用和人工复核要求。
> - **异常与降级**：处理模糊、旋转、裁剪丢失、版面错序、表格结构丢失、多图错位和视觉幻觉；低置信度关键字段保留原图转人工，不让模型猜。
> - **评测口径**：按文档/场景类型评估字符准确率、字段准确率、阅读顺序、表格结构、目标定位、问答忠实度和幻觉率，并记录视觉 Token、延迟、显存与人工复核率。
> - **通用追问应对**：小字/高分辨率加 ROI 与多尺度；高风险字段强化规则与人工；图片或视频增多时先检索、采样、压缩并保留 ID/时间戳。

## 场景 1：OCR 文字正确，但阅读顺序错误，怎么办？

> 面试优先级：★★★★★｜学习难度：★★★★☆｜适用岗位：文档智能、RAG  
> 掌握要求：能从区域、栏、层级和顺序图处理

**判断**：OCR 回答的是“每个文字区域写了什么”，版面分析回答的是“这些区域属于什么类型、应该按什么顺序阅读”。双栏论文、脚注和浮动文本框中，单纯按坐标从上到下排序很容易把两栏内容交叉拼接。

**先问清楚**：页面是单栏还是双栏/多栏？有无脚注、侧栏、跨栏标题和浮动图片？是否需要保留阅读顺序供引用回原文？

**怎么办**

1. 使用版面模型识别标题、正文、表格、图片和页脚；
2. 先分栏，再在栏内按 y/x 排序；
3. 跨栏标题先于各栏正文；
4. 根据字体、缩进、编号和几何关系恢复层级；
5. 图注与邻近图片绑定；
6. 保存原始坐标和顺序，支持重建；
7. 建双栏、脚注、浮动框专项评测。

**怎么说**

> OCR 识别正确不代表文档结构正确。我会把文字识别和版面分析分开，先识别栏、标题、正文、表格和图注，再基于区域关系生成阅读顺序，而不是按 y 坐标全局排序。原始坐标、块类型和顺序都保留，便于引用和修正，并对双栏、跨栏标题和脚注单独评测。

**别踩 & 追问**：别用全局 y 坐标给双栏页排序，也别丢掉原始坐标导致无法引用回原文；浮动图注要按区域邻接绑定，而不是按位置插入正文流。

## 场景 2：表格文字都对，但行列关系丢失怎么办？

> 面试优先级：★★★★★｜学习难度：★★★★☆｜适用岗位：OCR、RAG  
> 掌握要求：能设计表格检测、结构恢复和查询方式

**判断**：表格的含义不仅存在于文字里，还存在于“哪一个数值属于哪一行、哪一列”。只保存 OCR 文本会丢失表头与单元格的关系，因此必须同时恢复结构，并保留坐标以便回查原图。

**先问清楚**：是有线表格还是无线表格？有没有合并单元格、多级表头、跨页表头？下游是简单查值问答还是需要聚合计算？

**怎么办**

- 检测表格区域；
- 识别有线/无线表格的行列与单元格；
- 处理合并单元格、跨页表头和多级表头；
- 将文字框映射到单元格；
- 同时保存 HTML/Markdown、结构化 JSON 和原图；
- 简单问答可将表头补到每行；
- 大表优先入结构化数据库，用 SQL/计算工具查询；
- 结果引用回原页和单元格坐标。

**怎么说**

> 我会先检测表格区域和行列结构，再把 OCR 文字映射到单元格，处理合并单元格、多级表头和跨页表头。结果同时保存结构化 JSON、可读的 HTML/Markdown 以及原图坐标。简单表格问答可以把表头补入每行，大表和聚合计算则优先进入数据库或 DataFrame，由工具查询后再让模型解释。

**别踩 & 追问**：别把整张表按 OCR 顺序拼成一段文字，模型无法知道数值对应哪个年份和字段；大表也别整体塞进 Prompt 做聚合，交给 SQL/DataFrame 更可靠。

## 场景 3：图片文字很小，是放大、切图还是直接用 VLM？

> 面试优先级：★★★★☆｜学习难度：★★★★☆｜适用岗位：OCR、多模态应用  
> 掌握要求：能按信息密度和计算预算路由

**判断**：关键不是“放得多大”，而是原图是否真的包含足够像素。整图放大会同时放大大量无关区域，直接送 VLM 又可能消耗很多视觉 Token；通常先定位文字区域，再把局部以更高有效分辨率识别更划算。

**先问清楚**：原图分辨率是否足够，小字区域是否本身就模糊到看不清笔画？是密集文档还是自然场景？需要精确转录还是理解图文关系？

**怎么办**

1. 判断原始图是否本身有足够像素，没有信息时插值放大不会创造真实笔画；
2. 高分辨率整图会产生很多视觉 Token，应先检测文字/区域；
3. 对候选区域做裁剪、透视矫正和适度放大；
4. 密集文档优先专用 OCR，开放视觉理解再用 VLM；
5. 多尺度识别并按置信度融合；
6. 低置信度请求更清晰图片或人工复核。

**怎么说**

> 我先判断原图是否真正包含可辨识像素。单纯插值不能恢复不存在的细节。通常先做区域检测，把小字区域裁剪并矫正后以更高有效分辨率送 OCR；需要理解图文关系时再把整图和局部图一起给 VLM。这样比把超大整图直接送模型更节省视觉 Token，也更易定位置信度。

**别踩 & 追问**：别指望插值放大恢复不存在的笔画，也别无脑把超大整图直接送 VLM；小字区域用 ROI 裁剪加多尺度识别更省 Token。

## 场景 4：OCR 与 VLM 给出的文字结果冲突，相信谁？

> 面试优先级：★★★★☆｜学习难度：★★★★☆｜适用岗位：文档智能  
> 掌握要求：能用证据和置信度仲裁，而不是迷信大模型

**判断**：OCR 更擅长忠实转录字符，VLM 更擅长利用上下文推断，但推断也可能把模糊内容“补成看起来合理的字”。因此不能预设谁一定正确，应根据字段类型、图像证据和实测准确率仲裁。

**先问清楚**：冲突发生在字符级转录还是语义理解上？涉及的字段是否有格式/校验和/字典可验证？是否有带标注的测试集用来统计谁更可靠？

**怎么办**

- 保留两个结果、模型版本、区域和置信度；
- 对关键字段做格式/校验和/字典验证；
- 放大局部再次识别或使用第二 OCR 引擎；
- 高风险金额、证件号、合同条款进入人工复核；
- VLM 更适合上下文纠错，但可能幻觉补字；
- OCR 更适合逐字符转录，但可能受模糊和版面影响；
- 用标注集按字段类型统计谁更可靠。

**怎么说**

> 我不会固定相信某一个。对字符级转录先以专用 OCR 和局部图像为主，VLM 可提供上下文候选但可能幻觉。通过字段格式、词典、第二引擎和高分辨率局部做仲裁；金额、证件号等高风险字段低置信度时必须人工确认。最终依据分字段测试集的真实准确率选择策略。

**别踩 & 追问**：别预设“大模型一定对”，VLM 可能把模糊内容补成合理字；高风险字段低置信度时别自动采信任一方，必须人工确认。

## 场景 5：用户问“图片中有哪些安全隐患”，为什么 OCR 不够？

> 面试优先级：★★★★★｜学习难度：★★★☆☆｜适用岗位：多模态应用  
> 掌握要求：能区分文字抽取与视觉关系推理

**判断**：OCR 只能读取图片中的文字，而安全隐患通常来自物体、动作和空间关系。例如“未戴安全帽”即使图片中一个字也没有，仍然需要检测人、头部和安全帽之间的关系。

**先问清楚**：隐患主要来自文字标识（如“禁止烟火”），还是物体/动作/空间关系？是否需要给出可定位的告警框和置信度？

**怎么办**

OCR 只能看到“禁止烟火”“高压危险”等文字，还需要的视觉能力包括：

- 人是否佩戴安全帽；
- 电线是否裸露；
- 灭火器是否被遮挡；
- 人、设备和危险区域的空间关系；
- 烟雾、火焰、积水等非文字目标。

可组合目标检测/分割、OCR、规则和 VLM：专用模型提供可定位事实，VLM 汇总解释；高风险告警不能只靠自由生成。

**怎么说**

> OCR 只能提供文字证据，无法判断人员是否佩戴装备、设备是否遮挡或危险区域中是否有人。我会根据业务组合目标检测、分割、OCR 和规则，再让 VLM 汇总这些可定位事实并解释风险。高风险告警必须保留框、区域和置信度，并由专用模型或人工复核，不能只依赖自由文本生成。

**别踩 & 追问**：别用自由文本生成直接下高风险安全结论，告警要绑定检测框、区域和置信度，可回溯可复核。

## 场景 6：高分辨率图片视觉 Token 太多，怎么控制？

> 面试优先级：★★★★☆｜学习难度：★★★★☆｜适用岗位：VLM、推理  
> 掌握要求：能解释动态分辨率、切图和 Token 压缩

**判断**：图片通常会被切成 Patch，再映射成视觉 Token。分辨率越高，Patch 数越多，后续 Transformer 的计算和显存就越大。控制成本的核心是保留与问题有关的细节，而不是无差别降低所有区域分辨率。

**先问清楚**：问题需要全局理解还是局部细节？是密集文档还是自然场景？延迟和显存预算是多少？

**怎么办**

- 限制最大边长和总像素；
- 保留整图低分辨率，再增加重要区域高分辨率 Crop；
- OCR/检测先定位 ROI；
- 动态 Patch、分块和层级视觉特征；
- Q-Former/Pooling/Token Merge 压缩；
- 根据问题类型决定是否需要细节；
- 评测细节准确率、延迟和显存，避免过度压缩。

**怎么说**

> 我会先限制总像素，并保留一张低分辨率整图用于全局理解；再由 OCR、检测器或问题本身定位 ROI，只把关键区域以高分辨率输入。模型侧还可使用动态 Patch、Pooling 或 Token Merge 压缩。调参时同时看细节准确率、视觉 Token 数、延迟和显存，防止为了省 Token 把小字或关键目标裁掉。

**别踩 & 追问**：别无差别降低所有区域分辨率，也别为了省 Token 把小字或关键目标裁掉；细节准确率和 Token 数要一起盯。

## 场景 7：多张图片有顺序和关联，如何组织输入？

> 面试优先级：★★★☆☆｜学习难度：★★★☆☆｜适用岗位：多模态 Agent  
> 掌握要求：能保持图片 ID、顺序和文本绑定

**判断**：多图问题不仅要把图片送进去，还要让模型知道“哪张图是哪张、顺序代表什么、文本描述对应哪张图”。如果客户端排序、模板占位符和服务端实际图片顺序不一致，模型就会把证据引用错对象。

**先问清楚**：图片之间是否有时间/页码顺序？问题是否引用具体某张图？图片数量有多大，是否需要先筛选？

**怎么办**

- 为每张图分配稳定 ID 和时间/页码；
- 消息中明确“图1、图2”及问题引用；
- 图片与对应说明相邻或使用模板支持的占位 Token；
- 大量图片先检索/聚类/采样；
- 跨图比较保留统一尺度、时间和实体对应；
- 模型输出引用图片 ID 和区域；
- 防止客户端排序与服务端模板排序不一致。

**怎么说**

> 我会给每张图片分配稳定 ID，并保留页码、时间戳或拍摄顺序；在消息模板中让图片占位符与说明相邻，问题也明确引用图 ID。图片很多时先检索、聚类或抽样，跨图比较则保持实体和时间对应。输出要求引用图 ID 和区域，便于核验模型是否真的使用了正确图片。

**别踩 & 追问**：重点防客户端排序与服务端模板占位符顺序不一致，否则模型会把证据引用错对象；跨图比较要保持统一尺度和实体对应。

## 场景 8：扫描 PDF 如何进入 RAG？

> 面试优先级：★★★★★｜学习难度：★★★★★｜适用岗位：多模态 RAG、文档智能  
> 掌握要求：能给出 OCR、结构化、索引和引用全链

**判断**：扫描 PDF 的每一页本质上是一张图片，普通 PDF 文本提取器可能得到空字符串。因此要先把页面变成带文字、版面和坐标的结构化文档，再进行与普通 RAG 类似的切分和索引。

**先问清楚**：是扫描件还是数字 PDF（还是混合）？含表格、图表吗？是否要求回答引用页码和坐标？

**怎么办**

```text
PDF逐页渲染
→ 图像预处理和方向矫正
→ OCR检测/识别
→ 版面、表格和阅读顺序
→ 生成结构化文档树
→ 按条款/段落/表格切分
→ 保存页码、坐标、置信度和原图区域
→ 文本Embedding+BM25
→ 必要时图像/页面向量
→ 检索、重排、父块扩展
→ 回答并引用页码/区域
```

低置信度内容不应无条件进入高风险回答；图表问题可以在文本检索命中页面后，再把原始页面或裁剪区域交给 VLM。

**怎么说**

> 扫描 PDF 先逐页渲染并做方向、噪声等预处理，再通过 OCR 和版面模型恢复文字、表格与阅读顺序，形成带页码、坐标和置信度的文档树。之后按条款或段落切分，建立 BM25 与向量索引。检索命中后返回父块和原页区域；涉及图表时再把裁剪图交给 VLM，低置信度关键字段则转人工确认。

**别踩 & 追问**：别对扫描件用纯文本提取器（会得到空串或乱码），要先渲染成图再走 OCR；低置信度内容别无条件进入高风险回答。

## 场景 9：一分钟视频为什么不能逐帧送入 VLM？如何处理？

> 面试优先级：★★★☆☆；视频岗位★★★★☆｜学习难度：★★★★☆｜适用岗位：视频、多模态  
> 掌握要求：能处理时间采样和短事件遗漏

**判断**：相邻视频帧通常高度重复，逐帧输入会产生巨量视觉 Token，却不一定增加同等信息。真正困难的是在减少帧数的同时，不漏掉只持续很短时间的关键事件。

**先问清楚**：视频多长、帧率多少？关注的是长事件还是短事件？是否需要精确时间定位？

**怎么办**

30 FPS 的一分钟视频有 1800 帧，逐帧产生巨大视觉 Token、重复内容和推理成本，而且单帧无法表达动作时间关系。处理思路：

- 均匀采样建立全局概览；
- 镜头切分、运动/事件检测选关键帧；
- OCR/检测先筛候选时间段；
- 对候选段密集采样或使用视频编码器；
- 保存时间戳和实体轨迹；
- 短事件专项提高采样频率；
- 评测事件召回、定位误差、延迟和成本。

**怎么说**

> 一分钟 30 FPS 视频有 1800 帧，逐帧输入成本很高且相邻帧重复。我会先均匀采样获得全局概览，再结合镜头切分、运动检测、OCR 或目标检测定位候选时间段，对这些片段密集采样或使用视频编码器。结果保留时间戳和轨迹，并用短事件召回率和时间定位误差验证是否漏检。

**别踩 & 追问**：别逐帧硬送，也别用过低的均匀采样漏掉短事件；对候选时间段要局部密集采样，并用短事件召回率和定位误差验证。

## 场景 10：多模态模型产生视觉幻觉，如何降低？

> 面试优先级：★★★★☆｜学习难度：★★★★☆｜适用岗位：VLM、应用  
> 掌握要求：能从输入、模型、证据和评测治理

**判断**：视觉幻觉是模型描述了图片中不存在或无法确认的内容。它既可能来自模型根据语言先验补全，也可能是前处理压缩、裁剪或排序错误让真实证据没有进入模型，所以要先区分输入问题和模型判断问题。

**先问清楚**：幻觉是补全不存在的物体，还是错认文字/数量？前处理是否可能把目标裁掉或压糊？是否有针对性的负样例集？

**怎么办**

- 保证图片清晰、方向和裁剪正确；
- 要求回答引用图像 ID、区域或 OCR 文本；
- 专用检测/OCR 提供可验证事实；
- 不确定时允许模型说无法判断；
- 高风险结论由规则/专用模型/人工确认；
- 构造不存在物体、遮挡、计数、细粒度文字等负样例；
- 区分模型幻觉与前处理把目标裁掉；
- 监控不同分辨率、语言和场景切片。

**怎么说**

> 我会先保证图片方向、裁剪和分辨率正确，并要求关键结论引用图 ID、区域或 OCR 文本。可验证事实由检测器、OCR 或规则提供，VLM 负责综合解释；证据不足时允许明确说无法判断。高风险结论进入人工复核，并用不存在物体、遮挡、计数和小字等负样例持续评测幻觉率。

**别踩 & 追问**：别一上来就归因于模型，要先排查前处理是否把目标裁掉或压糊；负样例集（不存在物体、遮挡、计数、小字）是持续压制幻觉率的关键。

# 第三部分：一分钟总复习

## 必须能闭卷回答

1. 图片字节到张量的过程；
2. CNN 与 ViT；
3. Patch 数和视觉 Token；
4. 视觉编码器、Projector/Q-Former、LLM；
5. CLIP 对比学习；
6. OCR 检测、识别、版面、表格；
7. OCR 与 VLM 的能力边界；
8. URL/Base64 与真正模型输入；
9. VAE、Latent、Diffusion；
10. 扫描 PDF 到 RAG；
11. 表格、双栏、小字和视觉幻觉治理。

## 模块口述总结

> 图像先解码和预处理，再由 CNN/ViT 编码为视觉特征；VLM 通过 Projector、Q-Former 或 Cross-Attention 将视觉特征与 LLM 对齐并进行多模态训练。OCR 是检测、识别、版面、阅读顺序和表格结构组成的专用系统，擅长准确转录和定位；VLM 擅长开放视觉语义，两者在文档 RAG 中通常结合。生产系统必须保留文字坐标、页码、置信度和原图区域，并针对高分辨率 Token、表格结构、视频采样和幻觉做分层评测。
