# 04 SFT、微调与后训练

> 目标：理解数据怎样通过损失改变模型行为，掌握 LoRA/QLoRA、SFT、DPO、PPO、GRPO 的核心原理、适用边界和训练排错。

## 0. 模块地图

```text
预训练基座
→ SFT：学习示范行为、格式和任务
→ 偏好数据/奖励：学习“哪个回答更好”
→ DPO 或 RLHF/PPO/GRPO 等对齐
→ 离线评测、人工评测和线上灰度
```

先区分三个问题：

- 模型缺少最新事实：优先 RAG；
- 模型需要实时执行：优先工具/API；
- 模型行为、格式或领域任务模式不稳定：可能需要 SFT/LoRA；
- 模型已经会做但偏好不符合要求：考虑偏好对齐。

优先级：

- ★★★★★：训练数据、Chat Template、Label Mask、SFT、LoRA/QLoRA、评测；
- ★★★★☆：DPO、PPO/GRPO 主线、训练显存与 ZeRO/FSDP；
- ★★★☆☆：复杂 RL 变体、Agentic RL 的深入数学与分布式实现。

# 第一部分：常规八股

## 1. 什么时候选择 Prompt、RAG、工具或微调？

> 面试优先级：★★★★★｜学习难度：★★★☆☆｜适用岗位：全部  
> 掌握要求：能先诊断问题类型，而不是默认微调

**一句话**：四种方案改变的是系统的不同部分——Prompt 改当前指令，RAG 补外部知识，工具读实时状态或执行动作，微调改模型较稳定的行为模式。选型前先判断问题属于哪一类，往往比直接讨论训练方法更重要。

不要用微调去记实时知识：训练成本高、更新慢、无法精确撤销、难提供引用，而且模型可能只学到相关模式而不是可靠事实。实时状态应该交给外部系统提供。

| 问题 | 首选 |
|---|---|
| 指令表达不清、少量示例可解决 | Prompt/Few-shot |
| 私有知识、频繁更新、需要引用 | RAG |
| 余额、库存、订单等实时状态或动作 | Tool/API |
| 稳定输出格式、语气、分类或工具行为 | SFT/LoRA |
| 已会回答，但偏好、安全、风格需对齐 | DPO/RLHF 等 |

**面试怎么说**

> 我先判断问题属于提示表达、外部知识、实时操作还是模型行为。少量示例能解决的先优化 Prompt；频繁变化且需要引用的事实用 RAG；实时数据和副作用操作用工具；只有稳定行为模式、格式或任务能力需要改变时才考虑 SFT/LoRA。如果模型已经会做但偏好不符合要求，再使用 DPO 或 RLHF。实际系统常组合使用，而不是四选一。

## 2. SFT 的完整流程是什么？Label Mask 为什么重要？

> 面试优先级：★★★★★｜学习难度：★★★★☆｜适用岗位：算法、微调；应用岗掌握主线  
> 掌握要求：能从目标行为讲到 Token、Loss、训练和评测

### 先理解

SFT 用高质量示范数据训练模型按给定上下文预测目标回答。Label Mask 决定哪些 Token 计入损失：输入可以被模型读取，但通常只让助手回答位置承担监督。

SFT 不只是把问答文本交给 Trainer，而是要把消息模板、Token、标签和 Loss 对齐。模型需要读取用户问题作为条件，但通常只因助手答案预测得好坏受到训练，因此必须正确设置 Label Mask。

**为什么通常只训 Assistant**

我们的目标是让模型在看到上下文后生成理想回答，而不是奖励它复述用户输入和模板。具体是否训练其他位置取决于训练框架、任务和模板，不能机械套用。

### 原理与应用

#### 完整流程

1. 定义要改变的行为与不应改变的能力；
2. 收集正常、边界、失败、拒答和工具样例；
3. 清洗、去重、去污染、按任务和长度配比；
4. 划分 Train/Validation/Test，避免同源泄漏；
5. 使用模型 Chat Template 渲染消息；
6. Tokenize、截断、Padding/Packing；
7. 构造 Labels，通常只对 Assistant 部分计算 Loss；
8. 选择全参数或 PEFT，设置学习率、Batch、序列长度等；
9. 前向、交叉熵、反向与优化器更新；
10. 保存 Checkpoint/Adapter；
11. 与基座、Prompt 基线做离线和人工评测；
12. 灰度上线、监控并回流 Bad Case。

#### 训练目标

自回归交叉熵让模型在给定前文时提高正确下一个 Token 的概率：

```text
L = - Σ_t log p(y_t | y_<t, x)
```

#### Label Mask

```text
tokens: [system, user问题, assistant标记, 答案1, 答案2]
labels: [-100,  -100,    -100,       答案1, 答案2]
```

被设为 `-100` 的位置仍进入前向并可被后续 Token 读取，只是不计入交叉熵。

### 面试准备

**推荐回答**

> SFT 先定义目标行为，再构造覆盖正常、边界、拒答和工具结果的数据，清洗去重并做独立划分。消息必须用对应模型的 Chat Template 渲染，再 Tokenize、截断和构造 Labels。Decoder-only SFT 通常让用户和系统 Token 参与前向，但设为 -100 不计 Loss，只监督 Assistant 输出。训练后不能只看 Loss，要与基座和 Prompt 基线在固定测试集上比较任务质量、格式、拒答和通用能力。

**常见错误**

- 直接拼 `User:`/`Assistant:`，不使用模型模板；
- Assistant Token 全被 Mask，训练没有有效监督；
- 训练/测试存在近重复；
- 只看训练 Loss；
- 截断总是从尾部硬切，关键答案消失。

## 3. 全参数微调、LoRA 和 QLoRA 有什么区别？

> 面试优先级：★★★★★｜学习难度：★★★☆☆｜适用岗位：全部微调相关岗位  
> 掌握要求：能区分“训练谁”和“基座以什么精度常驻”

**一句话**：三者都可以完成 SFT，区别主要在“训练时更新多少参数”和“冻结基座以什么精度放在显存里”。全参数更新整个模型；LoRA 只训练额外的小矩阵；QLoRA 又把冻结基座压到 4-bit，从而进一步节省显存。全参数微调像整体翻修，LoRA 像在关键层增加可训练的小模块，QLoRA 又把不更新的基座压缩存放。

| 方案 | 基座参数 | 可训练参数 | 基座存储 | 主要优势 | 主要代价 |
|---|---|---|---|---|---|
| 全参数 | 更新 | 全部 | FP16/BF16 等 | 表达自由度最大 | 显存、算力和存储高 |
| LoRA | 冻结 | 低秩 A/B | 常为 FP16/BF16 | 训练参数少，Adapter 小 | 基座仍占较多显存 |
| QLoRA | 冻结 | 低秩 A/B | 常为 4-bit | 进一步降低基座常驻显存 | 量化/反量化与 Kernel 更敏感 |

要点：QLoRA 不是“所有训练计算都用 4-bit”。冻结基座以 4-bit 保存，计算时按块反量化到计算 dtype，LoRA 参数、梯度和优化器状态保持较高精度。

**面试怎么说**

> 全参数微调更新全部基座权重，能力强但训练显存和存储成本最高。LoRA 冻结基座，只训练低秩增量矩阵，减少可训练参数和优化器状态，但基座通常仍以 BF16/FP16 常驻。QLoRA 在此基础上把冻结基座以 4-bit 保存，前向时按计算精度反量化参与矩阵乘，优化器仍只更新 LoRA，因此主要进一步节省基座常驻显存，不代表全部运算都是 4-bit。

## 4. LoRA 的原理、Rank、Alpha、Target Modules 和合并是什么？

> 面试优先级：★★★★★｜学习难度：★★★★☆｜适用岗位：微调、算法；应用岗需会原理  
> 掌握要求：能写公式并解释每个超参数

### 先理解

LoRA 冻结原权重，只训练一个低秩增量矩阵来改变模型行为。Rank 控制增量容量，Alpha 控制缩放，Target Modules 决定改哪些层，合并则把增量写回基座权重。

全量更新大模型权重会产生巨大的梯度和优化器状态，而许多下游任务需要的权重变化可能集中在较低维的方向。LoRA 用两个小矩阵学习这部分增量，以更低显存改变模型行为。

**为什么低秩可能有效**

很多下游适配不需要在所有参数方向上独立变化，参数更新可能集中在较低维的有效子空间。LoRA 是一个经验上有效的结构假设，不是证明所有任务更新都严格低秩。

### 原理与应用

#### 核心公式

冻结原权重 `W0 ∈ R^(d_out×d_in)`，不直接学习完整更新 `ΔW`，而是：

```text
ΔW = B A

A ∈ R^(r×d_in)
B ∈ R^(d_out×r)

y = W0x + (α/r)BAx
```

当 `r` 远小于输入输出维度时，可训练参数从 `d_out×d_in` 降为 `r(d_in+d_out)`。

#### Rank `r`

- 小：参数少、显存低，但表达能力可能不足；
- 大：自由度增加，也更易过拟合并增加资源；
- 不是越大越好，需按任务、数据和模块做实验。

#### Alpha

常用 `α/r` 缩放 LoRA 分支。Alpha 与 Rank、初始化、学习率共同影响更新强度，不能单独机械解释。

#### Target Modules

常见目标包括 Attention 的 Q/K/V/O 投影和 FFN 投影。只训 Q/V 成本较低；覆盖更多模块可能提升复杂任务适配能力，也增加参数和过拟合风险。具体名称依模型实现，不能假定所有模型模块名相同。

#### 初始化与合并

常让一侧初始化为零，使训练开始时 `ΔW≈0`，模型先保持基座行为。推理时可以：

- 动态加载 Adapter，便于一基座多任务；
- 合并 `W = W0 + ΔW`，减少额外分支，但失去轻松切换和独立回滚。

### 面试准备

**推荐回答**

> LoRA 假设下游权重更新可以用低秩矩阵 BA 近似。它冻结原权重 W0，只训练 A 和 B，前向为 W0x 加 α/r 乘 BAx。Rank 控制低秩子空间容量，Alpha 控制缩放，Target Modules 决定哪些线性层允许适配。Rank 和覆盖层数不是越大越好，要通过目标任务与通用能力评测选择。部署时可以动态加载小 Adapter，也可合并到基座减少额外分支。

**常见追问**

- LoRA 为什么省显存？主要少了大规模参数梯度和优化器状态；激活显存不会自动消失。
- 合并后还是低秩模型吗？权重已经相加为普通矩阵，推理不必保留低秩分支。
- 多个 Adapter 能否组合？可以，但合并和冲突需要评测，不能假设线性叠加总有效。

## 5. QLoRA 中 NF4、Double Quantization 和计算精度是什么？

> 面试优先级：★★★★☆｜学习难度：★★★★☆｜适用岗位：微调、训练系统  
> 掌握要求：能说明量化对象和为什么 QLoRA 不一定更快

### 先理解

QLoRA 把冻结基座以 4-bit 常驻显存，同时让 LoRA 和实际矩阵计算保持较高精度。NF4 是适配权重分布的 4-bit 格式，Double Quantization 进一步压缩量化尺度。

普通 LoRA 仍需让冻结基座以 FP16/BF16 常驻显存，较大模型在消费级显卡上依然放不下。QLoRA 用 4-bit 保存基座来降低常驻显存，但矩阵计算和可训练 Adapter 仍使用较高精度。

**为什么不一定更快**

QLoRA 的主要目标是省显存。反量化、Kernel 支持、较小 Batch 和硬件特性可能让训练速度不升反降。速度必须实测。

### 原理与应用

#### NF4

NF4 是为近似正态分布权重设计的 4-bit 数据类型思想，用有限量化值更好覆盖常见权重分布。具体实现由量化库决定。

#### Double Quantization

权重量化通常还要保存每个块的 Scale；Double Quantization 进一步压缩这些量化常数，继续减少平均存储。

#### 前向与反向

```text
4-bit冻结权重
→ 按块反量化到BF16/FP16等计算dtype
→ 与输入做矩阵乘
→ 梯度通过该路径传播
→ 只保存并更新LoRA参数的梯度和优化器状态
```

### 面试准备

**推荐回答**

> QLoRA 将冻结基座按块量化到 4-bit，常使用 NF4 表示权重，并可通过 Double Quantization 继续压缩 Scale。计算时权重会反量化到 BF16/FP16 等计算精度，反向可以穿过这条路径，但优化器只更新 LoRA。它主要减少基座常驻显存，不保证训练更快，速度取决于反量化和 Kernel 支持。

## 6. RLHF、Reward Model 和 PPO 的完整关系是什么？

> 面试优先级：后训练岗★★★★★；应用岗★★★☆☆｜学习难度：★★★★★｜适用岗位：后训练、对齐算法  
> 掌握要求：能说明 Actor、Critic、Reference、Reward 的职责

### 先理解

典型 RLHF 先用 SFT 得到初始策略，再用人类偏好训练 Reward Model，最后由 PPO 在奖励与 KL 约束下更新策略。三步分别解决示范学习、偏好建模和策略优化。

SFT 能模仿示范答案，却不一定能在多种可行回答中持续偏向人类更喜欢的结果。RLHF 用 Reward Model 提供偏好信号，PPO 再在提升奖励的同时限制策略不要一次偏离参考模型过远。

**PPO 为什么需要 Importance Ratio**

采样来自旧策略，更新的是新策略。概率比：

```text
r_t(θ) = π_θ(a_t|s_t) / π_old(a_t|s_t)
```

衡量新旧策略对已采样动作的概率变化。

### 原理与应用

#### 典型 RLHF 流程

```text
SFT模型
→ 对同一Prompt采样多个回答
→ 人工或规则标注偏好
→ 训练Reward Model
→ Actor生成回答
→ Reward Model评分
→ PPO更新Actor，并用KL约束远离Reference
```

#### 四类模型/组件

- **Actor/Policy**：要优化的生成模型；
- **Critic/Value**：估计状态/Token 的期望回报，帮助计算 Advantage；
- **Reward Model**：对完整回答或轨迹评分；
- **Reference Model**：冻结的参考策略，用 KL 防止策略漂移过远。

#### Clip

```text
L_clip = E[min(r_t A_t, clip(r_t,1-ε,1+ε)A_t)]
```

它限制单次更新幅度。`A_t>0` 时希望提高动作概率，`A_t<0` 时希望降低，但 Clip 防止变化过猛。

#### GAE

GAE 用多步 TD Error 的加权组合估计 Advantage。`λ` 较小通常偏差更大、方差更小；较大更接近蒙特卡洛回报，偏差小但方差可能更高。

### 面试准备

**推荐回答**

> RLHF 通常先用偏好对训练 Reward Model，再让 Actor 生成回答，由 Reward Model 给奖励，PPO 根据 Advantage 更新策略。Critic 估计价值以降低方差，Reference Model 通过 KL 约束模型不要偏离原策略过远。PPO 使用新旧策略概率比修正采样分布，并通过 Clip 限制单次更新。它能够优化不可微的序列奖励，但系统复杂、资源高且容易受奖励偏差影响。

## 7. DPO 的原理是什么？与 PPO 有什么区别？

> 面试优先级：后训练岗★★★★★；应用岗★★★☆☆｜学习难度：★★★★★｜适用岗位：后训练、微调算法  
> 掌握要求：能解释 chosen/rejected/reference 和隐式奖励

### 先理解

DPO 直接使用 chosen/rejected 偏好对，让模型相对参考模型提高被偏好回答的概率，不需要单独训练 Reward Model 和在线 Rollout；PPO 则通过奖励驱动策略更新。

PPO 需要奖励模型、价值估计和在线采样，训练链路复杂。DPO 直接使用同一 Prompt 下的偏好回答对，提高 chosen 相对 rejected 的概率，为偏好对齐提供更简单的训练方式。

**直觉**

比较的不是 chosen 自身概率是否大，而是：

```text
新策略相对参考策略，对chosen增加了多少偏好
减去
新策略相对参考策略，对rejected增加了多少偏好
```

### 原理与应用

#### 数据

每条样本：

```text
prompt x
chosen y_w
rejected y_l
```

DPO 直接让策略相对 Reference 更偏向 chosen、远离 rejected。简化目标可写为：

```text
-log σ(β[(logπθ(yw|x)-logπref(yw|x))
        -(logπθ(yl|x)-logπref(yl|x))])
```

#### 与 PPO

| 维度 | DPO | PPO/RLHF |
|---|---|---|
| 显式 Reward Model | 通常不单独训练 | 通常需要 |
| 在线采样 | 可用离线偏好对训练 | 常需策略采样 |
| Critic | 不需要 | 通常需要 |
| 系统复杂度 | 较低 | 较高 |
| 探索新行为 | 受离线数据限制 | 可与环境交互采样 |

### 面试准备

**推荐回答**

> DPO 使用 prompt、chosen、rejected 偏好对，直接优化策略相对 Reference 对 chosen 与 rejected 的对数概率差。它把 KL 正则化偏好优化转成分类式目标，因此不需要显式 Reward Model 和 PPO 的在线强化学习循环，训练更简单稳定。但它受离线偏好数据覆盖限制，对需要环境探索和长期信用分配的任务未必足够。

**常见错误**

- 说 DPO 完全没有 Reference；
- 只提高 chosen 概率，不考虑 rejected 与参考策略；
- 认为 DPO 任何情况下都优于 PPO；
- 忽略回答长度和数据偏差。

## 8. GRPO 与 PPO 有什么区别？

> 面试优先级：后训练岗★★★★★；应用岗★★☆☆☆｜学习难度：★★★★★｜适用岗位：后训练、推理强化学习  
> 掌握要求：能解释同 Prompt 分组采样和组内相对 Advantage

### 先理解

GRPO 对同一问题采样一组回答，用组内相对奖励估计优势，通常不依赖单独的 Value Model；PPO 常使用 Critic 估值。两者都属于强化学习式策略优化。

偏好优化不只看奖励函数，还要解决“这次回答比基线好多少”以及更新不能过猛。PPO 借助价值模型估计 Advantage，GRPO 更多依赖同一问题下多条回答的组内相对奖励；二者差异会直接影响显存、采样量和训练稳定性。

### 原理与应用

#### 核心思路

对同一个 Prompt 采样一组回答，分别得到奖励，再用组内均值/标准差形成相对 Advantage：

```text
A_i ≈ (r_i - mean(r_group)) / (std(r_group)+ε)
```

相较典型 PPO，GRPO 可不依赖独立 Critic，而用同组样本作为相对基线，降低 Value Model 资源。

#### 关键问题

- 组内回答必须有差异，否则标准化信号弱；
- Reward 设计决定优化方向；
- 序列奖励如何分配到 Token 会影响训练；
- 仍需控制策略变化和采样/训练分布；
- 具体 GRPO 变体的 Clip、KL 与 Loss 不同，回答时说明实现版本。

### 面试准备

**推荐回答**

> GRPO 对同一个 Prompt 采样多个回答，用组内奖励的相对高低构造 Advantage，通常省去独立 Critic；PPO 则常依赖 Value Model 和 GAE 估计 Advantage。GRPO 适合可对多条候选打分的推理任务，但效果高度依赖组内多样性、奖励质量和序列到 Token 的信用分配。它不是简单的“PPO 去掉 Critic”，具体 Clip 和 KL 仍要看实现。

## 9. FSDP 与 DeepSpeed ZeRO-1/2/3 如何节省显存？

> 面试优先级：后训练/Infra岗★★★★☆｜学习难度：★★★★★｜适用岗位：训练系统、微调  
> 掌握要求：能从参数、梯度、优化器状态三个对象解释

### 先理解

大模型训练显存不只存权重，还要存梯度和优化器状态，单卡往往在计算开始前就放不下。FSDP 和 ZeRO 的共同思路是把这些状态分片到多张卡上，需要使用时再通信聚合；分片越彻底，显存越省，但通信和实现复杂度也越高。

### 原理与应用

#### 训练显存主要组成

```text
参数
梯度
优化器状态
激活
临时Buffer与通信Buffer
```

#### ZeRO

- Stage 1：分片优化器状态；
- Stage 2：再分片梯度；
- Stage 3：再分片参数，计算时按需聚合。

Stage 越高单卡常驻越少，但通信、调度和实现复杂度增加。Activation 需要 Checkpointing 等手段另行处理。

#### FSDP

FSDP 将参数、梯度和优化器状态分片，前向/反向按需 All-Gather 参数并 Reduce-Scatter 梯度。它与 ZeRO-3 思想相近，但 API、封装、调度和生态实现不同。

### 面试准备

**推荐回答**

> 训练显存不只有权重，还包括梯度、优化器状态和激活。ZeRO-1 分片优化器状态，Stage 2 再分片梯度，Stage 3 再分片参数；FSDP 也通过参数、梯度和优化器状态分片，在计算前按需聚合。更高分片降低单卡常驻显存，但增加通信和调度开销，激活显存仍要通过序列长度、Micro Batch、Activation Checkpointing 等方式控制。

# 第二部分：高频场景题

> **本部分共通检查**：方案通常需要在能力变化幅度、显存与算力、数据需求、训练稳定性、通用能力保持和部署复杂度之间取舍。先用 Prompt/RAG/LoRA 等低成本基线验证是否真的需要更重训练。异常与降级要考虑 OOM、NaN、错误 Mask、模板不一致、数据污染、过拟合、复读和能力退化；保留 Checkpoint 与 Adapter 回滚，异常数据或数值问题未定位前停止扩大训练。评测要固定推理模板与参数，对比基座、SFT/Adapter 和不同 Checkpoint，按目标能力、通用能力、安全、长度和成本切片并检查数据泄漏。条件变化时：数据更少优先参数高效方法；目标变成实时知识转向 RAG/工具；风险更高加强人工标注、独立留出和灰度；基座升级后重新验证或重训 Adapter。
>
> **共通澄清（每题默认先问，不再重复）**：目标是补事实、改行为/格式还是对齐偏好；数据量、质量、来源、授权和测试隔离是否可靠；基座、显存、训练时间、上线格式和可回滚要求是什么。下面每题只列该场景专属的澄清问题。

## 场景 1：只有几千条领域数据，应该用 RAG、LoRA 还是全量微调？

> 面试优先级：★★★★★｜学习难度：★★★★☆｜适用岗位：全部  
> 掌握要求：能按目标、质量、更新和风险选择

**判断**：数据条数不能直接决定方案。几千条“产品事实”与几千条“标准客服回答”训练目标不同：前者更需要可更新和可引用，适合 RAG；后者是在教模型稳定行为，才更适合 LoRA。

**先问清楚**

- 这批数据教的是“事实知识”还是“行为/格式/语气”？
- 是否需要引用来源、是否会频繁更新？
- 是否已经试过 Prompt/Few-shot 基线，效果差在哪？

**怎么分析**

先问数据教的是什么：

- 频繁变化的事实：RAG；
- 稳定格式/流程/语气：LoRA/SFT；
- 少量分类样例：先 Prompt/Few-shot 和小模型基线；
- 需要大范围改变模型能力：几千条通常不足以支撑全量微调；
- 高风险领域：数据质量和独立评测比数量更重要。

**怎么说**

> 我不会只按数据条数决定。先看数据是知识还是行为：频繁变化、需要引用的领域事实用 RAG；稳定格式、术语和工具行为可以 LoRA；如果 Few-shot 已达到目标就不训练。几千条高质量数据通常更适合 LoRA 而不是全量微调，但仍要划分独立测试集，与基座、Prompt 和 RAG 基线比较，并检查通用能力和灾难性遗忘。

**别踩 & 追问**

- 错误答案：“数据越多越该全量微调”“先训了再说”。
- 若目标其实是补实时事实，无论多少条都优先 RAG，微调解决不了更新与引用问题。

## 场景 2：训练 Loss 下降，但真实对话没有提升，怎么排查？

> 面试优先级：★★★★★｜学习难度：★★★★☆｜适用岗位：微调、算法  
> 掌握要求：能从数据、模板、Mask、评测和生成参数排查

**判断**：训练 Loss 衡量的是训练 Token 的预测误差，不直接等于用户任务成功率。模型可能只学会了固定格式或高频词，也可能训练有效但推理时模板、Adapter 或生成参数用错，因此要把“训练是否学到”和“上线是否正确使用”分开检查。

**先问清楚**

- 训练集和真实对话是否同分布，测试是否覆盖目标能力？
- 推理时的 Chat Template、Adapter/Checkpoint、生成参数是否与训练一致？
- 有没有金标准评测集，还是只凭主观感觉判断“没提升”？

**怎么排查**

1. Train 与 Test 是否同分布，测试是否覆盖目标能力；
2. 数据是否近重复、泄漏或答案质量低；
3. Chat Template 是否与推理一致；
4. Label Mask 是否只监督了正确位置；
5. 截断后答案是否消失；
6. LoRA 是否挂到正确模块，参数是否真的更新；
7. 推理是否加载正确 Adapter/Checkpoint；
8. 生成参数是否与基线一致；
9. Loss 改善是否只来自容易 Token 或格式；
10. 使用基座、金标准数据和小样本人工评审做对照。

**怎么说**

> Loss 只说明训练目标上的 Token 预测变好，不等于真实任务变好。我会先检查数据与独立测试是否对齐、是否泄漏；再核对 Chat Template、Label Mask 和截断；确认 LoRA 参数有梯度且推理加载正确 Adapter。之后固定生成参数比较基座、最佳 Checkpoint 和金标准样例，并按任务类型切片。如果只是格式 Token 变好，平均 Loss 下降也可能掩盖核心能力没有提升。

**别踩 & 追问**

- 错误答案：“Loss 降了就是训练成功”“再多训几轮就好”。
- 若推理侧模板或 Adapter 没加载对，训练本身可能是好的，别急着重训。

## 场景 3：微调后通用能力下降，怎么办？

> 面试优先级：★★★★☆｜学习难度：★★★★☆｜适用岗位：微调、算法  
> 掌握要求：能讨论数据配比、更新强度和回归集

**判断**：微调会把模型概率分布推向领域数据。如果数据过窄、重复或训练强度过大，模型会过度适应局部模式，原来的通用问答、推理和语言能力就可能退化，这通常称为灾难性遗忘或能力偏移。

**先问清楚**

- 下降的是哪类能力（通用问答、推理、格式、语言）？
- 训练数据是否过窄或高度重复？
- 用了多大的学习率、Epoch、Rank 和覆盖模块？

**怎么办**

先定位原因：

- 领域数据过窄或重复；
- 学习率、Epoch、Rank 或 Target Modules 过强；
- 训练只奖励单一风格；
- 模板不一致；
- Checkpoint 选择只看领域 Loss；
- 评测切片不足。

再对应处理：

- 混入高质量通用或保持数据；
- 降低学习率、Epoch、Rank 或覆盖范围；
- Early Stopping；
- 多任务配比与采样；
- 领域指标和通用回归共同作为门禁；
- 保留可切换 Adapter，不急于不可逆合并。

**怎么说**

> 我会先用领域集和通用回归集确认下降发生在哪些能力，再检查数据是否过窄、训练轮数和学习率是否过大。常见处理是混入高质量保持数据、降低更新强度并做 Early Stopping，同时用领域与通用指标共同选 Checkpoint。使用 LoRA 时保留可切换 Adapter，也便于快速回退和做对照。

**别踩 & 追问**

- 错误答案：“通用能力下降是正常代价，忍一下”。
- 只用领域 Loss 选 Checkpoint 会系统性放大遗忘，通用回归集必须进门禁。

## 场景 4：SFT 后模型复读、回答过长或不会停止，怎么办？

> 面试优先级：★★★★☆｜学习难度：★★★★☆｜适用岗位：微调、部署  
> 掌握要求：能区分数据、EOS、模板和推理参数

**判断**：模型停止生成并不是“自己觉得说完了”，而是学会在合适位置输出 EOS，或者被服务端停止条件截断。如果训练样本缺少结束边界、模板不一致或数据本身大量复读，模型就可能不知道何时结束。

**先问清楚**

- 是所有请求都这样，还是只有 SFT/LoRA 之后的模型？
- 是整段重复、逐字重复，还是重复到不出 EOS？
- 流式返回还是一次性返回，换客户端还复现吗？

**怎么排查**

1. 训练样本是否正确包含 EOS/结束边界；
2. 推理 Template 与训练是否一致；
3. 数据中是否大量冗长、重复、无结束回答；
4. Packing 是否串样本且边界处理错误；
5. Label 是否错位；
6. 学习率或 Epoch 是否过高；
7. 推理的停止 Token、最大长度和 repetition 参数；
8. 与基座和不同 Checkpoint 对比。

**怎么说**

> 我会先确认是模型复读还是流式客户端重复拼接。模型侧核对训练与推理的 Chat Template、EOS 和停止 Token，检查 Packing、Label 错位以及数据中是否存在大量冗长重复答案，再比较基座和不同 Checkpoint。生成参数可以临时缓解，但如果根因在训练边界和数据，仍应重新清洗或训练。

**别踩 & 追问**

- 错误答案：“调大 repetition penalty 就行”，只压症状不改数据。
- 若训练样本本身缺 EOS 或用 Packing 串了样本，必须回到数据和边界处理，而不是靠推理参数硬修。

## 场景 5：合成数据很多，但可能有幻觉和重复，怎么治理？

> 面试优先级：★★★★☆｜学习难度：★★★★☆｜适用岗位：训练数据、微调  
> 掌握要求：能设计生成、过滤、去重和人工抽检闭环

**判断**：合成数据会把生成模型的错误一起放大。数量越多不一定越好：大量近重复样本会改变训练分布，带来源的少量高质量数据通常比无法验证的百万条文本更有价值。

**先问清楚**

- 合成数据是否有可信来源（事实、工具结果、文档）？
- 是否已做过文本和语义去重？
- 是否可能混入测试题或其近重复？

**怎么办**

- 从可信事实、工具结果或文档生成，并保留来源；
- 规则检查格式、长度、标签和可验证字段；
- Exact/MinHash/Embedding 等多级去重；
- 使用独立模型或规则核验，不只让生成模型自评；
- 按难度、主题、长度和答案类型控制分布；
- 人工分层抽样，重点检查高风险和低置信度；
- 小规模训练做数据消融，确认合成数据真实增益；
- 防止测试题或近重复进入训练。

**怎么说**

> 合成数据的价值在覆盖，不在数量。我会从有来源的事实或工具轨迹生成，保留证据；用规则、独立模型和人工抽样做质量过滤，再做文本和语义去重，控制任务与长度分布。最后通过只加这批数据的消融实验验证增益，并检查通用能力和测试污染，不能因为生成了百万条就直接训练。

**别踩 & 追问**

- 错误答案：“让模型自己给自己打分过滤就够了”。
- 生成模型自评会放大同源偏差，核验至少要引入独立模型或规则。

## 场景 6：DPO 后回答变长、拒答增加，怎么处理？

> 面试优先级：后训练岗★★★★☆｜学习难度：★★★★★｜适用岗位：偏好对齐  
> 掌握要求：能分析偏好数据和长度偏差

**判断**：DPO 学的是偏好对之间的相对关系。如果标注数据中“更长的回答更常被选中”或“拒答更常被判安全”，模型就会把长度、拒答当成获得偏好的捷径，即使这些并不是我们真正想优化的目标。

**先问清楚**

- chosen 和 rejected 的长度是否高度相关？
- 安全/拒答类样本占比多少？
- β、学习率和训练强度设了多少？

**怎么办**

先定位原因：

- 标注者系统性偏好更长回答；
- chosen/rejected 长度高度相关；
- 安全数据配比过高；
- β、学习率或训练强度不合适；
- 训练分布与线上不同；
- 只看偏好准确率，没有长度和有用性切片。

再对应处理：

- 构造长度匹配的偏好对；
- 分离正确性、风格、安全和长度 Rubric；
- 调整数据配比与采样；
- 监控回答长度、拒答率、任务成功和 KL；
- 与 SFT、Reference 做逐切片对照；
- 对业务可接受长度加入规则或奖励，但避免机械截短。

**怎么说**

> 我会先分析 chosen/rejected 的长度、安全类型与任务分布，确认模型是否学到了数据偏差。随后构造长度匹配的偏好对，把正确性、有用性、安全和风格拆成独立 Rubric，调整数据配比和训练强度。评测不能只看偏好胜率，还要同时看回答长度、拒答率、任务成功率和相对参考模型的 KL。

**别踩 & 追问**

- 错误答案：“变长说明回答更详细，是好事”。
- 只看偏好胜率会掩盖长度和拒答偏差，长度和有用性切片必须一起看。

## 场景 7：Reward Model 被模型钻漏洞怎么办？

> 面试优先级：后训练岗★★★★★｜学习难度：★★★★★｜适用岗位：RLHF、Agent RL  
> 掌握要求：理解 Reward Hacking 和分布外利用

**判断**：策略模型会努力最大化“奖励模型给出的分数”，而不是自动理解设计者的真实意图。只要奖励存在可利用的偏差，训练就可能找到高分但无用甚至危险的行为，这就是 Reward Hacking。例如 Reward 偏好关键词“因此答案是”，策略可能大量输出该格式却没有正确推理；代码奖励只看测试通过数，模型可能利用测试漏洞。

**先问清楚**

- 奖励是单一指标还是多维、带硬约束？
- 是否有隐藏测试或对抗样例？
- 高奖励轨迹是否被人工抽查过？

**怎么办**

- 多维奖励和硬规则结合；
- 隐藏测试、环境随机化和对抗样例；
- Reward Ensemble 或不确定性；
- 人工审查高奖励异常轨迹；
- 监控奖励上升但真实任务不升的背离；
- 周期性用新策略数据更新奖励模型；
- 限制 KL 和单次策略更新；
- 高风险目标以真实环境约束为准。

**怎么说**

> Reward Hacking 的根因是代理指标与真实目标不完全一致。我会使用多维奖励、硬约束、隐藏测试和环境随机化，抽查高奖励异常轨迹，并监控奖励上升但真实任务成功率不升的背离。策略更新需要 KL 或步长约束，奖励模型也要用新策略产生的困难样本持续更新；高风险动作最终由真实环境规则限制。

**别踩 & 追问**

- 错误答案：“奖励一直在涨，说明训练很成功”。
- 奖励涨而真实任务不涨恰恰是 Hacking 的典型信号，要盯住这个背离而不是奖励曲线本身。

## 场景 8：训练 OOM 或突然 NaN，怎么排查？

> 面试优先级：★★★★☆｜学习难度：★★★★☆｜适用岗位：微调、训练系统  
> 掌握要求：能区分显存和数值问题

**判断**：OOM 是容量不足，NaN 是数值失稳，两者排查方向不同。前者重点看模型状态、激活和 Batch，后者重点看数据异常、精度、学习率、梯度和算子稳定性。

**先问清楚**

- 现象是 OOM 还是 NaN，还是先 NaN 再崩？
- 显存峰值发生在前向、反向、评测还是保存阶段？
- NaN 出现在第几个 step，是否可稳定复现？

**怎么排查**

OOM：

- 记录最长序列和真实 Token，而不只看样本数；
- 降低 Micro Batch/序列长度，使用梯度累积；
- 开 Activation Checkpointing；
- 使用 LoRA/QLoRA、ZeRO/FSDP；
- 检查 Padding/Packing、评测阶段和保存峰值；
- 清理无用张量和错误保留的计算图。

NaN：

- 学习率过高、Warmup 不足；
- FP16 上溢，尝试 BF16/Grad Scaling；
- 异常样本、空 Label、全 `-100`；
- 除零、对数非法、Reward 极端；
- 梯度爆炸，检查 Grad Norm 和裁剪；
- 定位第一个出现非有限值的层和 Batch。

**怎么说**

> OOM 我先看峰值发生在前向、反向、评测还是保存，并检查最长序列、Micro Batch、激活和优化器状态；按顺序调整 Batch、梯度累积、Checkpointing、QLoRA 或分片。NaN 则检查首个异常 Step、输入 Batch、有效 Label、学习率和 Grad Norm，并区分 FP16 数值上溢、非法 Loss 和异常奖励。两类问题不能只用“清缓存”处理。

**别踩 & 追问**

- 错误答案：“OOM 就无脑清缓存，NaN 就调小学习率”。
- 全 `-100` 的 Label 或空样本也会造成 NaN，别只盯着学习率。

## 场景 9：基座模型升级后，旧 LoRA 能直接用吗？

> 面试优先级：★★★☆☆｜学习难度：★★★☆☆｜适用岗位：微调平台、应用  
> 掌握要求：能说明架构、Tokenizer 和权重基线依赖

**判断**：LoRA 不是独立完整模型，而是叠加在特定基座线性层上的增量。即使新旧模型都叫 7B，只要层形状、模块名称、Tokenizer 或原始权重发生变化，旧增量的含义就可能不再成立。

**先问清楚**

- 新旧基座的架构、层形状、Target Module 名称是否一致？
- Tokenizer 和 Chat Template 是否变化？
- 基座权重版本是否变化（含继续预训练/对齐版本）？

**怎么判断**

不能默认兼容。LoRA 学的是相对某个基座权重和模块结构的增量。需要检查：

- 架构与 Target Module 名称/形状；
- 隐藏维度、层数和模块数量；
- Tokenizer 与 Chat Template；
- 基座权重版本；
- Adapter 配置与量化方式；
- 在旧/新基座上的完整回归。

即使形状能加载，行为也可能退化。稳妥做法通常是基于新基座重训或蒸馏迁移，并做灰度对比。

**怎么说**

> 不能默认直接使用。首先要检查目标模块名称与形状是否兼容，以及 Tokenizer、Chat Template 和基座权重版本是否一致。即使技术上能加载，LoRA 学到的是相对旧基座的增量，在新基座上行为也可能失真。生产迁移通常基于新基座重新训练或蒸馏，并用旧组合、新组合和新基座做完整回归与灰度。

**别踩 & 追问**

- 错误答案：“形状能加载就说明能用”。
- 能加载不等于行为对，必须在新基座上跑完整回归，而不是只看是否报错。

# 第三部分：一分钟总复习

## 必须能闭卷回答

1. Prompt、RAG、工具、微调的选择；
2. SFT 数据到 Loss 的完整流程；
3. Attention Mask 与 Label Mask；
4. 全参、LoRA、QLoRA；
5. LoRA 公式、Rank、Alpha、Target 和合并；
6. QLoRA 量化对象和计算精度；
7. RLHF/PPO 的组件和 Clip；
8. DPO 的偏好对目标；
9. GRPO 的组内相对 Advantage；
10. ZeRO/FSDP 与训练显存；
11. Loss 下降但任务不升的排查；
12. 灾难性遗忘、Reward Hacking 和数据治理。

## 模块口述总结

> 微调的核心不是把数据交给 Trainer，而是先定义目标行为、构造和治理数据，再确保 Chat Template、Tokenization、Label Mask 和训练目标一致。LoRA 冻结基座并学习低秩增量，QLoRA 进一步把冻结基座 4-bit 常驻，但计算和 Adapter 仍使用较高精度。SFT 学示范行为，DPO 直接利用偏好对，PPO/GRPO 适合用奖励优化采样行为但系统更复杂。训练效果不能只看 Loss，必须与基座和 Prompt/RAG 基线比较，并检查通用能力、长度、拒答、安全和真实业务指标。
