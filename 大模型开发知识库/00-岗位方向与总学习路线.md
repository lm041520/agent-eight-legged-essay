# 大模型实习岗位方向与总学习路线

> 适用方向：Agent 应用开发、RAG/知识库、大模型应用后端、Agent 算法、微调与后训练、模型部署/AI Infra、多模态大模型。
>
> 文档目标：帮助你根据岗位选择学习重点，而不是九个模块平均用力。每个模块都要求逐步达到“能解释、能编码、能排错、能结合项目讲”的程度。

---

## 阅读前先说明：这套文档应该怎样写、怎样学

这套知识库不是“术语词典”，也不应该只是面试前翻看的提纲。第一次接触某个技术时，如果只看到下面这样的表述：

```text
Prefill负责处理Prompt，Decode负责逐Token生成，KV Cache用于缓存历史KV。
```

读者虽然认识每个字，却仍然不知道：

- 为什么一次请求要分成两个阶段？
- “处理Prompt”具体执行了什么？
- K和V究竟是什么数据？
- 为什么Prefill可以并行，Decode却具有串行依赖？
- 这些概念会怎样影响显存、延迟和并发？

因此，重新整理后的每个模块采用两层结构。

### 第一层：零基础慢讲

先使用一个具体场景建立画面，再逐步引出术语。例如讲推理部署时，会从“用户发送一句问题后，服务器内部依次发生什么”开始；讲RAG时，会从“怎样让模型回答员工报销手册中的规定”开始。

这一层不要求读者预先理解英文缩写，出现新术语时必须回答：

1. 它是什么；
2. 为什么需要它；
3. 没有它会出现什么问题；
4. 它在完整流程的什么位置；
5. 用一组具体数据或代码怎样演示。

### 第二层：工程深入与复习

建立直觉以后，再进入参数、框架、优化方法、故障排查和面试表达。原有的表格、要点和复习卡仍然保留，但它们的角色是“学完后的压缩总结”，不再承担第一次教学的任务。

### 每个重要知识点的统一写法

后续学习时，可以用下面八项检查内容是否真正讲清楚：

| 部分 | 必须回答的问题 |
|---|---|
| 问题背景 | 现实项目中遇到了什么问题？ |
| 一句话定义 | 这个技术最简单的定义是什么？ |
| 直觉类比 | 能否用日常过程建立第一印象？ |
| 逐步流程 | 输入、处理步骤和输出分别是什么？ |
| 具体例子 | 能否用一句请求、几条数据或一段代码走一遍？ |
| 原理深入 | 为什么这样设计，内部机制是什么？ |
| 工程权衡 | 它对质量、延迟、显存、成本有什么影响？ |
| 排错与面试 | 常见误区是什么，怎样用自己的话解释？ |

### 判断自己是否真的学会

以“KV Cache”为例，以下四种状态并不相同：

```text
听过：知道它和大模型推理有关
看懂：能理解一篇解释中的流程图
会用：能启动推理服务并观察缓存和显存变化
掌握：能解释缓存内容、估算开销、分析OOM并给出优化方案
```

求职准备的目标不是把所有P2内容都背下来，而是把目标岗位的P0知识点至少推进到“会用”，其中几个核心知识点达到“掌握”。

## 一、先看结论：不同岗位重点完全不同

这套知识库包含九个学习模块：

1. `01-Python与工程能力.md`
2. `02-Agent核心机制.md`
3. `03-评测与优化.md`
4. `04-RAG.md`
5. `05-工程化落地.md`
6. `06-深度学习基础.md`
7. `07-微调与后训练.md`
8. `08-推理部署.md`
9. `09-多模态与CV.md`

选择学习重点时使用三级深度：

- **A级：深入掌握。** 能讲原理、写核心代码、定位常见故障，并能用项目案例回答面试问题。
- **B级：实践掌握。** 理解核心机制，完成过最小实验，知道常见参数和局限。
- **C级：方向了解。** 知道解决什么问题、何时使用、与相邻技术的区别。

这套A/B/C用于“不同岗位应该把某个模块学多深”；每个模块内部再使用知识点优先级：**P0=必须掌握，P1=需要理解并实践，P2=根据岗位方向选学**。二者不是重复：例如Agent应用岗对模块06整体为B级，但其中Transformer主干仍是该模块内的P0。

## 二、九个模块分别解决什么问题

### 模块01：Python与工程能力

回答“如何把想法写成稳定、可维护的程序”。重点包括：

- Python 对象、函数、面向对象、类型标注、Pydantic；
- 线程、进程、协程、GIL、异步并发；
- 数据结构与算法；
- HTTP、REST、SSE、WebSocket；
- Linux、Git、测试和调试；
- 综合实践：异步工具执行器。

这是所有应用类岗位的地基。模型能做决策，但工具执行、并发控制、错误恢复和接口服务仍由工程代码完成。

### 模块02：Agent核心机制

回答“模型如何从一次问答变成能持续执行任务的智能体”。重点包括：

- 消息、Prompt、Structured Output；
- Function Calling 与工具执行闭环；
- ReAct、Planning、Reflection；
- State、Context、Checkpoint；
- 长短期 Memory；
- Skills、MCP、Multi-Agent；
- 权限、注入攻击和人工确认。

### 模块03：评测与优化

回答“如何证明 Agent 真的变好了”。重点包括：

- Golden Set 与回归测试集；
- 回答质量、工具调用、任务成功率指标；
- RAG 和 Memory 指标；
- LLM-as-a-Judge 与人工校准；
- Badcase 分类、根因定位和迭代闭环；
- Trace、Span、Token、延迟和成本观测。

### 模块04：RAG

回答“如何让模型可靠地使用企业私有知识”。重点包括：

- 文档解析、清洗、OCR和元数据；
- Chunking 与 Parent-Child；
- Embedding 和向量数据库；
- BM25、Dense、Hybrid Search；
- Query Rewrite、Rerank、Context 组装；
- 引用、拒答、RAG评测；
- GraphRAG、权限隔离和数据更新。

### 模块05：工程化落地

回答“如何把原型变成可供多人长期使用的服务”。重点包括：

- FastAPI、OpenAPI、SSE、WebSocket；
- MCP Server 与 Client；
- SQL、事务、连接池；
- Redis、缓存、分布式锁；
- Celery 与消息队列；
- 超时、重试、熔断、限流和幂等；
- Docker、Kubernetes、CI/CD、监控和安全。

### 模块06：深度学习基础

回答“LLM内部为什么能够训练和生成”。重点包括：

- 向量、矩阵、梯度、交叉熵和KL散度；
- 神经网络、反向传播和优化器；
- Tokenization、Attention、Transformer；
- RoPE、KV Cache、MoE；
- PyTorch训练循环；
- Hugging Face模型加载和数据处理。

### 模块07：微调与后训练

回答“如何让基础模型适应领域任务和行为偏好”。重点包括：

- 指令、对话、工具调用和Trajectory数据；
- SFT；
- LoRA/QLoRA；
- DPO、RLHF、GRPO基础；
- Agent后训练；
- 显存优化、训练监控、Checkpoint与评测。

### 模块08：推理部署

回答“如何高并发、低延迟、低成本地运行模型”。重点包括：

- Prefill、Decode、KV Cache；
- vLLM、SGLang、TGI、TensorRT-LLM和Ollama；
- Continuous Batching、PagedAttention；
- 量化、Prefix Cache、Speculative Decoding；
- TTFT、TPOT、QPS、吞吐和P99；
- 压测、显存排查、模型路由与服务降级。

### 模块09：多模态与CV

回答“如何让模型理解和生成图像、文档与视频”。重点包括：

- 图像预处理、CNN、ViT和基础CV任务；
- CLIP、Vision Encoder、Projector和VLM；
- OCR、文档版面和表格理解；
- 视频抽帧、检索和时序理解；
- Diffusion、Stable Diffusion、Inpainting和ControlNet；
- 多模态Agent、RAG和评测。

## 三、七类岗位的具体学习路线

下面不是要求把九个模块全部学到同样深度，而是根据岗位日常工作选择主线。先完成该岗位的核心模块和项目达标线，再补相邻模块；同一家公司岗位名称可能不同，最终仍要把招聘描述中的任务映射到具体模块。

## 五、学习方法：每个知识点如何判定“学会”

### 第一层：能解释

不看文档回答：

- 它解决什么问题？
- 核心概念是什么？
- 完整流程是什么？
- 与相似技术有什么区别？

### 第二层：能编码

能够写出最小实现，并说明：

- 输入和输出；
- 数据结构；
- 异常边界；
- 关键参数；
- 测试方法。

### 第三层：能排错

面对失败现象，能按照以下顺序处理：

```text
复现问题
→ 收集日志和Trace
→ 判断错误环节
→ 提出原因假设
→ 设计验证实验
→ 修改并回归测试
```

### 第四层：能结合项目讲

使用“背景—问题—方案—取舍—结果—改进”表达：

```text
项目遇到了什么问题
→ 为什么选择该技术
→ 具体怎样实现
→ 有什么边界和代价
→ 用什么指标验证
→ 后续如何继续优化
```

## 六、推荐的综合项目

项目的作用是把孤立知识串成可运行、可评测、可解释的系统。建议选择一个主项目完整做深，再按目标岗位增加第二个专项；每个项目都应保留架构说明、运行步骤、测试/评测结果、Badcase和性能数据，而不只是代码截图。

## 项目一：企业知识库Agent

覆盖模块：01、02、03、04、05。

建议能力：

- 文档上传、解析、分块和索引；
- 混合检索与Rerank；
- Function Calling；
- LangGraph状态机；
- Redis会话或Checkpoint；
- SSE流式响应；
- 引用和无答案拒答；
- 自动评测、Badcase和Trace。

## 项目二：异步多工具任务Agent

覆盖模块：01、02、03、05。

建议能力：

- 多工具注册和Schema；
- 并行调用、超时、重试和限流；
- Planner、Executor、Reviewer；
- 断点恢复；
- 危险工具人工确认；
- 任务成功率和轨迹评测。

## 项目三：本地模型部署与微调

覆盖模块：06、07、08。

建议能力：

- 完成LoRA/QLoRA；

## 项目四：多模态文档助手

- PDF、图片、OCR、表格和图表解析；
