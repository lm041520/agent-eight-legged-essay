## 三、推荐学习顺序

```text
关系数据库：表设计 → 索引 → 执行计划 → 事务/MVCC → 锁 → 日志与恢复 → 复制
→ Redis：数据结构 → 缓存一致性 → 淘汰与持久化 → 高可用 → 分布式锁
→ 消息队列：共同语义 → Kafka/RabbitMQ → 幂等 → Outbox → 重试与积压
→ 搜索与图：Elasticsearch → 混合检索 → Neo4j → GraphRAG
→ 可靠性：把前面组件串进超时、重试、降级和观测体系
→ 综合场景：说明事务边界、失败窗口、补偿和权衡
```

如果时间只有两周，先覆盖：索引和 `EXPLAIN`、事务/MVCC/锁、redo/undo/binlog 与 WAL、Redis 缓存一致性、MQ 至少一次与幂等、Outbox，以及综合场景中的失败处理。

## 四、P0 重点清单

### 关系数据库

- B+Tree、聚簇/二级索引、回表、覆盖索引、联合索引和索引失效；
- `EXPLAIN`、估算行数与实际行数、Join、排序、深分页和慢 SQL 排查；
- ACID、脏读/不可重复读/幻读、MySQL RR 与 PostgreSQL RC 的差异；
- MVCC、快照读、当前读、undo 版本链、PostgreSQL dead tuple/VACUUM；
- record/gap/next-key lock、锁等待、死锁检测和重试；
- MySQL redo/undo/binlog、PostgreSQL WAL、checkpoint、备份与 PITR；
- 异步复制、复制延迟、读写一致性、分区与分库分表边界。

### Redis、消息与可靠性

- Cache Aside、穿透/击穿/雪崩、热点 Key/大 Key、过期删除与淘汰；
- RDB/AOF、复制、Sentinel/Cluster、故障切换和数据丢失窗口；
- 分布式锁的唯一持有者、TTL、续期、条件释放和 fencing token；
- 至多一次、至少一次、恰好一次的边界，ACK/Offset 失败窗口；
- 业务幂等、状态机、唯一约束、Outbox/CDC、重试队列和死信；
- 超时、指数退避、jitter、熔断、限流、背压、降级和可观测性。

### 搜索与图

- Analyzer、倒排索引、`text`/`keyword`、BM25、refresh、segment 和分片；
- query/fetch、PIT + `search_after`、mapping explosion、写入和搜索排障；
- 向量 + BM25 + metadata filter + rerank 的 RAG 检索链路；
- Node/Relationship/Label/Property、`MATCH`/`CREATE`/`MERGE`、Cypher 计划；
- GraphRAG 的实体消歧、图扩展、来源证据和多跳爆炸控制。

## 七、版本与资料规则

- MySQL 与 PostgreSQL 先学共同问题，再单独写实现差异，不能把一种产品的 MVCC 或锁机制套到另一种产品。
- Kafka 4.x 以 KRaft 为当前架构重点；RabbitMQ 4.x 以 Quorum Queue 为高可用重点。
- Elasticsearch、Neo4j 的 API 与索引能力随版本变化，具体命令以锁定版本的官方文档为准。
- 面试社区题库只用于发现问法；机制、版本和配置优先使用官方资料。
